## Must-fix
- Opposed-input fixture (b) for AC-3.2 is not opposed. Under the wrapper's own rule, byte-identical prompts ARE a divergence: `h-mad/scripts/hmad-dispatch.sh:3688` is `if [ -z "$div" ] || [ "$foreign" -ne 0 ]; then`, so an empty diff halts `prompt_divergence`, and spec AC-3.2 agrees ("An empty diff fails the cycle"). Fixture (b) pairs byte-identical prompts with a recorded `reason=prompt_divergence`, so the raw input and the token say the same thing. A probe that reads the prompts with a faithful copy of the predicate fails AC-3.2 on (b) exactly as the token does, so (b) stays green. The stated claim that (b) catches "reads the prompts instead of the token" holds only for an unfaithful reader that treats identical prompts as clean. The Risks row ("turns red on either drift direction") is therefore false for one direction. Repair: make (b) prompts that differ ONLY on lines containing one of the two report paths (the wrapper's rule says pass) beside a recorded `reason=prompt_divergence`. Every prompt-reading probe, faithful or masked, then passes AC-3.2 and turns (b) red. The byte-identical case can stay as an extra agreeing fixture. instance of: opposed-input pairs over token-read wrapper verdicts. The rule over that set: each fixture's raw inputs must satisfy the authority's predicate for the verdict OPPOSITE to the recorded token, checked by running the authority (the wrapper or the imported function) on those raw inputs when the fixture is built. That applies equally to the AC-3.1, AC-1.1, AC-1.3 and AC-1.6/AC-3.4 members. Residual: a member whose authority cannot be run offline gets no such check.
