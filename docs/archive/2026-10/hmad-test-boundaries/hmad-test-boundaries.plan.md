# Plan: hmad-test-boundaries

## Executive Summary

| Perspective | Summary |
|---|---|
| **Problem** | H-MAD's Phase 6 gates (`h-mad/scripts/h_mad_tdd_judge.py`, `h-mad/hooks/h-mad-tdd-gate.sh`, and `h-mad/scripts/h_mad_mutation_harness.py`) verify that tests precede production edits and that declared code mutations are caught, but Phase 4 (Design) does not require a machine-checked declaration of the public interface under test, the independent source of expected outputs (the oracle), mocked external dependencies, or boundary exclusions. This gap allows tautological tests (asserting against values computed by the implementation under test) and boundary drift (testing private helpers or mocking internal collaborators) to pass Phase 4 unchallenged. |
| **Solution** | Add a mandatory `## Test Boundaries` section with a 5-column Markdown table (`Public interface`, `Acceptance criteria`, `Expected result source`, `Mocked dependencies`, `Exclusions`) to the Phase 4 design template (`h-mad/references/inline-protocols.md`) and `h-mad/agents/design-author.md`; ship a standalone deterministic checker (`h-mad/scripts/h_mad_test_boundaries_check.py`) invoked by `h-mad/scripts/h_mad_audit_gate.py` on Phase 4 design audits without modifying `REQUIRED_SECTIONS` in `h-mad/scripts/h_mad_doc_shape_check.py`; extend the Phase 4 design audit rubric (`h-mad/audit-prompt.template.md` and `h-mad/agents/doc-auditor.md`) to challenge semantic oracle independence and boundary placement; and verify the checker against a 3-design archived calibration suite, 5 seeded broken fixture classes, and a two-direction connection-enforced mutation spec (`h-mad/tests/mutation-specs/test_boundaries_gate.json`). |
| **Function / UX Effect** | Every new Phase 4 design document (`docs/02-design/features/<feature>.design.md`) must include a valid `## Test Boundaries` table covering 100% of active `AC-X.Y[a-z]` identifiers in `docs/01-plan/features/<feature>.spec.md` (either as unit/integration test rows or as `verified by: audit \| live-run \| operator \| doc-review` rows naming a concrete proving artifact) before `h-mad/scripts/h_mad_audit_gate.py` can emit `GATE: PASS` or write a `.gated.json` stamp. Pre-existing tracked designs (`10` feature stems) and archived designs (`docs/archive/**`) lacking `## Test Boundaries` emit `TEST-BOUNDARIES: EXEMPT` unless `--no-exempt` is passed. |
| **Core Value** | Moves test-boundary and oracle-independence verification upstream to Phase 4 Design where deterministic tooling (`h-mad/scripts/h_mad_test_boundaries_check.py`) catches structural, coverage, placeholder, and lexical-tautology defects and Phase 4 LLM auditors (`h-mad/agents/doc-auditor.md`) catch semantic oracle tautologies and over-mocked internal boundaries before Phase 5 (`impl-plan`) and Phase 6 (`implement`). |

## Overview

H-MAD currently enforces RED/GREEN test-first discipline (`h-mad/scripts/h_mad_tdd_judge.py` and `h-mad/hooks/h-mad-tdd-gate.sh`) and code-level mutation catching (`h-mad/scripts/h_mad_mutation_harness.py`), yet neither mechanism checks whether a test exercises a real public interface or derives its expected values from an oracle independent of the implementation under test. This plan delivers the `hmad-test-boundaries` feature across six functional requirement groups (`FR-1`..`FR-6`, `17` acceptance criteria `AC-1.1`..`AC-6.3` in `docs/01-plan/features/hmad-test-boundaries.spec.md` `v1.3`): it introduces a 5-column `## Test Boundaries` table in Phase 4 design documents, enforces table shape, placeholder hygiene, tautological-oracle rejection, and head-anchored active spec AC coverage via a standalone script (`h-mad/scripts/h_mad_test_boundaries_check.py`) wired into `h-mad/scripts/h_mad_audit_gate.py`, updates the Phase 4 auditor prompt and agent instructions to challenge semantic oracle independence, and proves `< 200ms` per-design performance, calibration, and two-direction connection-mutation resistance across the test suite.
