AUDIT-gate-non-py-production-files-design-v1-BEGIN
## Summary
`docs/02-design/features/gate-non-py-production-files.design.md` cleanly consolidates the doc/data predicate (`is_doc_data`) in `h_mad_target_identity.py` via `CANON 1` (`doc_data yes|no`) and centralises plan matching in `h_mad_tdd_judge.py`. However, four build-impacting defects in the judge listing logic, the codex/agy 6-step code-like path, and the FR-9 hermetic probe fixture would cause false-ALLOW verdicts on listed non-`.py` files without tests, `IndexError` / `NameError` / contract-assertion failures in the codex and agy gates, and `kind=judge-error` failures in the FR-9 probe.

## Must-fix
- `_match_plans` and `listing` in `docs/02-design/features/gate-non-py-production-files.design.md` conflate "listed under `**Production file**:`" with "has non-empty `.py` `**Test file**:` entries", causing all three gates to allow a listed code-like non-`.py` file when its task has no `.py` test instead of denying with `kind=no-test-resolved` — `_match_plans` returns only `tuple[Path, ...]` (`matched_tests`), and `listing` treats a target name as listed only when `_match_plans(rel, records)` is non-empty (`if not matched: return Listing(False, None, ())`). When a task in an active plan lists a code-like non-`.py` path under `**Production file**:` whose `**Test file**:` is empty, omitted, `none`, or non-`.py`, `_match_plans` returns `()`, `listing` returns `Listing(False, None, ())` (`TDD-LISTING: unlisted`), and all three gates allow the write as unlisted without ever calling `judge()` or `resolve()`, violating `docs/01-plan/features/gate-non-py-production-files.spec.md` (FR-2 and FR-8 / AC-8.2) and `docs/01-plan/features/gate-non-py-production-files.plan.md` (Flow) and leaving the `# M:JR-NONPY` branch in `resolve()` unreachable through the gates.
