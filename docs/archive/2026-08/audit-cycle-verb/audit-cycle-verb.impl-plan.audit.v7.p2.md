## Summary
The implementation plan is extremely thorough and cleanly translates the design's constraints into actionable code. The reasoning behind the test discrimination exemptions and isolated parsing logic is excellent. However, there are two must-fix issues in the shell verb: an unverified state mutation (the prompt file creation is not checked for success) and a loose string match that will falsely report verified cycles as `unverified` if the feature name contains that word.

## Must-fix
- **Task 5, step 4 violates the Mutation verification invariant by not checking prompt file creation.** The shell verb calls `h_mad_assemble_audit.py` to write `${prompt[$i]}` and treats its exit code 0 and `ASSEMBLE:` token as proof of success, but never asserts that `${prompt[$i]}` was actually created and is non-empty. An assembly script could emit a token but fail to write the file, leading to `agy` being dispatched against a missing prompt. Add an explicit file check (e.g., `[ -s "${prompt[$i]}" ] || exit 4`) after assembly before proceeding.
- **Task 5, step 5 `size_status` substring match is too loose and will falsely trigger on feature names.** The check `case "${tok[$i]}" in *unverified*)` matches the substring anywhere in the assembly token. Since the token includes the prompt file path (`PASS /tmp/audit_<feature>_...`), if the audit's `--feature` name contains the word "unverified" (e.g., `unverified-logins`), the `case` will match and falsely report the cycle as `unverified` even when it is verified. Change the pattern to strictly match the field, e.g., `*size_status=unverified*`.

## Should-fix
- **Task 5, step 0 uses `local here` in what might be a global scope.** If the `audit-cycle)` case branch in `hmad-dispatch.sh` executes at the top level of the script rather than inside a function (e.g., inside `main()` or `cmd_exec()`), `local here` will throw a fatal syntax error (`bash: local: can only be used in a function`) and crash the script. Either ensure this case branch is wrapped in a function, or remove the `local` keyword.
- **Task 5, step 7 `diff` exit code might crash the script under `pipefail`.** If `hmad-dispatch.sh` operates with `set -o pipefail` (or someone adds it later), the `diff` command exiting 1 (which it always does when prompts differ, as expected) will cause the pipeline to fail and `set -e` to abort the script, preventing the `prompt_divergence` logic from executing. Protect the `diff` invocation inside the subshell, e.g., `$( (diff "${prompt[1]}" "${prompt[$i]}" || true) | grep -c '^[<>]' )`.

## Nit
- **Task 5, step 3 channel clearing could safely include the prompt and assembly logs.** While `rm -f` clears the `report`, `.done`, and `out` paths, it leaves `${prompt[$i]}` and `${asm[$i]}`. If a previous run left a read-only prompt file, the `>` redirection or assembly script write could fail. Clearing them ensures a completely clean slate.
