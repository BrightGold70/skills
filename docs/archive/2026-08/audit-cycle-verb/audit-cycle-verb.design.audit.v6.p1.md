## Summary
The design cleanly maps the shell-orchestration and Python-handling boundary described in the plan, capturing the necessary checks for a reliable two-pass audit cycle. The error handling accurately segregates cannot-judge states from operational errors, and the CLI boundaries are respected. However, there are two significant gaps: `premise_items` cannot correctly filter acknowledged findings based on its signature and reliance on the `GATE:` token, violating both the Single-Source Contract and the operator override; and the test designed to pin the gate's real concatenation behavior is scheduled to run against a stub, rendering it untestable.

## Must-fix
- **Single-source contract / Operator-override bypass in premise checklist** — The design specifies that the python helper parses the `GATE:` line output from a subprocess call to `h_mad_audit_gate.py`, meaning it only receives `(verdict, must, should)`. To produce the premise checklist, the helper must re-parse the markdown file itself. This is an independent reimplementation of the gate's section-extraction logic (violating the Single-Source Contract). More critically, the signature `def premise_items(results: list[PassResult])` does not accept the `--ack-file`, meaning it will blindly extract and emit premise checklist items for findings that the operator explicitly cleared via `## Acknowledged-not-fixed`. The helper must either consume the `--ack-file` and replicate the filtering (with a differential test), or the gate's python internals should be imported to single-source the extraction.
- **Untestable AC regarding the concatenation pinning test (AC-10.3)** — The Test Strategy states that helper tests mock `h_mad_audit_gate.py` at the subprocess boundary with a stub executable. However, `test_prose_plus_bullet_not_concatenated` is placed in this helper suite to fulfill AC-10.3, which explicitly exists to "pin exactly the case that distinguishes the two designs, so a future change to the gate breaks a test". A stub gate cannot assert how the *real* gate behaves on concatenated markdown vs separate files. If this test uses a stub, a future breaking change to the real gate's parser will silently escape detection, violating the plan's explicit requirement. This specific test must invoke the real `h_mad_audit_gate.py` (or import its parser) to legitimately pin the internal dependency.

## Should-fix
- **Missing `--feature` in `render()` signature** — The design dictates that `render()` outputs the `[H-MAD] <feature> audit-cycle <verdict>` marker line, but the signature `def render(results, verdict, reason, *, size_status, passes) -> str` omits `<feature>`. It needs to be passed in to properly format the marker.
- **Orphaned `findings` field in `PassResult`** — `PassResult` is defined with a `findings` field, but the `gate()` function that presumably populates the result only returns `tuple[str | None, int, int]` (`verdict`, `must`, `should`). The origin of the `findings` data is undefined.
