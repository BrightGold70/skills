# Design: grok-audit-surface

## Executive Summary
One stdlib-only probe, `docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py`, with nine modes (`check-ledger`, `build-root`, `record-cycle`, `commit-data`, `smoke`, `extract`, `score`, `rescore`, `main-leak`), a declared exclusion list beside it, five new test modules under `h-mad/tests/`, and one new mutation spec. Together they measure grok against agy on 27 seeds, read every verdict the wrapper already computes from the wrapper's own token lines, and keep all calibration data on the never-merged branch `calibration/grok-audit-surface`. The only production code the feature edits is SKILL.md text (and `grok-runtime.md`); `exit_check`, `round_check`, `combine`, `scan_grok` and the wrapper are pinned by tests and not edited.

## Overview
This design takes spec v1.7 and plan v1.5 (both at `28ec5bfc`) as given and settles every item the plan leaves to the design (listed in "Plan obligations answered"). It was first written against spec v1.6 (`94a4fd2c`) and plan v1.3 (`ab3c9f32`); the later revisions changed only operator decision D4, which v1.2 of this design took. The plan and the delta review cite shas from before a rebase; this design cites only the post-rebase ids, which `docs/03-analysis/grok-audit-surface.sha-remap.md` maps (`946ffc5a→a0b41697`, `5b2df07b→bfb6960a`, `611c299d→2f7bf7ae`, `b085ad7a→ab3c9f32`). There are three key decisions. The probe never re-derives a verdict the wrapper or the gate computes: it reads the token, or imports the function. No S2 root is used for more than one cycle; the one S1 root serves its three cycles, because AC-1.6 requires the same root, and it is reset to its build and re-scanned before each of its second and third dispatches (D5). Calibration data reaches the branch only through git plumbing, so it is never checked out in any work tree.

## Architecture Overview

```
 main (CI-tested, S0)                         calibration/grok-audit-surface (operator, never merged)
 ───────────────────────                      ──────────────────────────────────────────────────────
 grok_audit_probe.py ── reads ──> HEAD:exclusions.txt         calibration sha: ledger.jsonl + seeded/*.md
   │ imports h_mad_audit_gate (classify, section walk)        smoke commit:     + s1/<surface>/... (root.txt each)
   │ imports h_mad_audit_cycle (_gate_token)                  score sha:        + s2/d<k>/v<N>/... (root.txt each),
   │ imports h_mad_audit_origins (ORIGINS)                                        findings, key, labels, extract.txt
   │ imports h_mad_review_evidence (_GROK_TYPES)
   │ reads hmad-dispatch.sh text (_GROK_TYPES_RE)
   │ runs h_mad_audit_gate.py CLI (GATE: token)
   │
   ├─ build-root ── git archive <calibration sha> ──> $TMPDIR/gas-root-d<k>-<purpose>-XXXX/  (non-git)
   │                 remove exclusions, place target + paired docs, scan, reach check
   │
   │   operator: env -u GIT_* HMAD_AUDIT_STEM_DIR=$KEEP/run-<cal12>/stem/<cycle>  hmad-dispatch audit-cycle ... | tee
   │
   ├─ record-cycle ── copies stem + root by-products + root record ──> $KEEP/run-<cal12>/data/{s1,s2}/...
   ├─ commit-data ─── hash-object / read-tree / commit-tree / update-ref (temp index, no checkout) ──> branch
   ├─ smoke ───────── SMOKE: PASS|FAIL|UNREADABLE   (exit 0, 0, 2)
   ├─ extract ─────── findings.jsonl + key.jsonl (opaque ids, shuffled) + advisory hints on stdout
   ├─ score ───────── SEEDSCORE: ... from one exported score-sha tree
   ├─ main-leak ───── ref/sha checks → drift → main leak over HEAD against the smoke commit or the score sha
   └─ rescore ─────── ls-remote/fetch ref → sha checks → drift → git archive score sha → main leak
                      over HEAD → list check → rebuild roots + scan + reach → score → remove temp dirs
```

The scorer is a pure function of two trees, as the plan's Architecture section requires: the `main` commit (probe and exclusion list) and the exported score-sha tree, which holds the ledger, the seeded copies, the recorded cycles, the findings, the key and the labels, plus the archive sources that came from `main` when the branch was made.

## Detailed Design

### D1. Probe file, imports and invocation
- **Path**: `docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py`, run as `python3 docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py <mode> …` from the repository root. It is not named `test_*.py`.
- **Imports**: the stdlib only, plus four `h-mad/scripts/` modules reached as `Path(__file__).resolve().parents[4] / "h-mad" / "scripts"` put first on `sys.path`. (`parents[0]` is the probe directory, `[1]` `probes`, `[2]` `03-analysis`, `[3]` `docs`, `[4]` the repository root.) The four modules are `h_mad_audit_gate` (`classify`, `BLOCKING_SECTIONS`, `_bullet_groups`, `_collapses`, `_flat_findings`, `_bullet_remainder`, `_payload`, `_is_none_sentinel`; D12), `h_mad_audit_cycle` (`_gate_token`, which parses the gate's first-line token with `GATE_RE`), `h_mad_audit_origins` (`ORIGINS`) and `h_mad_review_evidence` (`_GROK_TYPES`). The gate is imported as a module object, `import h_mad_audit_gate as _gate`, and every call is `_gate.classify(...)`, so the classify connection is one attribute that a test can replace (D12). `_GROK_TYPES_RE` is read from the text of `h-mad/scripts/hmad-dispatch.sh` (or the `--vocab-sh` path, D11) with the regex `^_GROK_TYPES_RE=['"]([^'"\n]*)['"]$` (multiline; either quote character, as implemented in `vocab_sets`), split on `|`, and never copied. The private names are imported the same way `h_mad_audit_cycle._must_findings_from_gate_parser` already imports `_BULLET_MARKERS` and `_payload` from the gate.
- **Subprocesses**: only `git` and `sys.executable h-mad/scripts/h_mad_audit_gate.py <report>`, the latter to obtain a real `GATE:` token. The gate is run without `--gated`, so it writes no stamp beside the report (the stamp branch runs only under `args.gated`). The probe never invokes `codex`, `agy`, `grok` or `hmad-dispatch` (base §"No new external dependency").
- **Source features** are the module constant `SOURCES`, in spec FR-2 order: `audit-report-docs-copy` (`docs/archive/2026-09/`), `tdd-gate-fail-opens` (`docs/archive/2026-09/`), `agy-coder-fallback` (`docs/archive/2026-10/`). Documents are numbered `d1`…`d9` in feature order, then plan, design, impl-plan (AC-2.2). `--sources <name>=<archive dir>,…` overrides the constant, and only the synthetic fixtures pass it. It is accepted by every mode that reads the ledger or the archive sources, which are `check-ledger`, `build-root`, `extract`, `score`, `rescore` and `main-leak` (D2), and each passes the one parsed mapping to every check it calls in process (`rescore` to `check_ledger`, `build-root` and `score`; `main-leak` to trigger (iii)'s archived-source read). Every function that maps a document id to its archive path therefore takes the mapping as a required argument and never reads `SOURCES` itself: `placements(doc, sources)` (D5, D12), `extract_all(tree, s2_dir, sources)` (D12), `hints(findings, tree, sources)` (D12) and `check_ledger(tree, sources)` (D4); `record-cycle`, `commit-data` and `smoke` read neither and do not accept it. **DECISION (design-author):** a CLI override and not a config file, because the plan restricts the probe directory on `main` to "the probe and the declared exclusion list, and nothing else".
- **Token discipline** (spec AC-5.1, verbatim: "Every invocation of the probe, in every mode and on every path out of it (an exception that escapes the mode's own checks included), ends on exactly one token line on stdout; there is no exit without one."). Each mode's grammar is the D2 table: one prefix per mode, used by its success token and by its refusal token, and by nothing else. Lines printed before the token (`VOCAB:`, `SURFACE:`, `LIST:`, `HINT:` and the rest) are published lines, never tokens, and no published line starts with another mode's token prefix. An `[H-MAD] grok-audit-surface <mode> <verdict>` marker goes to **stderr**, so the token stays the last stdout line (base §"Marker discipline"). The one invocation that names no mode (D2, "No mode named") prints the tenth prefix, `PROBE:`, which no mode owns.
- **The last resort.** `main()` wraps the parse and the mode in one `try` and maps every exception to the mode's refusal token through one function, `refusal_token(mode, exc, argv)`, then exits 2. Three channels, in this order:
  1. A `Refusal` (a mode's declared refusal) prints its own `exc.reason` (`# M:GAS-REFUSAL-REASON`); this is how every D2 reason other than `internal:<E>` reaches the token.
  2. Otherwise, for `smoke`, the reason is `input_unparseable:<path>` (AC-5.1: the smoke's "unexpected failures map to its own two UNREADABLE reasons"). `<path>` is the module global `_OPEN_INPUT` when it is set (`# M:GAS-OPEN-INPUT`), else the `--data` value as given in argv (`--data <v>` or `--data=<v>`), else the empty string. `main()` sets `_OPEN_INPUT = None` on entry; the smoke sets it to each input's path immediately before that input is read (`_smoke_read` for every text input, `vocab_sets` for `--vocab-py`, `delivered` for the collected report before the gate runs) and never clears it. Residual, stated exactly: an exception after every input has been read (in the published-line or reason assembly) names the last input opened, not the place it failed; and a smoke usage error with no `--data` prints `input_unparseable:` with an empty path.
  3. Otherwise the reason is `internal:<ExceptionName>` (the class name; `# M:GAS-LAST-RESORT`). For `score` and `rescore` that is exactly the spec's `SEEDSCORE: UNREADABLE reason=internal:<ExceptionName>`.

  **Traceback scope.** The traceback is printed on stderr only for an exception that is not a declared refusal (`# M:GAS-TRACEBACK-SCOPE`: `not isinstance(exc, ProbeRefusal)`). The declared classes all derive from `ProbeRefusal`: `Refusal`, `UsageError` (D2) and the seven reset classes of D5 (`ResetArgsConflict`, `ResetPurposeNotS1`, `ResetTargetNotAbsolute`, `ResetTargetNotDirectory`, `ResetTargetOutsideTempdir`, `ResetTargetPrefix`, `RootResetMismatch`). The last eight still print `internal:<ClassName>` (or, under `smoke`, channel 2's form), but with no traceback, because they are expected outcomes and not defects. An expected I/O or parse failure inside a listed check is reported as that check's reason and never as `internal`.

### D2. Modes, command lines and the token grammar of each

This table is the one statement of each mode's grammar (spec AC-5.1: "Every other mode has one token grammar, which the design names, and no mode prints two grammars"). The tests assert the exact last stdout line per mode (Test Plan, "Token grammar").

| Mode | Command line | Success token (exit 0) | Refusal token (exit 2) | Refusal reasons | Stage |
|---|---|---|---|---|---|
| `check-ledger` | `check-ledger (--tree <dir> \| --repo . --calibration-sha <sha40>) [--sources …]` | `LEDGER: OK seeds=<n> docs=<n> C1=<n> C2=<n> C3=<n> C4=<n>` | `LEDGER: UNREADABLE reason=<r>` | `ledger_counts`, `ledger_origin`, `seed_rebuild`, `calibration_ref:sha_unknown:<sha>`, `internal:<E>` | S0b, tests |
| `build-root` | `build-root --repo . --calibration-sha <sha40> --doc d<k> --purpose <s1\|s2v1\|s2v2\|rescore> [--list-commit <sha>] [--dest-parent <dir> \| --reset <abs root>] [--sources …]` | `ROOT: READY doc=d<k> purpose=<p> path=<abs> calibration=<sha40> list_commit=<sha40> list_blob=<oid> absent=<n>` | `ROOT: UNREADABLE reason=<r>` | the `check-ledger` reasons, `leak:<path>`, `root_git:<path>`, `internal:<E>` | S0b, S1, S2 |
| `record-cycle` | `record-cycle --stem <dir> --root <dir> --root-record <file> --stdout <file> --command <file> --dest <dir>` | `RECORD: OK dest=<abs> files=<n>` | `RECORD: REFUSED reason=<r>` | `input_missing:<path>`, `no_auditcycle_line:<file>`, `stem_prefix:<n>`, `command_unparseable:<file>`, `root_record:no_line`, `root_record:path_mismatch`, `internal:<E>` | S1, S2 |
| `commit-data` | `commit-data --repo . --parent <sha40> --src <dir> --message <text>` | `COMMIT: OK sha=<sha40> ref=refs/heads/calibration/grok-audit-surface` | `COMMIT: REFUSED reason=<r>` | `parent_unknown:<sha>`, `ref_moved:<oid>`, `outside_calibration_dir:<path>`, `ref_unconfirmed`, `internal:<E>` | S0b, S1, S2 |
| `smoke` | `smoke --data <dir>/s1 [--vocab-py <path>] [--vocab-sh <path>]` | `SMOKE: PASS` and `SMOKE: FAIL reason=<r>[,<r>…]` (both exit 0) | `SMOKE: UNREADABLE reason=<r>` | `input_missing:<path>`, `input_unparseable:<path>` (AC-1.7) | S1 |
| `extract` | `extract (--tree <dir> \| --repo . --base-sha <sha40>) --s2 <dir> --shuffle-seed <int> --out <dir> [--sources …]` | `FINDINGS: WRITTEN findings=<n> must=<n> should=<n> reports=<n>` | `FINDINGS: UNREADABLE reason=<r>` | the `check-ledger` reasons, `cycle_token:<cycle>`, `must_count_mismatch:<report>`, `internal:<E>` | S2 |
| `score` | `score --tree <dir> [--calibration-sha <sha40> --score-sha <sha40>] [--sources …]` | `SEEDSCORE: PASS\|MISS reason=bar_missed\|INCONCLUSIVE reason=<r> …` | `SEEDSCORE: UNREADABLE reason=<r>` | any AC-5.4 reason the score's checks name (D13) | tests, inside `rescore` |
| `rescore` | `rescore --repo . --calibration-sha <sha40> --smoke-sha <sha40> --score-sha <sha40> [--remote origin] [--sources …]` | the `score` token | `SEEDSCORE: UNREADABLE reason=<r>` | any of the fifteen AC-5.4 reason forms | S3 (AC-6.4) |
| `main-leak` | `main-leak --repo . --calibration-sha <sha40> --smoke-sha <sha40> [--score-sha <sha40>] [--remote origin] [--sources …]` | `MAINLEAK: CLEAN scanned=<sha40> data=<sha40> blobs=<n>` | `MAINLEAK: UNREADABLE reason=<r>` | `calibration_ref:<kind>`, `calibration_drift:<path>`, `calibration_drift:not_descendant`, `main_leak:<path>`, `internal:<E>` | S3, every outcome (D9) |

`<E>` is the escaping exception's class name (D1). **DECISION (design-author):** one grammar per mode, with two refusal words. The modes that check calibration data (`check-ledger`, `build-root`, `extract`, `score`, `rescore`, `main-leak`) refuse with `UNREADABLE`, and every reason they print is one of AC-5.4's fifteen forms, so a check that runs at S0b and again inside `rescore` carries the same reason in both places. The two recording modes (`record-cycle`, `commit-data`) refuse with `REFUSED` and their own closed reason sets: those refusals are operator preconditions on writing a record, not readings of calibration data, so they neither need nor widen AC-5.4's closed list. This replaces v1.0's "one refusal vocabulary" sentence, which was false: v1.0 had `COMMIT:` and `RECORD:` refusals beside it.

**No mode named (the tenth prefix, `PROBE:`).** When argv is empty or its first word is not one of the nine modes above, there is no mode whose grammar applies, so `main()` prints exactly one stdout line, `PROBE: UNREADABLE reason=unknown_mode` (`# M:GAS-UNKNOWN-MODE`), before any parsing, then the usage on stderr and `[H-MAD] grok-audit-surface unknown_mode UNREADABLE` on stderr, and exits 2. `PROBE:` is owned by no mode, has this one form and no counts, and no mode prints it. This is the plan's extension (impl-plan Task 2, operator ruling); it keeps AC-5.1's "no exit without one [token]" true for the argv the D2 table cannot name. Spec AC-5.1/AC-5.4 owe the same prefix (report).

**Usage errors inside a mode.** The parser is built with `add_help=False` (`# M:GAS-NO-HELP`) and `allow_abbrev=False` (`# M:GAS-NO-ABBREV`), and its `error()` raises `UsageError` (`# M:GAS-USAGE`) instead of exiting, so every argparse exit path, `--help` and an abbreviated flag included, reaches D1's last resort and ends on the mode's token: `<PREFIX> <WORD> reason=internal:UsageError` with no traceback, or, under `smoke`, `SMOKE: UNREADABLE reason=input_unparseable:<--data value>` (D1 channel 2). The paired-flag rules that argparse cannot express (`check-ledger`'s `--repo` with `--calibration-sha`, `extract`'s `--repo` with `--base-sha`, `score`'s `--calibration-sha` with `--score-sha`) are checked in `main()` through the same `parser.error`.

`--tree <dir>` is always a directory holding an exported commit tree (or a synthetic fixture shaped like one), never a work tree. `--repo . --calibration-sha` and `--repo . --base-sha` export that commit with `git archive` into a fresh `mkdtemp` directory and then run the same function the `--tree` form runs, so each check has one implementation and two front doors.

### D3. Calibration directory layout (branch only)
Every path is under `docs/03-analysis/probes/grok-audit-surface/calibration/` in the branch's tree:

```
ledger.jsonl                         one JSON object per seed (AC-2.4)
seeded/<feature>.<phase>.md          the 9 seeded copies (AC-2.5)
s1/versions.txt                      grok_binary=<path> <grok --version line>, then agy and codex --version output (AC-3.6, D8)
s1/<surface>/                        surface ∈ {grok, agy, codex}; codex absent when not run
s2/d<k>/v<N>/                        k ∈ 1..9; N ∈ {1, 2}
findings.jsonl                       {"id","doc","cycle","section","text","quotes":[...]}; shuffled; no surface field
key.jsonl                            {"id","doc","cycle","pass","surface","report"}, one record per finding and nothing else
labels.jsonl                         {"id","label","why"}; "why" required for UNDECIDABLE
extract.txt                          the extract command line verbatim, shuffle seed included
```

A cycle directory (`s1/<surface>/` or `s2/d<k>/v<N>/`) holds the following.

| File | From | Read by |
|---|---|---|
| `auditcycle.txt` | the wrapper's full stdout, captured with `tee` | smoke, extract, score (the `AUDITCYCLE:` line and the `Effort:` block) |
| `command.txt` | the exact dispatch command, verbatim | record-cycle, score (`--feature`, `--phase`, `--cycle`, `--surfaces`), measurement doc |
| `root.txt` | the `ROOT: READY` line of the root the cycle ran in (`--root-record`) | rescore (`list_changed`), extract (quote paths), measurement doc |
| `wall_seconds.txt` | `date +%s` before and after, as a difference (S1 grok only) | smoke (AC-1.4 timeout) |
| `resolved_model.txt` | `h_mad_resolved_model.py` stdout and stderr (S1 only, D8) | measurement doc (AC-1.4, AC-3.6) |
| `p<i>.prompt.txt`, `p<i>.asm.txt`, `p<i>.out.txt`, `p<i>.log`, `p<i>.report.md` | the stem dir (`<stem>_p<i>.txt`, `.asm.txt`, `.out.txt`, `.log`, `.report.md`), each only if present | the labeller, smoke (grok log), opposed fixtures |
| `collected/<feature>.<phase>.audit.v<N>.p<i>.md` and its `.effort.json` | the root's `docs/0X-…/features/`, only this cycle's `v<N>` | smoke and score (GATE, findings), AC-3.3 `log_sha256` |
| `pass-logs/<collected name>.log` | the root's `.h-mad/pass-logs/`, only this cycle's `v<N>` | the measurement doc (AC-3.3) |

`record-cycle` copies these and nothing else. It never writes the root's `.gated.json` stamps, which are root-local artefacts.

**What counts as calibration data** (spec AC-2.7). The set is every file under the calibration directory at the commit in question, except a file that has one of six names below **and** carries none of the spec's three kinds of text (spec AC-2.7, verbatim: "A file is outside the set only when it carries none of these"). The test is per file and per commit, never by name alone. A file with one of the six names is in the set when its normalised content (the D6 normaliser) contains any of: (a) any seed's normalised `seeded` span; (b) any seed's normalised `expected` sentence; (c) the words of any finding filed on a seeded document. For every must and should finding that `report_findings` (D12) gives over every collected report in the same tree (`s1/*/collected/*.md` and `s2/d*/v*/collected/*.md`), the needles are per line and never the joined group: the normalised `_gate._payload` of the finding's bullet line (its first line, for a finding that starts at a bullet, which is a flat finding or a collapsed group's parent), and, for a prose-only finding (D12 step 3, which starts at no bullet), the normalised `_gate._payload` of each of its lines. A finding's continuation lines (`class:`, `quote:`, `instance of:`) and a collapsed group's nested evidence bullets are not needles. Every collected report under the calibration directory is a report on a seeded document (S1 audits `d1`'s seeded copy, S2 each `d<k>`'s), so (c) reads them all. Each of the six names is a candidate for exclusion for one stated reason:
- `command.txt`: the dispatch argv (feature name, phase, cycle, root path, surfaces, timeout).
- `root.txt`: one `ROOT: READY` line (shas, a path and a count).
- `wall_seconds.txt`: one integer.
- `resolved_model.txt`: one `RESOLVED-MODEL` line or its refusal.
- `s1/versions.txt`: three version strings, the first prefixed with the grok binary's path (D8).
- `extract.txt`: the extract argv.

They are candidates because they are short metadata files that an unrelated `main` blob can equal byte for byte (a one-integer file is the extreme case), which would make trigger (i) refuse a clean `main`. Such a file that does carry (a), (b) or (c) is in the set whatever its name, so trigger (i) compares it with every `main` blob like any other calibration file; v1.2 excluded the six by name alone, which left a metadata file holding a finding's text (but no seed span) outside the whole-file check. Everything else is in the set, `auditcycle.txt` included: on a `PASS` or `FAIL` cycle the wrapper's stdout carries a `Premise checklist:` with one line per finding (`render` in `h_mad_audit_cycle.py`), and those findings quote seeded spans. v1.0 excluded `auditcycle.txt` on the premise that it carries no seed text; that premise was false. Triggers (ii) and (iii) scan every `main` blob for every seed's `expected` and `seeded` text whatever the file, independently of the set. One function, `calibration_data_files(tree)`, computes the set, and trigger (i) and its tests all call it (D9). Residual, stated exactly: (c) matches each needle as one substring of the normalised file, so a metadata file stays outside the set when it carries only a paraphrase or a fragment of a payload, or only a finding's continuation lines or a collapsed group's nested evidence bullets; this is AC-2.6's paraphrase residual, applied to finding text. The other direction is fail-closed: a short payload (a `- Build defects:` label parent is itself a finding, D12, so `Build defects:` is a needle) can bring a metadata file into the set, where trigger (i) compares it with every `main` blob; that over-includes and never leaks.

### D4. Ledger checks (`check-ledger`; AC-2.2–2.5)
- Records are read from `ledger.jsonl`. `ledger_counts` fires on each of these, each its own guard: a line that does not parse as one JSON object; a record lacking one of the nine AC-2.4 fields (`id source phase class origin section original seeded expected`); a `source` that is not one of the nine FR-2 documents; an empty `original`; an empty `expected` (an empty needle would match every file).
- **Per-document class rule** (spec AC-2.2, verbatim: "for every k, document k's multiset of seed classes must equal exactly the three classes other than `((k−1) mod 4) + 1`, one each"). The probe compares, for each `d<k>`, `sorted(classes of d<k>)` with `sorted({C1,C2,C3,C4} − {C((k−1) mod 4)+1})`. A mismatch refuses `ledger_counts`. The totals (C1=6, C2=7, C3=7, C4=7, sum 27) are then derived from the rule and compared with the ledger's; the numbers are not literals in the code. The per-document check is what catches the spec's balanced counterexample (d1 as C2, C2, C4 and d4 as C1, C3, C3), which keeps every document size and every total. The totals comparison is implied by the per-document rule (every document's multiset equal to its permitted one makes the summed multisets equal), so no ledger that passes the per-document guard can fail it: it is kept unmarked, with no fixture and no mutation row, and its residual is exactly that it is unreachable while the per-document guard stands.
- `ledger_origin`: `origin ∉ ORIGINS` (the imported 8-tuple).
- `seed_rebuild`: for each document, start from the archive source bytes in the exported calibration tree. For each seed, the exact (unnormalised) `original` must occur **exactly once** in the source, and it is replaced by `seeded`. The result must equal `seeded/<feature>.<phase>.md` byte for byte. The four AC-2.3 placement violations refuse `seed_rebuild` too, each its own guard (spec AC-5.4: "two seeds of one document in the same `##`/`###` section, a seed under `## Version History`, a record whose `section` does not name the heading its span sits under, or a `seeded` span that does not occur exactly once in its seeded document").

### D5. Export root (`build-root`; AC-2.6)
**Parent directory.** By default this is `tempfile.mkdtemp(prefix=f"gas-root-d{k}-{purpose}-")` under `tempfile.gettempdir()`. On this Mac that is `$TMPDIR` (`/var/folders/…/T/`), and `git -C <a mktemp -d dir> rev-parse --git-dir` exits 128 there (Readings). The reach check, not this choice, is the evidence. `--dest-parent` exists for fixtures, including the "root nested inside a work tree" fixture.

**Roots and cycles.** **DECISION (design-author):** S1 builds one fresh root for its three cycles (AC-1.6 requires the same root), and S2 builds a fresh root for every cycle, re-dispatch included (`s2v1`, `s2v2`). That makes 10 to 19 dispatch roots in all (one for S1, and nine to eighteen for S2: one per document, plus one per AC-3.4 re-dispatch), besides the roots `rescore` rebuilds; plan v1.5's S1 and S2 rows say the same ("one fresh export root … shared by its three cycles"; "each (and each AC-3.4 re-dispatch) in a fresh export root"). A used root holds the earlier cycle's collected reports, `.effort.json` sidecars and `.h-mad/pass-logs/` (the wrapper writes them under `--project-root`), and a re-dispatched cycle that could read the first cycle's reports from other surfaces is a cross-surface leak. The S1 root is never reused for S2. **The smoke document is `d1`** (audit-report-docs-copy plan, the smallest), and S1 runs its cycles as `--cycle 1` (grok), `--cycle 2` (agy) and `--cycle 3` (codex), so the collected paths never collide, and `record-cycle` copies only the `v<N>` files of the cycle it records.

**Resetting the S1 root between its cycles (spec AC-2.6: "Before any dispatch, the probe reads every regular file in the root").** The shared root is checked before every one of its three dispatches, not only at construction: after the grok cycle and again after the agy cycle, the operator runs `record-cycle` for that cycle first (it copies the by-products out), and then `build-root` with the same `--calibration-sha`, `--doc`, `--purpose s1` and `--list-commit` and with `--reset <abs root>` (the `path=` of the root's `ROOT: READY` line). `--reset` and `--dest-parent` are mutually exclusive, checked by the mode before anything else (never by an argparse mutually-exclusive group, whose usage error would exit with no token): both given raises `ResetArgsConflict`, which D1's last resort prints as `ROOT: UNREADABLE reason=internal:ResetArgsConflict` (guard `# M:GAS-RESET-EXCLUSIVE`). Next, and still before the five target guards, `--reset` is refused for any `--purpose` other than `s1` (only S1 reuses a root between cycles; an `s2v1`, `s2v2` or `rescore` root is always fresh): `ResetPurposeNotS1`, printed as `ROOT: UNREADABLE reason=internal:ResetPurposeNotS1` (guard `# M:GAS-RESET-PURPOSE`; a plan extension, impl-plan Task 5, implemented). Nothing under the target is touched by either refusal.

**The reset target precondition, which runs before step 1 and before any removal.** Nothing is written to or removed under the target, and step 1 does not start, until all five guards below have passed, in this order, each its own marked guard:
1. the `--reset` value as given is an absolute path (`os.path.isabs`; the empty string, which `Path` reads as `.`, fails here), else `ResetTargetNotAbsolute` (`# M:GAS-RESET-ABS`);
2. it is an existing directory (`os.path.isdir`), else `ResetTargetNotDirectory` (`# M:GAS-RESET-ISDIR`);
3. its resolved parent equals `Path(tempfile.gettempdir()).resolve()` (both sides resolved, so `/var/folders/…` and `/private/var/folders/…` compare equal, and a symlink is judged by where it points), else `ResetTargetOutsideTempdir` (`# M:GAS-RESET-TMPDIR`);
4. its resolved basename starts with `gas-root-d<k>-s1-`, with `<k>` from the same `--doc` (the prefix the S1 build's `mkdtemp` gave it), else `ResetTargetPrefix` (`# M:GAS-RESET-PREFIX`);
5. the D7 reach check, run on the target itself: a `.git` entry at any depth, or `git -C <target> rev-parse --absolute-git-dir` exiting 0, refuses `root_git:<path>` exactly as D7 does (`# M:GAS-RESET-REACH`).

Guards 1–4 each raise their own exception class, printed by D1's last resort as `ROOT: UNREADABLE reason=internal:<that class>`; one class per guard is what lets each guard's fixture tell it from its siblings, so a disarmed guard that falls to the next one changes the token. **DECISION (design-author):** AC-5.4's list is closed and `build-root` prints only its forms (D2), so the choice is between `root_git:<path>` and `internal:<E>`. `root_git:<path>` states that a git repository was found at `<path>`; a mistyped target such as `$HOME` or a directory outside the temp directory is usually not one, so that reason would be false there. `internal:<E>` names the class of the refusal and asserts nothing about git, and no other AC-5.4 reason names an operator's wrong argument. Guard 5 is a real git reach and keeps `root_git:<path>`. Residual of the precondition, stated exactly: a target that passes all five but is not the root of this run (an older `gas-root-d<k>-s1-*` directory left directly under the temp directory by an earlier S1 build of the same document) is reset; the removal then stays inside a directory a probe built, and the directory that results has just been made equal to this build and passed the scan and the reach check, so a dispatch in it is still a dispatch in a clean root. The precondition does not prove that the target is the root of the previous cycle; `record-cycle --root-record` (`root_record:path_mismatch`) is what ties each cycle to the root it ran in.

**The reset itself.** The reset runs steps 1–5 below into a fresh `mkdtemp` directory (the expected tree), then makes the live root equal to it: every entry of the live root whose root-relative path is absent from the expected tree is removed, whatever its kind (the collected reports, `.effort.json` sidecars, `.gated.json` stamps, `.h-mad/pass-logs/` and anything else the cycle wrote), and every expected file whose bytes differ, or which is absent, is written again from the expected tree. It then re-walks the live root and asserts that its set of root-relative paths, and each file's sha256, equal the expected tree's; a difference there (a writer still running in the root) is not one of AC-5.4's named triggers, so it raises `RootResetMismatch` (guard `# M:GAS-RESET-REWALK`) and D1's last resort prints `ROOT: UNREADABLE reason=internal:RootResetMismatch`. The re-walk comes before step 6, and this order is the implemented one (impl-plan Task 5's OPEN-DECISION was resolved as option (b): the order is unchanged, and the two fixtures that plant a path in the live root after the precondition, `test_build_root_reset_rescans_after_removal` and `test_build_root_reset_runs_the_reach_check`, also replace `rewalk_matches` in process so that step 6 is reached). Then step 6 runs on the **live root**, the content scan (D6) and then the git reach check (D7), and the expected tree is removed. It prints the published line `RESET: removed=<n> restored=<n>` and then the same `ROOT: READY` token as the original build, with `path=` the live root. The rule is over the axis "what a cycle leaves in its root": by-products are never enumerated, because anything not in the build is removed, so a by-product kind the wrapper adds later is removed too. **The reset never follows a symlink in the live root**, so a by-product a cycle left as a link cannot make it delete or write outside the root: a live entry that is a symlink is unlinked, never resolved (`# M:GAS-RESET-NOFOLLOW-REMOVE`); while a placed file's parent directories are re-created, a parent that is not a real directory (a symlink included) is unlinked and made a directory (`# M:GAS-RESET-NOFOLLOW-PARENT`); and each placed file is written through `os.open(…, O_NOFOLLOW)` (`# M:GAS-RESET-NOFOLLOW-WRITE`), with a link found at that path (`ELOOP`) unlinked and the file created afresh. The re-walk then admits only regular files and directories. The reset adds no AC-5.4 reason form: its refusals are `internal:ResetArgsConflict`, `internal:ResetPurposeNotS1`, the precondition's four `internal:ResetTarget…` classes and `root_git:<path>`, `internal:RootResetMismatch`, and the existing `leak:<path>`, `root_git:<path>` and `check-ledger` reasons of the steps it re-runs. The reset `ROOT: READY` line is what the next cycle's `record-cycle --root-record` reads (D8). Residual, stated exactly: state an agent keeps outside the root (its own session store, cli logs, caches under `$HOME`) is not reset; that is AC-2.6's "reads outside the root by absolute path" residual.

**Order of operations**, each step re-read before the next (base §"Mutation verification"):
1. Read the exclusion list from `<list-commit>:docs/03-analysis/probes/grok-audit-surface/exclusions.txt` with `git cat-file blob`. `--list-commit` defaults to `HEAD` of `--repo`. The probe never reads the work tree copy. Record `list_commit` (full sha) and `list_blob` (`git rev-parse <list-commit>:<path>`).
2. Run the D4 checks on the calibration sha (the needles of step 5 come from the ledger).
3. Export `git archive --format=tar <calibration sha>`. Its stdout is read by `tarfile` with `extractall(filter="data")` into the fresh root. A `tarfile.FilterError` on member `m` refuses `leak:<m>`: a member the data filter rejects would land outside the root.
4. Remove every list entry (format below), then **assert each removed path is gone** by re-walking the root.
5. Place the documents, writing each as bytes from `git cat-file blob <calibration sha>:<path>`. One function, `placements(doc, sources) -> {live path: tree path}` (the parsed `--sources` mapping, D1), decides every placement, and `extract`'s quote resolver calls the same function (D12). The seeded target `seeded/<feature>.<phase>.md` goes to its live path (`docs/01-plan/features/<feature>.<phase>.md`, or `docs/02-design/features/<feature>.design.md`). Then only the paired documents the assembler reads for that phase are placed, at their live paths, from `docs/archive/<yyyy-mm>/<feature>/`: a plan root gets the spec; a design root gets the spec and the plan; an impl-plan root gets the design.
6. Run the content scan (D6), then the git reach check (D7). Only then print `ROOT: READY`.

**Exclusion list format** (`docs/03-analysis/probes/grok-audit-surface/exclusions.txt`, on `main`). It is UTF-8 with one entry per line, and `#` starts a comment. There are two kinds. `dir <tree path>` removes that subtree. `name-contains <s>` removes every file or directory, at any depth, whose final path component contains `<s>`. Any other line refuses with `leak:docs/03-analysis/probes/grok-audit-surface/exclusions.txt` (spec AC-5.4: "a line of the declared exclusion list outside the list's grammar (the path is then the list's own path)"). An entry naming a path absent from the export is counted in `absent=<n>` and is not a refusal. The committed list holds exactly these six entries:

```

dir docs/archive/2026-09/tdd-gate-fail-opens
dir docs/archive/2026-10/agy-coder-fallback
dir docs/03-analysis/probes/grok-audit-surface
dir docs/03-analysis/agy-coder-fallback.authoring
name-contains grok-audit-surface
```

**DECISION (design-author):** `name-contains` is a superset of the spec's "final component begins with `grok-audit-surface`" (which AC-2.6 allows as "at least"). At `94a4fd2c` it also removes `docs/handoffs/2026-10-18-main__grok-audit-surface-phase3.md` and `docs/handoffs/2026-10-18-main__grok-audit-surface-phase3-exit.md`, which discuss this feature's answer key and which "begins with" would leave in place (Readings). Residual: a file that discusses the feature without its name in the file name (`docs/learnings.md` and `docs/skill-candidates.md` mention it) is a name mention, AC-2.6 residual (4). Verbatim seed text in any such file is caught by the scan, not by the list.

**Which list version** (spec AC-3.6: "Every export root records the list blob id it was built with, and those records go to the branch with the cycle that ran in the root"). The operator captures each `build-root` stdout to a file, and `record-cycle --root-record <file>` copies its one `ROOT: READY` line into the cycle directory as `root.txt`. `record-cycle` refuses `root_record:no_line` when the file holds no line starting `ROOT: READY ` or more than one (`# M:GAS-RECORD-ROOT-LINE`), and also when its one such line is malformed, i.e. `parse_root_line` returns `None` for it (`# M:GAS-RECORD-ROOT-MALFORMED`; a plan extension, implemented): a word without `=` or with an empty value, a repeated key, or a key set other than exactly `doc purpose path calibration list_commit list_blob absent`. A malformed line is reported as no line, never as `root_record:path_mismatch`, because it names no root. It refuses `root_record:path_mismatch` when a well-formed line's `path=` is not the resolved `--root`. So every recorded cycle names the root it ran in and that root's list blob, and the association is checked when the record is made. `rescore` refuses `list_changed:<oid>` (D9 step 5).

### D6. Content scan (AC-2.6 class closer)
- **Normaliser**, one function used for needle and haystack alike: `re.sub(r"\s+", " ", data.decode("utf-8", errors="replace"))`. There is no strip and no case folding.
- **Needles**: for all 27 seeds (every ledger record, not only the target's), the normalised `original` and the normalised `expected`. An empty needle has already refused `ledger_counts` (D4).
- **Walk**: `os.walk(root, followlinks=False)`. Every symlink, whether to a file or a directory, refuses `leak:<root-relative path>` whatever its target. Every regular file is read and scanned. The first hit in sorted path order refuses `leak:<root-relative path>`.
- **The one exemption**: a hit on seed `s`'s `original` in file `f` is exempt iff `f` sits at the live path where `s`'s own source document is placed as a paired copy, AND `sha256(f) == sha256(archive source of s)`. `expected` is never exempt. The seeded target sits at its source's live path, but its sha differs, so a hit there is a `leak` (spec: widen the span).
- **Residuals**, as the spec states them: paraphrase or partial copy; non-UTF-8 stored forms; reads outside the root by absolute path; name mentions; submodule paths, which `git archive` exports empty (a C2 seed must not name a path under `beautiful_prose`, `drawio-skills` or `humanizer`). Added here: special files other than symlinks are not refused. `git archive` emits only regular files, directories and symlinks.

### D7. Git reach check
The check walks the root for any entry named `.git` (file or directory) at any depth; the first one in sorted order refuses `root_git:<root-relative path>`. It then runs `git -C <root> rev-parse --absolute-git-dir` in an environment with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` removed, which is the same environment the dispatch runs in. Exit 0 refuses `root_git:<the printed git dir>`.

### D8. Live dispatch and recording (S1, S2; the runbook in the measurement doc)
- **Kept directory**: `KEEP=$HOME/.local/state/h-mad/grok-audit-surface`. Under it, `authoring/` exists during S0b only. The stem dir for one cycle is `run-<cal12>/stem/<cycle-id>/`, and the recorded by-products go to `run-<cal12>/data/{s1,s2}/…`. `<cal12>` is the first 12 hex of the calibration sha, and `<cycle-id>` is `s1-<surface>` or `s2-d<k>-v<N>`. The kept directory lives under `$HOME`, so it is outside every export root (which live under `$TMPDIR`); `git -C $HOME/.local/state rev-parse --git-dir` fails there (Readings). The stem dir is created before the cycle, because the wrapper refuses a stem dir that is not "an existing absolute directory without ':'". Nothing the smoke derives from lives in `/tmp`, so `SMOKE: UNREADABLE`'s "derive again from the same passes" has its inputs.
- **Re-smoke target (operator decision D4, `docs/03-analysis/grok-audit-surface.decision-2026-10-19-d4.md`, verbatim):** "The audit-path re-smoke runs against the grok on PATH at S1, whatever its version; the smoke records that binary's path and its `grok --version` line, and the measurement doc names that version. No phase document names a target grok version." This design therefore names no grok version; every place that needs one reads the recorded line below.

Every later redirection or `tee` in this runbook writes into one of these three directories or into a `$STEM` directory the cycle block creates first, and `record-cycle` creates its `--dest` with its parents, so the runbook works from an empty `$KEEP`.
- **Versions (S1, once, before the first cycle).** `{ if g=$(command -v grok); then echo "grok_binary=$g $("$g" --version 2>&1 | head -1)"; else echo "grok_binary=absent"; fi; agy --version; codex --version; } > "$KEEP/run-<cal12>/data/s1/versions.txt" 2>&1`, with a missing agy or codex `command not found` line kept as written. This is the AC-3.6 version record, still three lines.
- **One cycle**, as the runbook pins it. Every `<…>` is filled before the run; this block is a template for the measurement doc, not a command to run as written.

  ```bash
  STEM="$KEEP/run-<cal12>/stem/<cycle-id>"; mkdir -p "$STEM"
  python3 docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py build-root --repo . \
  ```

  `[--reset "${ROOT:?}"]` is written only for S1's second and third cycles. `${ROOT:?}` makes the shell stop before the probe runs when `ROOT` is unset or empty (a fresh shell after a resume), and the D5 precondition refuses any other target that is not an S1 root of this document directly under the temp directory, before anything is removed. For S1 the three cycles share the one root: the first cycle's `build-root` line builds it, and each later cycle's line resets it (D5, "Resetting the S1 root between its cycles") after the previous cycle's `record-cycle` has run, so every S1 dispatch starts in a root equal to its build that has just passed the content scan and the reach check. Each cycle's `record-cycle` reads that cycle's own `$STEM.root.txt`, and the operator does not dispatch when the line's token is not `ROOT: READY`. S1 runs the cycle three times: `--passes 1 --surfaces grok` (and writes `$((t1-t0))` to `wall_seconds.txt` in the grok dest), then `agy`, then `codex` when `command -v codex` succeeds. S1 omits `--timeout`, so the wrapper default of 900 s applies. S2 runs `--passes 3 --surfaces codex,agy,grok`, or `--passes 2 --surfaces agy,grok` when codex is absent or refused the root at S1, with the AC-1.4 derived `--timeout`. The time bound is the wrapper's own `--timeout`, never `timeout <s>` (base §"Portable time bounds").
- **Resolved model (S1, right after each surface's cycle).** `python3 h-mad/scripts/h_mad_resolved_model.py grok --log "$DEST/p1.log"` for grok, the same with `codex` for codex, and for agy, a dispatch-specific selection of agy's own cli logs, below. Each writes stdout and stderr to `"$DEST/resolved_model.txt"`. A refusal (`RESOLVED-MODEL: UNKNOWN — …`, exit 2) is kept as written and published as unknown.

  **agy provenance.** The script refuses an `exec agy` `--log` (stream-json carries no model field), and without `--log` `agy_from_cli_logs` sorts every `cli-*.log` under `~/.gemini/antigravity-cli/log` by mtime and reads the newest, refusing only when the two newest name different models. Running it right after the cycle therefore names the newest-written agy process, not this dispatch: when the two newest logs both belong to another agy process (or agree on its model), that process's model is reported with no refusal, whatever this dispatch's log says. So the runbook selects the dispatch's own logs by content and hands the helper only those. Each agy cli log is named by its process start (`cli-<yyyymmdd>_<hhmmss>.log`) and carries the line `workspaceDirs=[<dir>]` (Readings). The selection is: the `cli-*.log` names absent from a listing taken just before the agy cycle, AND whose text contains `workspaceDirs=[$ROOT]` or `workspaceDirs=[$ROOTP]`, where `ROOTP=$(cd "$ROOT" && pwd -P)` is the physical spelling of the S1 root's unique `mkdtemp` path (on this Mac `$TMPDIR` is `/var/folders/…` and its physical form `/private/var/folders/…`, and which one agy logs is not measured). Exactly one such file is copied into an otherwise empty directory and the helper reads only it; zero, or more than one, publishes `UNKNOWN`:

  ```bash

  done
  if [ "$n" -eq 1 ]; then
    python3 h-mad/scripts/h_mad_resolved_model.py agy --agy-log-dir "$STEM.agy-log"
  else
    echo "RESOLVED-MODEL: UNKNOWN — agy attribution unavailable: $n new cli logs name workspaceDirs=[$ROOT] or [$ROOTP]"
  fi > "$DEST/resolved_model.txt" 2>&1
  ```

  This block runs after the agy cycle's `record-cycle` and before the codex cycle block begins: it reads the agy cycle's `$STEM`, `$ROOT` and `$DEST`, which the next cycle block reassigns, and it needs the root to exist, which holds until the next cycle's `build-root --reset`.

  **Phase-5 step, before S1 (not run by this design):** one tracer, `h-mad/bin/hmad-dispatch exec agy <prompt file> --cd "$T"` with `T=$(mktemp -d)` and a one-line prompt, with the `cli-*.log` listing taken before it; the one new cli log's `workspaceDirs=` line (`grep -o -m1 'workspaceDirs=\[[^]]*\]'`) is recorded as a Reading in the measurement doc beside `$T` and `$(cd "$T" && pwd -P)`. If it names neither spelling, the selection above is re-derived from that reading before S1 dispatches.

  Residual, stated exactly: until that tracer is read, whether `hmad-dispatch`'s `exec agy` leg logs the export root as its `workspaceDirs` entry, in either the `ROOT: READY` spelling or its `pwd -P` spelling, is not measured here (the Readings row is over interactive agy runs). If it does not, `n` is 0 and the line is `UNKNOWN`, which is fail-safe: the selection can drop an attribution, and it names another process's model only if a second agy process was started inside the same export root during the cycle, which no step of this runbook does.
- **`record-cycle`** checks, in this order, the first failure refusing: `--stem` and `--root` are directories and `--root-record`, `--stdout` and `--command` are readable (`input_missing:<path>`, the first missing one); the root record (D5, `root_record:no_line`, then `root_record:path_mismatch`); the stdout's `AUDITCYCLE: ` line (`no_auditcycle_line:<file>`); the command file; the stem prefix. It reads `--feature`, `--phase` and `--cycle` from the command file, each as `--flag value` or `--flag=value` (`shlex` split); a flag absent or repeated, a `--feature` value that is empty or begins `--`, a `--phase` outside `plan`, `design`, `impl-plan`, or a `--cycle` that is not a positive integer refuses `command_unparseable:<file>`. Every selected source is read before any destination file is created (a read failure there refuses `input_missing:<path>`), and each D3 file is copied byte for byte. It copies the D3 files from the stem dir (matched by the stem's single `audit_<feature>_<phase>_cycle<N>_run*` prefix; zero or several prefixes refuse `stem_prefix:<n>`), copies from the root only the `<feature>.<phase>.audit.v<N>.p*` reports, sidecars and pass logs of this cycle's `<N>`, and writes `root.txt` (D5). It creates `--dest` with its parents (`mkdir(parents=True, exist_ok=True)`) before the first copy. It then re-lists the dest and prints `files=<n>`. It refuses `no_auditcycle_line:<file>` when the stdout file holds no line starting `AUDITCYCLE: `, so a cycle whose wrapper exited 4 on assembly failure is caught at record time as well as at score time (`cycle_token`).
- **Re-dispatch (AC-3.4).** A cycle whose recorded `AUDITCYCLE:` is `UNVERIFIED` (any reason, `prompt_divergence` and `assemble_halt:pN` included) is re-run once, in a fresh root (`s2v2`), as `--cycle 2`, which gives a new sentinel. No third cycle is run.

### D9. Calibration data, the shas and the ref (`commit-data`, `main-leak`, `rescore`; AC-2.7)
- **No checkout anywhere.** `commit-data` builds each branch commit with plumbing in the operator's `main` clone. It uses a temporary index (`GIT_INDEX_FILE=<mkdtemp>/index`): `git read-tree <parent>`; `git hash-object -w` for each file under `--src`; `git update-index --add --cacheinfo 100644,<blob>,<calibration dir>/<rel>`; `git write-tree`; `git commit-tree <tree> -p <parent> -m <message>`; `git update-ref refs/heads/calibration/grok-audit-surface <new> <expected old>`. The expected old value is the parent when the ref exists, and the zero-oid form (`git update-ref <ref> <new> ""`) for the first commit. It refuses, and writes no ref, with `parent_unknown:<sha>` when `--parent` is not a commit, `ref_moved:<oid>` when the ref's current value is neither absent nor `--parent` (`<oid>` is that current value), and `outside_calibration_dir:<path>` when a `--src` path would land outside the calibration directory. It re-reads `git rev-parse refs/heads/calibration/grok-audit-surface` and prints `COMMIT: OK` only when that equals `<new>`, and `COMMIT: REFUSED reason=ref_unconfirmed` otherwise. The work tree and the real index are never touched. `$KEEP/authoring/` (the ledger and seeded copies as plain files) is deleted after the calibration sha is pushed and confirmed, so during S1 and S2 the ledger exists only as git objects (the AC-2.6 residual (3) and AC-2.7 residual (5) routes, which stay open).
- **The commits on the branch.** The first commit's parent is the `main` sha that holds S0. One or more commits follow while S0b answers refusals by re-choosing spans (never an amend). The **calibration sha** is the first one on which `check-ledger` reads `LEDGER: OK` and every `build-root` reads `ROOT: READY`. Next comes the **smoke commit** holding `s1/` (each S1 cycle with its `root.txt`, and `s1/versions.txt`), on every smoke outcome that derives to `PASS` or `FAIL`. Last, on `SMOKE: PASS` only, comes the **score sha** holding `s2/` (each cycle with its `root.txt`), `findings.jsonl`, `key.jsonl`, `labels.jsonl` and `extract.txt`. Every commit after the calibration sha only adds files under the calibration directory. Each push is `git push origin refs/heads/calibration/grok-audit-surface:refs/heads/calibration/grok-audit-surface` (no force), confirmed by `git ls-remote origin refs/heads/calibration/grok-audit-surface` printing the expected sha. On a smoke failure the smoke commit is the branch tip and the measurement doc cites it (spec AC-1.8).
- **Ref and sha checks** (shared by `main-leak` and `rescore`), in this order. The first failure refuses.
  1. `git ls-remote --exit-code <remote> refs/heads/calibration/grok-audit-surface`: exit 2 refuses `calibration_ref:ref_absent`; any other non-zero exit (128 for a missing remote or an unreachable URL; Readings) refuses `calibration_ref:fetch_failed`. Then `git fetch --no-tags <remote> +refs/heads/calibration/grok-audit-surface:refs/h-mad-probe/grok-audit-surface/calibration`; a non-zero exit refuses `calibration_ref:fetch_failed`, and so does a missing local ref afterwards. The fetched tip is that ref. It is a private namespace, never a branch, so nothing is ever checked out from it.
  2. For each cited sha (calibration, smoke, then score when given): `git cat-file -e <sha>^{commit}` fails, which refuses `calibration_ref:sha_unknown:<sha>`; or `git merge-base --is-ancestor <sha> <tip>` exits 1, which refuses `calibration_ref:not_on_ref:<sha>`.
- **Drift check** (spec AC-2.7, "Two shas, and the smoke commit"), run for the smoke commit and, when given, the score sha, each against the calibration sha. **DECISION (design-author):** the score sha is also required to descend from the smoke commit, because the spec defines it as "the later branch commit, descending from the smoke commit"; that failure refuses `calibration_drift:not_descendant` too. For a later commit `L`:
  1. `git merge-base --is-ancestor <calibration> <L>` exits 1: `calibration_drift:not_descendant`.
  2. `git diff --name-only -z <calibration> <L>`, sorted: the first path not under the calibration directory refuses `calibration_drift:<path>`.
  3. For every blob under the calibration directory in `git ls-tree -r -z <calibration>`, sorted: absent at `L`, or present with a different blob id, refuses `calibration_drift:<path>`. This is the byte-identity rule ("every file present at the calibration sha … is byte-identical at the smoke commit and at the score sha"), so the ledger and seeded copies the roots were built from are the ones scored.
- **Main leak check** (`main-leak`, and step 4 of `rescore`). The data commit `D` is the score sha when one is given, and otherwise the smoke commit (spec AC-2.7: "or, when there is no score sha (a smoke failure), at the smoke commit"). `D`'s tree is exported into a fresh `mkdtemp` directory and the D7 reach check is run on it. Then every blob of `git ls-tree -r -z HEAD` is read through `git cat-file --batch`, and the first path in sorted order refuses `main_leak:<path>` on: (i) `sha256(blob)` equal to the sha256 of any file in `calibration_data_files(export of D)` (D3); (ii) the normalised blob containing any normalised `expected`; (iii) the normalised blob containing any normalised `seeded` span that does **not** occur in the normalised archived source of the same seed. `main-leak` prints `MAINLEAK: CLEAN scanned=<HEAD sha40> data=<D sha40> blobs=<n>`; `rescore` prints the same facts as the published line `SCANNED: main=<HEAD sha40> data=<D sha40> blobs=<n>`. **When it runs:** `main-leak` runs on every outcome before the measurement doc is committed to `main` (without `--score-sha` on a smoke failure, with it otherwise), and `rescore` runs the same function again. A refusal blocks that commit; the leak is removed from `main` and the check is run again.
- **`rescore` steps**, in AC-6.4's order:
  1. The ref and sha checks for the calibration, smoke and score shas.
  2. The drift check for the smoke commit and the score sha.
  3. Export the score sha into a fresh `mkdtemp` directory and run the D7 reach check on it.
  4. The main leak check, with `D` = the score sha.
  5. **List check.** The recorded root lines are every `root.txt` under the export, in record order (`s1/grok`, `s1/agy`, `s1/codex`, then `s2/d1/v1`, `s2/d1/v2`, … `s2/d9/v2`, numeric in `k`). It prints `LIST: recorded=<oid>[,<oid>…] current=<oid>`, where `current` is `git rev-parse HEAD:docs/03-analysis/probes/grok-audit-surface/exclusions.txt`. The first recorded cycle whose `root.txt` is absent (`# M:GAS-LIST-UNRECORDED`), or holds no line starting `ROOT: READY ` or more than one, or whose one such line `parse_root_line` rejects (`# M:GAS-LIST-MALFORMED`; the D5 malformed-line rule, which includes a line with no `list_blob=` field; a plan extension, implemented) refuses `list_changed:unrecorded`; otherwise the first recorded blob that differs from `current` refuses `list_changed:<oid>` (spec AC-5.4).
  6. `check_ledger` on the export; `build-root --purpose rescore` for `d1`…`d9` from the calibration sha, with the list at `HEAD`, in process, printing no `LEDGER:` or `ROOT:` token.
  7. `score` on the export, in process.
  8. In a `finally`: remove every temporary directory, re-list to confirm removal, and print the `[H-MAD]` marker on stderr. A removal failure is printed on stderr and never replaces the token.

### D10. One authority per wrapper verdict: the final member list (plan "The class")

### D11. Smoke mode (AC-1.7)
- **Inputs** (`--data <dir>/s1`): `grok/` and `agy/`, which are required, and `codex/`, which is optional (its absence means "not run"). Each holds D3's cycle files. A cycle **reached dispatch** when its `AUDITCYCLE:` line carries a `delivered=` field: on a halt (`assemble_halt:pN`, `prompt_divergence`) the wrapper renders the line from no pass results, so it has no `delivered=` field and no `Effort:` block (Readings).
- **UNREADABLE first**, so that exactly one reason is printed. The inputs are checked in this fixed order, and the first problem wins:
  1. `grok/auditcycle.txt`: absent → `input_missing`; not exactly one line that `parse_auditcycle` accepts (`^AUDITCYCLE: (PASS|FAIL|UNVERIFIED)( \S+)*$`) → `input_unparseable`; a malformed `Effort:` block (below), whether or not the cycle reached dispatch → `input_unparseable:<grok/auditcycle.txt>` (`# M:GAS-SMOKE-EFFORT-MALFORMED`).

     **The `Effort:` block grammar**, the one reading `parse_effort_items` makes (smoke and score both call it; implemented as the plan's Task 4 states): the block opens at a line equal to `Effort:`; its items are the lines after it that begin `- `, up to the first line that does not; each item is that line without the `- `. A text with no `Effort:` line has no block and gives `[]` (a halted cycle, which `render` writes without one). It gives `None` (malformed) when there are two or more `Effort:` lines (`# M:GAS-PARSE-EFFORT-TWICE`), when an item does not begin `p<digits> ` (`# M:GAS-PARSE-EFFORT-ITEM`), or when the block has no item (`# M:GAS-PARSE-EFFORT-EMPTY`). This is the shape `h_mad_audit_cycle.render` writes: `Effort:`, then one `- <item>` per `_effort_items` entry, then the next block's heading or the `[H-MAD]` marker.
  2. `grok/p1.log`, when the grok cycle reached dispatch: absent → `input_missing`; no line that parses as a JSON object with a string `type` → `input_unparseable`. This type reading (`grok_log_types`) runs `json.loads` per line and skips a line that raises `ValueError` or `RecursionError`, exactly as `scan_grok` does; unlike `scan_grok`, it applies no `GROK_MAX_DEPTH` bound.
  3. The grok `Effort:` item for `p1`, when the grok cycle reached dispatch: absent (no item beginning `p1 `) → `input_unparseable:<grok/auditcycle.txt>` (the wrapper renders one for every pass that carried a log). Present, step 3 refuses only a **wrong-file rendering**, the item `_effort_items` gives when the measured file was not a readable grok transcript at all: `p1 unreadable (log named but not readable)` (shapes `missing` and `empty`) and the item beginning `p1 not measured (codex-text log` (shape `codex-text`); each refuses `input_unparseable:<grok/auditcycle.txt>`. Three renderings fall through to the reasons, each recognised positively: the **positive grok item**, which matches `^p1 tools=\d+ ok=\d+ unresolved=\d+ thinking=\d+ format=grok( |$)` (what `_effort_items` renders for shape `grok`, with its optional ` paths=… code=… other=… unmeasured=…` suffix from `format_targets` and its optional ` low-evidence (…)` suffix after the space); the **truncated item**, which begins `p1 not measured (grok log truncated` (shape `grok-truncated`); and the **non-grok counts item**, which matches `^p1 tools=\d+ ok=\d+ failed=\d+ thinking=\d+( |$)` (shapes `parsed` and `unparseable`, which `_effort_items` renders identically). A readable log that is not grok's shape is the AC-1.2 drift the smoke exists to report, so it must reach `FAIL` and not `UNREADABLE`, which the spec reserves for inputs that "could not be read". An item in none of these five forms (none today: the renderer pin below maps each of `measure_effort`'s seven shapes to exactly one form) also refuses `input_unparseable:<grok/auditcycle.txt>`, so a shape `_effort_items` adds later refuses until this design names it. AC-1.1 ("reports `format=grok` (shape `grok`), not `grok-truncated`") is therefore met only by the positive grok item, and a non-grok item that is not a wrong file **fails** the smoke rather than refusing it: the truncated item through the `truncated` reason, and a non-grok counts item through `vocab_missing`. For `unparseable` that is guaranteed **outside residual (2)'s deep-event class**: `measure_effort` gives `unparseable` only when `scan_grok` saw no `_GROK_TYPES` type within its depth bound, and `end`, `tool_call` and `tool_call_update` are all `_GROK_TYPES` members, so, when every line the step-2 reading counts is also within that bound, all three are absent from the log's type set and `vocab_missing:end,vocab_missing:tool_call,vocab_missing:tool_call_update` fires. Residual, stated exactly: (1) a `parsed` item (the log carries an agy event, which `measure_effort` tests before grok) on a log whose type set holds all three of `end`, `tool_call` and `tool_call_update` fires no reason from the item and can reach `SMOKE: PASS`; (2) an `unparseable` item on a log that carries `end`, `tool_call` or `tool_call_update` only on lines nested deeper than `GROK_MAX_DEPTH` (64), which `scan_grok` skips and this step-2 type reading, having no depth bound, counts, fires no `vocab_missing` for each type so carried, and with all three so carried can reach `SMOKE: PASS`. A line that raises `RecursionError` in `json.loads` is not in this residual: both readers skip it. Both are pinned as residuals by fixtures (Test Plan), so a change that closes or widens either shows.
  4. The grok collected report, when its `delivered=` value is `report-file` or `out`: absent → `input_missing` (spec AC-1.7: "a delivered pass's collected report, that the derivation needs, is absent"); `_gate_token` finds no `GATE:` line in the gate's stdout → `input_unparseable`.
  5. `agy/auditcycle.txt`, as in 1.
  6. The agy collected report, as in 4.
  7. `codex/auditcycle.txt` and the codex collected report, as in 1 and 4, when `codex/` is present.
  8. The two vocabulary sources: no `_GROK_TYPES` frozenset, or no `_GROK_TYPES_RE=` line → `input_unparseable`.

  The agy and codex pass logs are **not** smoke inputs (no smoke reason reads them), and no `Effort:` item is required of agy or codex, so a halted agy cycle or a `codex-text` log never makes the smoke UNREADABLE. v1.0 required both and over-refused.
- **Vocabulary injection (plan obligation).** `--vocab-py <path>` (default `h-mad/scripts/h_mad_review_evidence.py`) is loaded with `importlib.util.spec_from_file_location("_gas_vocab_py", path)` and its `_GROK_TYPES` attribute is read. `--vocab-sh <path>` (default `h-mad/scripts/hmad-dispatch.sh`) is read as text. A fixture drives `vocab_split` by passing a three-line Python file and a one-line shell file whose sets differ.
- **Delivery and acceptance**, per surface, from the AC-1.3 evidence (spec AC-1.3, verbatim: "A pass **delivers a report** when its value in the `delivered=` field of the cycle's `AUDITCYCLE:` line is `report-file` or `out`, AND `h_mad_audit_gate.py`, run on that pass's collected report, prints `GATE: PASS` or `GATE: FAIL`."). `delivered(surface)` is true iff the cycle reached dispatch, its `p1` value is `report-file` or `out`, and the gate's token is `PASS` or `FAIL`. `none`, `unscorable:<reason>`, a missing field and any other gate token (`INVALID`, `UNSTAMPABLE`) are not delivery. `accepts(surface)` is `delivered(surface)` and a verdict word other than `UNVERIFIED` (spec AC-1.6). **v1.0's narrowing to `report-file` is reverted**: `delivered=out` with a collected, gate-scored report is delivery.
- **Reasons, each from its own observation, in AC-1.7 order:**
  - `truncated`: the grok `p1` Effort item is the rendering `_effort_items` gives a `grok-truncated` effort (it begins `p1 not measured (grok log truncated`). Step 3 has already refused the wrong-file renderings and any unrecognised one, so the items that reach the reasons are the positive grok item, this one and the non-grok counts item. All four step-3 predicates (positive grok, truncated, non-grok counts, wrong file) are pinned against the renderer (Test Plan), so a change of the wording fails a test rather than silently disarming a reason or the refusal.
  - `vocab_split`: the two vocabulary sets differ.
  - `vocab_missing:<type>`, for each of `end`, `tool_call`, `tool_call_update` (in that order) absent from the grok log's distinct `type` set. When the grok cycle did not reach dispatch there is no log, the set is empty, and all three are printed.
  - `no_delivery`: `not delivered(grok)`.
  - `nongit_root_refused:grok`, then `nongit_root_refused:agy`: `not accepts(surface)`.

  **Coupled reasons** (spec AC-1.7: "Every grok `no_delivery` is therefore printed as `no_delivery,nongit_root_refused:grok`"). That coupling follows from the definitions above (`accepts` requires `delivered`), so no fixture can separate it, and the tests assert the coupled list. The second-kind couplings (`truncated` with `vocab_missing:end` and `nongit_root_refused:grok` on real runs) are separated by fixtures, because each reason reads its own observation.
- **codex** goes through the same `accepts` predicate, is printed as `ROOT-ACCEPT: codex=accepted|refused|not_run`, and is never a reason.
- **Published lines, before the token:** one `VOCAB: type=<t> re=in|out frozenset=in|out tool=yes|no usage=yes|no` per distinct type, sorted (or `VOCAB: none reason=no_grok_dispatch` when the grok cycle did not reach dispatch). Here `tool`/`usage` is `yes` when any key of that type's events, to depth 2, contains `tool`, or contains `usage` or `token`. Then `ROOT-ACCEPT: grok=… agy=… codex=…`, and `TIMEOUT: wall_seconds=<W> derived=<max(900, ceil(1.5·W/60)·60)>` (or `wall_seconds=unrecorded`; `wall_seconds.txt` is not a smoke input, so its absence is not UNREADABLE). Then `GROK-BINARY: path=<abs> version=<line>`, copied from the `grok_binary=` first line of `<data>/versions.txt` (D8), where `<line>` is the recorded `grok --version` line verbatim; or `GROK-BINARY: unrecorded` when that file or that line is absent or the line is `grok_binary=absent`. Like `wall_seconds.txt`, `versions.txt` is not a smoke input and never makes the smoke UNREADABLE or adds a reason (AC-1.7's reasons and UNREADABLE triggers are unchanged); an unrecorded binary is caught at S3 instead, where the measurement doc must name the version (D15, Doc pins).
- **Exit**: 0 on `SMOKE: PASS` and `SMOKE: FAIL reason=<r>[,<r>…]`, and 2 on `SMOKE: UNREADABLE reason=<r>`.

### D12. Extraction, blinding and hints (`extract`; AC-4.1–4.5)
- **Inputs.** `extract` runs in S2 before the score sha exists, so it reads two places: the exported tree of `--base-sha` (the smoke commit) or `--tree`, for the ledger, the seeded copies and the archive sources; and `--s2 <dir>` (`$KEEP/run-<cal12>/data/s2`), for the recorded cycles. The same function, `extract_all(tree, s2_dir, sources)`, is what `score` calls for re-extraction, with `s2_dir` the score-sha tree's own `s2/`; `sources` is the one parsed `--sources` mapping (D1), a required third argument (a plan extension, implemented), which `extract_all` passes to `check_ledger` and uses to number the documents `d1`…`d<3·len(sources)>`. It writes `findings.jsonl`, `key.jsonl` and `extract.txt` to `--out` (`$KEEP/run-<cal12>/data`), which `commit-data` then commits, with the labels, as the score sha.
- **The stands rule (AC-3.4, plan Risks).** For each document, `v1` is read. If its verdict word is `UNVERIFIED`, `v2` must exist and **the whole of `v2` stands for every surface**, including surfaces whose `v1` pass was fine; nothing in `v1` is scored. If `v1` is not `UNVERIFIED`, `v1` stands. If `v2` is also `UNVERIFIED`, it still stands: each pass that did not deliver (D11's `delivered`) contributes zero findings, and every delivered pass is scored even when its evidence was low.
- **Cycle-record refusals**, all `cycle_token:d<k>.v<N>`, exactly spec AC-5.4's seven triggers, each its own guard: (1) no recorded `AUDITCYCLE:` line; (2) a recorded line that does not parse; (3) `v1` is `UNVERIFIED` and no `v2` is recorded; (4) a `v2` is recorded although `v1` is not `UNVERIFIED`; (5) a `v3` or later; (6) a `command.txt` whose `--surfaces` is not exactly `codex,agy,grok` or `agy,grok`; (7) a pass whose `delivered=` value is `report-file` or `out` has no recorded collected report.
- **Pass → surface** is read from `command.txt`'s `--surfaces` list by pass index (AC-10.1's sense: index, not time).
- **Findings: the gate's own decision structure, not a re-implementation of it** (spec AC-4.1: "Extraction uses the gate's own machinery (`h_mad_audit_gate.classify_detail`, or the same section walk)"). The gate counts a section in `_section_detail` (called by `classify_detail`, which `classify` calls): an all-`None` section is zero; otherwise, for each group of `_bullet_groups(content)`, a group for which `_collapses(group, acknowledged)` is true counts once (its parent), and any other group counts every finding `_flat_findings(group["lines"])` returns; when no group yields a finding, the non-`None` content counts once (the fail-safe). The probe's pure walk `report_findings(text) -> {"must": [...], "should": [...]}` makes the same calls in the same order, with the same empty acknowledged set `classify(text)` uses. It splits sections the way `classify_detail` does (a stripped line equal to a key of `_gate.BLOCKING_SECTIONS` opens that section, any other `## ` line closes it, blank lines are dropped), then for each section:
  1. If every line's `_gate._payload` is a `_gate._is_none_sentinel` payload, the section has no findings.
  2. For each group of `_gate._bullet_groups(content)`: if `_gate._collapses(group, set())` (the line marked `# M:GAS-COLLAPSE-WIRE`), the group is **one** finding, whose text is the group's lines joined with `\n`. Otherwise the group yields one finding per real bullet, which is exactly `len(_gate._flat_findings(group["lines"]))` of them: each line for which `_gate._bullet_remainder(line.strip())` is not `None` and whose payload is real (non-empty, not a `None` sentinel) starts a finding, whose text is that line and the following lines of the group up to the next bullet line. A `- None` bullet starts no finding, and the lines after it up to the next bullet belong to no finding, as they classify nothing in `_flat_findings`.
  3. If step 2 gave no finding, the section's non-`None` content is one finding, its lines joined.

  So the walk's per-section count equals `_section_detail(content, set())["count"]` by construction. That includes the two shapes the v1.2 walk (one finding per real-parent group) got wrong: a short `Label:` parent (`- Build defects:` with two nested children) does not collapse, so it is three findings, as `classify` counts it; and a real parent with a `- None` child and then a real child does not collapse (`none_child`), so it is two. The production caller `extract_report(text, report)` calls `report_findings` and then obtains both counts from one `_gate.classify(text)` call, written as these five lines in this order:

  ```python
  found = report_findings(text)
  must, should = found["must"], found["should"]
  _counts = _gate.classify(text)
  must_count = _counts["must_count"]  # M:GAS-MUST-COUNT-WIRE
  should_count = _counts["should_count"]  # M:GAS-SHOULD-COUNT-WIRE
  ```

  The `classify` call is on an unmarked line, so each marked wire is one line that holds one integer, and X1/X2 (must) and X5/X6 (should) mutate it without changing its type, which is what keeps every row a test kill and not a crash kill. It then asserts `len(must) == must_count`; a mismatch refuses `must_count_mismatch:<report tree path>`. Since the walk now agrees with the gate on every shape by construction, the assertion catches a gate change after this design and a severed connection, and it is tested three ways: direct parity fixtures with the real `classify` (Test Plan, the `test_extract_parity_*` tests), `_gate.classify` replaced, and mutation rows in both directions on each wire (X1/X2 on the must count, X3/X4 on `_collapses`, X5/X6 on the should count). Residual, stated exactly: the section split is the one piece the probe writes itself, because `classify_detail` keeps it inline and exports no function for it; the parity fixtures and the count assertion on every report are what check it.
- **Should-fix findings (spec AC-4.5: "Should-fix hits are published separately and never enter the bar").** The `## Should-fix` section goes through the same walk. Its findings are **always** written to `findings.jsonl` with `"section": "should"` (must findings carry `"section": "must"`), are labelled like every finding, and are counted only on the published `SHOULD:` lines (D13); no path drops them. `extract_report` also compares their number with `should_count`, taken from the same `classify` call on the line marked `# M:GAS-SHOULD-COUNT-WIRE`. A difference is not a refusal, because AC-5.4 is closed and should-fix never enters the bar: the findings are written as the walk gives them, and `extract` prints the published line `SHOULD-COUNT: <report> walk=<n> gate=<m>` before its token, which the measurement doc carries under its observational heading (D15). Because the walk is the gate's own decision structure, that line can appear only after a gate change, and the parity fixtures fail in CI first.
- **Blinding**: ids are `F%08x` from `random.Random(shuffle_seed).getrandbits(32)`, redrawn on collision, and the order is shuffled by the same generator. `findings.jsonl` carries `id doc cycle section text quotes` (the `quote:` lines) and no surface or pass. `key.jsonl` carries `id doc cycle pass surface report` and nothing else; the shuffle seed is in `extract.txt`, which nothing in `score` reads. **DECISION (design-author):** v1.0's `{"shuffle_seed": n}` record in `key.jsonl` is gone, so the key file has one record shape and `key_mismatch` keeps exactly the AC-5.4 triggers (answers the agy nit).
- **Hints (AC-4.4)** are printed to stdout only, as `HINT: <id> candidate-fabrication` or `HINT: <id> candidate-hit:<seed-id>`, and are never written to any file that `score` reads. A `quote:` line is `quote: <path> › <span>` (the grammar `h-mad/audit-prompt.template.md` prescribes), with one level of backtick fencing stripped from the span. The path is resolved to the exported tree before it is checked, because the reviewer saw the root, not the tree: (1) a path under the cycle's recorded root (`root.txt` `path=`) is made root-relative; (2) a root-relative path that is a key of `placements(doc, sources)` (D5) is mapped to its tree path, so the seeded target resolves to `seeded/<feature>.<phase>.md` and each paired copy to its `docs/archive/<yyyy-mm>/<feature>/` source; (3) any other path is looked up in the tree as given. `candidate-fabrication` fires when the normalised span is absent from the resolved file, or the file is absent; `candidate-hit:<seed-id>` fires when the span overlaps a seed's normalised `seeded` span in the resolved seeded copy. Residual: a quote that names a file by a spelling none of the three rules resolves (a bare basename, say) yields a `candidate-fabrication` hint, which is advisory and never moves the score.

### D13. Scoring (`score`; AC-4.3, 4.5, 5.1–5.3)
- **Inputs**: `--tree`'s calibration directory: the ledger, the recorded cycles, `findings.jsonl`, `key.jsonl`, `labels.jsonl`.
- **Order of refusals**: `ledger_counts`, then `ledger_origin`, then `seed_rebuild` (D4), then `cycle_token` (D12), then `must_count_mismatch` (re-extracted), then `key_mismatch`, then `label:<id>`.
- **`key_mismatch`**, each trigger its own guard (spec AC-5.4: "the set of finding ids and the set of key ids differ; an id occurs twice in either file; a key record's surface is not the surface that the cycle's recorded dispatch command lists at that pass index, or its document, cycle or report is not the one the finding was extracted from; or re-extraction from the recorded reports does not give the findings the key maps them to"). Concretely: the id sets differ; an id occurs twice in `findings.jsonl`; an id occurs twice in `key.jsonl`; a key row's `surface` is not `--surfaces[pass − 1]` of `s2/<doc>/v<cycle>/command.txt`; a key row's `doc` or `cycle` differs from its finding's; a key row's `report` is not `s2/<doc>/v<cycle>/collected/<…>.p<pass>.md`; the multiset of `(report, section, text)` that re-extraction gives differs from the one the findings joined with the key give.
- **`label:<id>`**, each trigger its own guard (spec AC-5.4: "a finding with no label; two or more label records for one id, whether identical or conflicting; a label for an id not in the findings file; a value outside the four AC-4.3 labels; an `UNDECIDABLE` with no reason sentence; or a `HIT` naming a seed that is unknown or that belongs to another document than the finding's"). Every finding, must or should, takes exactly one label.
- **Per surface**: `hits` = distinct seeds with at least one `HIT` from that surface's **must** findings (AC-4.5); `n` musts; `f` fabricated; `u` undecidable; `fab_rate = Fraction(f, n−u)`, with `0/0` read as `Fraction(0)` (AC-5.2). Each surface prints `SURFACE: <s> recall=<hits>/27 musts=<n> fabricated=<f> undecidable=<u> fab_rate=<f>/<n−u> delivered=<n> low_evidence=<n|unreadable>`, in the order codex, agy, grok. The denominator is the ledger's seed count, derived. On the codex-unavailable shape, codex prints `SURFACE: codex not_run` (a surface that no standing cycle's `--surfaces` lists). The two published fields, both read from the standing cycle of each document (the stands rule, D12), with the surface's pass index taken from that cycle's `command.txt` `--surfaces`:
  - `delivered=<n>`: the number of standing cycles whose `delivered=` value at that pass index is `report-file` or `out`.
  - `low_evidence=<n>` (impl-plan Task 9's OPEN-DECISION, resolved as option (b) and implemented): the number of that surface's Effort items, over the standing cycles, that begin `p<index> ` and contain ` low-evidence (`, read through `parse_effort_items` (D11's grammar) from the cycle's `auditcycle.txt`. A cycle with no `Effort:` block contributes 0. When `parse_effort_items` returns `None` for any standing cycle, every surface that cycle lists publishes `low_evidence=unreadable` (`# M:GAS-SCORE-EFFORT-MALFORMED`), and stays `unreadable` for the rest of the run; this never refuses and adds no AC-5.4 reason, because the field is published only.

  Neither field enters the verdict: `verdict` takes only the per-surface `(hits, n, f, u)` (below), so a malformed Effort block changes the `SURFACE:` line and never the `SEEDSCORE:` token (`test_score_maps_a_malformed_effort_block`).
- **Observational lines** (spec AC-4.5 and FR-6's "observational per-phase and per-class split"), printed after the `SURFACE:` lines and computed by a function the verdict never calls:
  - `SHOULD: <s> hits=<distinct seeds HIT by should findings>/27 should=<n> fabricated=<f> undecidable=<u>`.
  - `SPLIT: <s> phase=<plan|design|impl-plan> recall=<hits>/<seeds in that phase> musts=<n> fabricated=<f>`, three per surface.
  - `SPLIT: <s> class=<C1|C2|C3|C4> recall=<hits>/<seeds of that class>`, four per surface. Fabrication has no class split, because a fabricated finding hits no seed.
  The per-phase and per-class denominators are derived from the ledger. The verdict function `verdict(totals)` takes the per-surface `(hits, n, f, u)` only, so none of these lines can move it (Test Plan: the split and should tests).
- **D3**: `d3(fg, rg, fa, ra) = (fg < fa and rg >= ra) or (fg == fa and rg > ra)`, over `Fraction` and `int`. The worst cases, with undecidables decided, use denominator `n`:
  - pessimistic grok: `Fraction(f+u, n)`
  - optimistic grok: `Fraction(f, n)`
  - and the same pair for agy.
  - `n = 0` reads as zero.
- **Verdict**, in spec AC-5.3's precedence ("The verdict is decided in this order, and the first rule that applies wins: (1) `seeds_undetected`; (2) PASS; (3) MISS (`reason=bar_missed`); (4) `undecidable_flips`."):
  1. If no surface (codex included) has a must hit: `INCONCLUSIVE reason=seeds_undetected`.
  2. `d3(pess_g, rg, opt_a, ra)`: `PASS`.
  3. `not d3(opt_g, rg, pess_a, ra)`: `MISS reason=bar_missed`.
  4. Otherwise: `INCONCLUSIVE reason=undecidable_flips`.
- **Token**: `SEEDSCORE: <V>[ reason=<r>] calibration=<sha40|unstated> score=<sha40|unstated>` is the last stdout line.

## Error Handling Strategy
- Every refusal is a token line in its mode's D2 grammar, read by callers from stdout and never from `$?` (base §"Audit-gate signal discipline").
- **AC-5.4 reasons, and where each fires** (the checking modes' `UNREADABLE` tokens):

  - `leak:<path>`: D5, D6
  - `root_git:<path>`: D5 (the reset target precondition), D7, D9
  - `must_count_mismatch:<report>`, `key_mismatch`, `label:<id>`: D12, D13
  - `calibration_drift:<path>`, `calibration_drift:not_descendant`, `calibration_ref:<kind>`, `main_leak:<path>`, `list_changed:<oid>`: D9
  - `cycle_token:<cycle>`: D12
  - `internal:<ExceptionName>`: D1, every mode (D2 `UsageError`; D5's seven reset classes)

  The order inside each mode is the order listed in its section.
- **Smoke**: `SMOKE: UNREADABLE reason=input_missing:<path>|input_unparseable:<path>` (exit 2) is decided before any FAIL reason (D11).
- **Recording modes**: `RECORD: REFUSED` and `COMMIT: REFUSED`, with the D2 reason sets (D8, D9).
- **Unexpected errors.** An exception that escapes a mode's own checks prints the mode's refusal token with `reason=internal:<ExceptionName>` (for `smoke`, `input_unparseable:<path>`), exit 2 (D1); its traceback goes to stderr unless it is one of the declared `ProbeRefusal` classes (D1, "Traceback scope"). An argv that names no mode prints `PROBE: UNREADABLE reason=unknown_mode`, exit 2 (D2). There is no exit without a token. v1.0's no-token traceback branch is removed (spec AC-5.1, AC-5.4 `internal:<ExceptionName>`).

## Test Strategy
- **Synthetic only, never the network or the real ref** (AC-2.7). Every AC-2.7 fixture builds `tmp_path/origin.git` (bare) and `tmp_path/work` with `origin` pointing at it, and creates the branch inside that repo. Each test whose clean case depends on `tmp_path` lying outside a work tree first asserts that `git -C tmp_path rev-parse --git-dir` fails; it does not skip.
- **The probe is driven as a subprocess** (`sys.executable` plus the literal path), so the exit code and the token are asserted together, and every refusal test asserts the **exact** last stdout line (prefix, word and reason). Pure helpers (the normaliser, `d3`, `verdict`, `calibration_data_files`, the token parsers) are also imported for unit tests, by path, through `importlib.util.spec_from_file_location`. Tests that must replace a function (`_gate.classify`, a mode handler) call `main(argv)` in process with `monkeypatch` and `capsys`.
- **Archive survival.** Each probe test module defines `PROBE = REPO / "docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py"` as a single literal, which is what `h_mad_archive_feature.probe_readers` matches (needle `docs/03-analysis/probes/grok-audit-surface` followed by a path boundary).
- **Tests over unchanged code** (FR-8, FR-9, FR-10, AC-7.2's stamp pin, the kept doc pins) are shown able to fail only by their mutation rows. **New probe guards** are RED first, and then each gets a row.
- **Incident replay** (base §"Incident replay"). The real artefacts are the archived documents and the live runs. AC-2.7 forbids real calibration data in the suite, so the replay is the S0b `check-ledger`/`build-root` run and the S3 `main-leak` and `rescore` runs over the real ref, whose token lines the measurement doc records.

  **The reset guards' P-rows, written out** (D5; the rule above applied to the seven guards v1.4 adds and the purpose guard the plan adds). Each `find` is the marked guard line and each `replace` makes that guard's condition never fire: `# M:GAS-RESET-EXCLUSIVE` → `test_build_root_reset_and_dest_parent_are_exclusive`; `# M:GAS-RESET-PURPOSE` → `test_build_root_reset_refuses_a_non_s1_purpose`; `# M:GAS-RESET-REWALK` → `test_build_root_reset_mismatch_is_internal`; `# M:GAS-RESET-ABS` → `test_build_root_reset_refuses_an_empty_target`; `# M:GAS-RESET-ISDIR` → `test_build_root_reset_refuses_a_missing_target`; `# M:GAS-RESET-TMPDIR` → `test_build_root_reset_refuses_a_target_outside_the_tempdir`; `# M:GAS-RESET-PREFIX` → `test_build_root_reset_refuses_another_documents_root`; `# M:GAS-RESET-REACH` → `test_build_root_reset_refuses_a_git_target`. Because guards 1–4 raise distinct classes, a disarmed guard whose input then falls to a later guard prints a different token, so each row kills on its own fixture rather than on a sibling's refusal.

  **The one gate or wrapper test with no row.** `test_m1_m2_raw_shapes_are_what_the_wrapper_says` is an authority check (it asserts what the wrapper emits, which the D10 opposed pairs then consume), not a pin over a guard or a wire, so it has no mutation row; every other test named in the Gate pins and Wrapper pins sections is a row target.

  **Two units, two derivations, neither carried.** The **marker-site** count is `grep -c 'M:GAS-' docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py` (matching lines). The **row** count is `len(json.load(open("h-mad/tests/mutation-specs/grok_audit_surface.json"))["mutations"])` (rows), which exceeds the site count wherever a site carries several alternatives. **Residual.** A row shows its test can fail on that one change. A property the test asserts that no row disturbs stays unshown. `--check-anchors` catches a row that no longer lands, not one that lands somewhere harmless.

The probe imports `classify`, `_gate_token`, `ORIGINS` and `_GROK_TYPES`, reads `_GROK_TYPES_RE` from its file, and reads wrapper verdicts from tokens through one parser per token kind (D10).
