# Design: grok-audit-surface

## Executive Summary
One stdlib-only probe, `docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py`, with nine modes (`check-ledger`, `build-root`, `record-cycle`, `commit-data`, `smoke`, `extract`, `score`, `rescore`, `main-leak`), a declared exclusion list beside it, six new test modules under `h-mad/tests/`, and one new mutation spec. Together they measure grok against agy on 27 seeds, read every verdict the wrapper already computes from the wrapper's own token lines, and keep all calibration data on the never-merged branch `calibration/grok-audit-surface`. `exit_check`, `round_check`, `combine` and `scan_grok` are pinned by tests and not edited. **FR-11 (spec v1.9–v1.12) edits the wrapper**: `exec grok` runs `--sandbox strict` by default (D16), `audit-cycle` gives each pass its own export root (D17), and a new verb `grok-canary` runs the per-run canary (D18). Two new stdlib modules under `h-mad/scripts/` carry the out-of-root tool-call scan (`h_mad_tool_calls.py`, D19) and the canary judge and the session-store quarantine (`h_mad_grok_containment.py`, D18, D20). Dispatch roots, prompts and probe scratch directories move out of system temp into the run directory (D5, D8, D16). The rest of the production edits are SKILL.md text, `grok-runtime.md` and the `exec grok` row of `references/agent-substrate.md`.

## Overview
Up to v1.5 this design took spec v1.7 and plan v1.5 (both at `28ec5bfc`) as given; v1.6 took spec v1.12 (`e3d84865`), below, and v1.7 and v1.8 take spec v1.13 (`37e48a23`) with the v1.14 exit contract the orchestrator ruled at the same sha. It settles every item the plan leaves to the design (listed in "Plan obligations answered"). It was first written against spec v1.6 (`94a4fd2c`) and plan v1.3 (`ab3c9f32`); the later revisions changed only operator decision D4, which v1.2 of this design took. The plan and the delta review cite shas from before a rebase; this design cites only the post-rebase ids, which `docs/03-analysis/grok-audit-surface.sha-remap.md` maps (`946ffc5a→a0b41697`, `5b2df07b→bfb6960a`, `611c299d→2f7bf7ae`, `b085ad7a→ab3c9f32`). There are three key decisions. The probe never re-derives a verdict the wrapper or the gate computes: it reads the token, or imports the function. No S2 root is used for more than one pass; the one S1 root serves its three cycles, because AC-1.6 requires the same root, and it is reset to its build and re-scanned before each of its second and third dispatches (D5). Calibration data reaches the branch only through git plumbing, so it is never checked out in any work tree.

**v1.6 (corrective revision against spec v1.12 at `e3d84865`).** The 2026-10-20 S2 run let a grok pass write to the live checkout and read the unseeded originals there (`docs/03-analysis/grok-audit-surface.incident-2026-10-20-grok-root-escape.md`). Spec v1.9–v1.12 answer it with FR-11 (containment), AC-1.9 (a full S1 re-smoke under containment), AC-3.8 (one root per pass), AC-6.6 (an out-of-root tool-call scan) and AC-11.7 (a grok session-store quarantine), and route (a): a fresh S2 of all nine documents in a new run directory, with the 2026-10-20 run kept as incident evidence only. This revision designs those: D16 (the wrapper's grok profile, prompt staging and `TMPDIR`), D17 (per-pass roots), D18 (the canary), D19 (the scan), D20 (the quarantine), and the changes they force in D1–D3, D5, D8, D9 and D11–D15. The void-cycle amendment of spec v1.9 was withdrawn in v1.10, so nothing here declares a void cycle and `stands()` is unchanged.

## Architecture Overview

```
 main (CI-tested, S0)                         calibration/grok-audit-surface (operator, never merged)
 ───────────────────────                      ──────────────────────────────────────────────────────
 grok_audit_probe.py ── reads ──> HEAD:exclusions.txt         calibration sha: ledger.jsonl + seeded/*.md
   │ imports h_mad_audit_gate (classify, section walk)        smoke commit f7520e72: + s1/<surface>/... (superseded)
   │ imports h_mad_audit_cycle (_gate_token)                  re-smoke commit:  + runs/<run-id>/resmoke/<surface>/..., canary/
   │ imports h_mad_audit_origins (ORIGINS)                    score sha:        + runs/<run-id>/s2/d<k>/v<N>/... (p<i>.root.txt each),
   │ imports h_mad_review_evidence (_GROK_TYPES)                                  s2/run.txt, findings, key, labels, extract.txt
   │ imports h_mad_tool_calls (scan_log; D19)
   │ reads hmad-dispatch.sh text (_GROK_TYPES_RE)
   │ runs h_mad_audit_gate.py CLI (GATE: token)
   │
   ├─ build-root ── git archive <calibration sha> ──> $RUN/roots/gas-root-d<k>-<purpose>-XXXX/  (non-git, one per pass)
   │                 remove exclusions, place target + paired docs, scan, reach check; scratch under $RUN/work/
   │
   │   operator: h_mad_grok_containment.py quarantine; hmad-dispatch grok-canary --run-dir $RUN   (D18, D20)
   │   operator: env -u GIT_* HMAD_AUDIT_STEM_DIR=$RUN/stem/<cycle>  hmad-dispatch audit-cycle --pass-root ... | tee
   │   operator: h_mad_tool_calls.py scan on every grok pass at cycle end; any non-CLEAN token halts the run (D19)
   │
   ├─ record-cycle ── copies stem + root by-products + root records ──> $READING/{resmoke,s2}/...
   ├─ commit-data ─── hash-object / read-tree / commit-tree / update-ref (temp index, no checkout) ──> branch
   ├─ smoke ───────── SMOKE: PASS|FAIL|UNREADABLE   (exit 0, 0, 2)
   ├─ extract ─────── findings.jsonl + key.jsonl (opaque ids, shuffled) + advisory hints on stdout
   ├─ score ───────── SEEDSCORE: ... from one exported score-sha tree
   ├─ main-leak ───── ref/sha checks → drift → main leak over HEAD against the smoke commit or the score sha
   └─ rescore ─────── ls-remote/fetch ref → sha checks → drift → git archive score sha → main leak
                      over HEAD → list check → rebuild roots + scan + reach → score → remove work dirs
```

`$KEEP` is `$HOME/.local/state/h-mad/grok-audit-surface`, and `$RUN` is the run directory, `$KEEP/run-<cal12>-<yyyymmddThhmmssZ>` (D8). The 2026-10-20 run's directory `$KEEP/run-ab2c85dc2e25/` is incident evidence; no step of this design writes to it, no probe mode reads it, and the only step that reads it is the AC-6.6 positive control, which reads one of its logs (D19).

The scorer is a pure function of two trees, as the plan's Architecture section requires: the `main` commit (probe and exclusion list) and the exported score-sha tree, which holds the ledger, the seeded copies, the recorded cycles, the findings, the key and the labels, plus the archive sources that came from `main` when the branch was made.

## Detailed Design

### D1. Probe file, imports and invocation
- **Path**: `docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py`, run as `python3 docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py <mode> …` from the repository root. It is not named `test_*.py`.
- **Imports**: the stdlib only, plus five `h-mad/scripts/` modules reached as `Path(__file__).resolve().parents[4] / "h-mad" / "scripts"` put first on `sys.path`. (`parents[0]` is the probe directory, `[1]` `probes`, `[2]` `03-analysis`, `[3]` `docs`, `[4]` the repository root.) The five modules are `h_mad_audit_gate` (`classify`, `BLOCKING_SECTIONS`, `_bullet_groups`, `_collapses`, `_flat_findings`, `_bullet_remainder`, `_payload`, `_is_none_sentinel`; D12), `h_mad_audit_cycle` (`_gate_token`, which parses the gate's first-line token with `GATE_RE`), `h_mad_audit_origins` (`ORIGINS`), `h_mad_review_evidence` (`_GROK_TYPES`) and, new in v1.6, `h_mad_tool_calls` (`scan_log`, D19), so the cycle-end scan and the score's re-derivation are one function. The gate is imported as a module object, `import h_mad_audit_gate as _gate`, and every call is `_gate.classify(...)`, so the classify connection is one attribute that a test can replace (D12). `_GROK_TYPES_RE` is read from the text of `h-mad/scripts/hmad-dispatch.sh` (or the `--vocab-sh` path, D11) with the regex `^_GROK_TYPES_RE=['"]([^'"\n]*)['"]$` (multiline; either quote character, as implemented in `vocab_sets`), split on `|`, and never copied. The private names are imported the same way `h_mad_audit_cycle._must_findings_from_gate_parser` already imports `_BULLET_MARKERS` and `_payload` from the gate.
- **Subprocesses**: only `git` and `sys.executable h-mad/scripts/h_mad_audit_gate.py <report>`, the latter to obtain a real `GATE:` token. The gate is run without `--gated`, so it writes no stamp beside the report (the stamp branch runs only under `args.gated`). The probe never invokes `codex`, `agy`, `grok` or `hmad-dispatch` (base §"No new external dependency").
- **Source features** are the module constant `SOURCES`, in spec FR-2 order: `audit-report-docs-copy` (`docs/archive/2026-09/`), `tdd-gate-fail-opens` (`docs/archive/2026-09/`), `agy-coder-fallback` (`docs/archive/2026-10/`). Documents are numbered `d1`…`d9` in feature order, then plan, design, impl-plan (AC-2.2). `--sources <name>=<archive dir>,…` overrides the constant, and only the synthetic fixtures pass it. It is accepted by every mode that reads the ledger or the archive sources, which are `check-ledger`, `build-root`, `extract`, `score`, `rescore` and `main-leak` (D2), and each passes the one parsed mapping to every check it calls in process (`rescore` to `check_ledger`, `build-root` and `score`; `main-leak` to trigger (iii)'s archived-source read). Every function that maps a document id to its archive path therefore takes the mapping as a required argument and never reads `SOURCES` itself: `placements(doc, sources)` (D5, D12), `extract_all(tree, s2_dir, sources)` (D12), `hints(findings, tree, sources)` (D12) and `check_ledger(tree, sources)` (D4); `record-cycle`, `commit-data` and `smoke` read neither and do not accept it. **DECISION (design-author):** a CLI override and not a config file, because the plan restricts the probe directory on `main` to "the probe and the declared exclusion list, and nothing else".
- **Token discipline** (spec AC-5.1, verbatim: "Every invocation of the probe, in every mode and on every path out of it (an exception that escapes the mode's own checks included), ends on exactly one token line on stdout; there is no exit without one."). Each mode's grammar is the D2 table: one prefix per mode, used by its success token and by its refusal token, and by nothing else. Lines printed before the token (`VOCAB:`, `SURFACE:`, `LIST:`, `HINT:` and the rest) are published lines, never tokens, and no published line starts with another mode's token prefix. An `[H-MAD] grok-audit-surface <mode> <verdict>` marker goes to **stderr**, so the token stays the last stdout line (base §"Marker discipline"). The one invocation that names no mode (D2, "No mode named") prints the tenth prefix, `PROBE:`, which no mode owns.
- **The last resort.** `main()` wraps the parse and the mode in one `try` and maps every exception to the mode's refusal token through one function, `refusal_token(mode, exc, argv)`, then exits 2. Three channels, in this order:
  1. A `Refusal` (a mode's declared refusal) prints its own `exc.reason` (`# M:GAS-REFUSAL-REASON`); this is how every D2 reason other than `internal:<E>` reaches the token.
  2. Otherwise, for `smoke`, the reason is `input_unparseable:<path>` (AC-5.1: the smoke's "unexpected failures map to its own two UNREADABLE reasons"). `<path>` is the module global `_OPEN_INPUT` when it is set (`# M:GAS-OPEN-INPUT`), else the `--data` value as given in argv (`--data <v>` or `--data=<v>`), else the empty string. `main()` sets `_OPEN_INPUT = None` on entry; the smoke sets it to each input's path immediately before that input is read (`_smoke_read` for every text input, `vocab_sets` for `--vocab-py`, `delivered` for the collected report before the gate runs) and never clears it. Residual, stated exactly: an exception after every input has been read (in the published-line or reason assembly) names the last input opened, not the place it failed; and a smoke usage error with no `--data` prints `input_unparseable:` with an empty path.
  3. Otherwise the reason is `internal:<ExceptionName>` (the class name; `# M:GAS-LAST-RESORT`). For `score` and `rescore` that is exactly the spec's `SEEDSCORE: UNREADABLE reason=internal:<ExceptionName>`.

  **Traceback scope.** The traceback is printed on stderr only for an exception that is not a declared refusal (`# M:GAS-TRACEBACK-SCOPE`: `not isinstance(exc, ProbeRefusal)`). The declared classes all derive from `ProbeRefusal`: `Refusal`, `UsageError` (D2), the reset classes of D5 (`ResetArgsConflict`, `ResetPurposeNotS1`, `ResetTargetNotAbsolute`, `ResetTargetNotDirectory`, `ResetTargetInSystemTemp`, `ResetTargetOutsideRoots`, `ResetTargetPrefix`, `RootResetMismatch`; v1.6 renames `ResetTargetOutsideTempdir` to `ResetTargetInSystemTemp`, whose meaning is now the opposite, and adds `ResetTargetOutsideRoots`) and the parent-directory classes of D5 (`ParentNotDirectory`, `ParentInSystemTemp`, `WorkDirInGitTree`). Every declared class other than `Refusal` still prints `internal:<ClassName>` (or, under `smoke`, channel 2's form), but with no traceback, because they are expected outcomes and not defects. An expected I/O or parse failure inside a listed check is reported as that check's reason and never as `internal`.

### D2. Modes, command lines and the token grammar of each

This table is the one statement of each mode's grammar (spec AC-5.1: "Every other mode has one token grammar, which the design names, and no mode prints two grammars"). The tests assert the exact last stdout line per mode (Test Plan, "Token grammar").

| Mode | Command line | Success token (exit 0) | Refusal token (exit 2) | Refusal reasons | Stage |
|---|---|---|---|---|---|
| `check-ledger` | `check-ledger (--tree <dir> \| --repo . --calibration-sha <sha40> --work-dir <dir>) [--sources …]` | `LEDGER: OK seeds=<n> docs=<n> C1=<n> C2=<n> C3=<n> C4=<n>` | `LEDGER: UNREADABLE reason=<r>` | `ledger_counts`, `ledger_origin`, `seed_rebuild`, `calibration_ref:sha_unknown:<sha>`, `internal:<E>` | S0b, tests |
| `build-root` | `build-root --repo . --calibration-sha <sha40> --doc d<k> --purpose <s1\|s2v1\|s2v2\|rescore> [--list-commit <sha>] --work-dir <dir> (--dest-parent <dir> \| --reset <abs root>) [--sources …]` | `ROOT: READY doc=d<k> purpose=<p> path=<abs> calibration=<sha40> list_commit=<sha40> list_blob=<oid> absent=<n>` | `ROOT: UNREADABLE reason=<r>` | the `check-ledger` reasons, `leak:<path>`, `root_git:<path>`, `internal:<E>` | S0b, S1, S2 |
| `record-cycle` | `record-cycle --stem <dir> --root <dir> (--root-record <file> \| --pass-root-record <file> …) --stdout <file> --command <file> --dest <dir>` | `RECORD: OK dest=<abs> files=<n>` | `RECORD: REFUSED reason=<r>` | `input_missing:<path>`, `no_auditcycle_line:<file>`, `stem_prefix:<n>`, `command_unparseable:<file>`, `root_record:no_line`, `root_record:path_mismatch`, `internal:<E>` | S1, S2 |
| `commit-data` | `commit-data --repo . --parent <sha40> --src <dir> --message <text>` | `COMMIT: OK sha=<sha40> ref=refs/heads/calibration/grok-audit-surface` | `COMMIT: REFUSED reason=<r>` | `parent_unknown:<sha>`, `ref_moved:<oid>`, `outside_calibration_dir:<path>`, `would_replace:<path>` (v1.6, D9), `ref_unconfirmed`, `internal:<E>` | S0b, S1, S2 |
| `smoke` | `smoke --data <dir> [--vocab-py <path>] [--vocab-sh <path>]` | `SMOKE: PASS` and `SMOKE: FAIL reason=<r>[,<r>…]` (both exit 0) | `SMOKE: UNREADABLE reason=<r>` | `input_missing:<path>`, `input_unparseable:<path>` (AC-1.7) | S1 |
| `extract` | `extract (--tree <dir> \| --repo . --base-sha <sha40> --work-dir <dir>) --s2 <dir> --shuffle-seed <int> --out <dir> [--sources …]` | `FINDINGS: WRITTEN findings=<n> must=<n> should=<n> reports=<n>` | `FINDINGS: UNREADABLE reason=<r>` | the `check-ledger` reasons, `cycle_token:<cycle>`, `list_changed:unrecorded`, `out_of_root:<doc>.v<N>`, `must_count_mismatch:<report>`, `internal:<E>` | S2 |
| `score` | `score --tree <dir> [--run-id <run-id>] [--calibration-sha <sha40> --score-sha <sha40>] [--sources …]` | `SEEDSCORE: PASS\|MISS reason=bar_missed\|INCONCLUSIVE reason=<r> …` | `SEEDSCORE: UNREADABLE reason=<r>` | any AC-5.4 reason the score's checks name (D13) | tests, inside `rescore` |
| `rescore` | `rescore --repo . --calibration-sha <sha40> --smoke-sha <sha40> --score-sha <sha40> --run-id <run-id> --work-dir <dir> [--remote origin] [--sources …]` | the `score` token | `SEEDSCORE: UNREADABLE reason=<r>` | any of the sixteen AC-5.4 reason forms | S3 (AC-6.4) |
| `main-leak` | `main-leak --repo . --calibration-sha <sha40> --smoke-sha <sha40> [--score-sha <sha40>] --work-dir <dir> [--remote origin] [--sources …]` | `MAINLEAK: CLEAN scanned=<sha40> data=<sha40> blobs=<n>` | `MAINLEAK: UNREADABLE reason=<r>` | `calibration_ref:<kind>`, `calibration_drift:<path>`, `calibration_drift:not_descendant`, `main_leak:<path>`, `internal:<E>` | S3, every outcome (D9) |

`<E>` is the escaping exception's class name (D1). **DECISION (design-author):** one grammar per mode, with two refusal words. The modes that check calibration data (`check-ledger`, `build-root`, `extract`, `score`, `rescore`, `main-leak`) refuse with `UNREADABLE`, and every reason they print is one of AC-5.4's sixteen forms (fifteen until spec v1.10 added `out_of_root:<doc>.v<N>`), so a check that runs at S0b and again inside `rescore` carries the same reason in both places. The two recording modes (`record-cycle`, `commit-data`) refuse with `REFUSED` and their own closed reason sets: those refusals are operator preconditions on writing a record, not readings of calibration data, so they neither need nor widen AC-5.4's closed list. This replaces v1.0's "one refusal vocabulary" sentence, which was false: v1.0 had `COMMIT:` and `RECORD:` refusals beside it.

**No mode named (the tenth prefix, `PROBE:`).** When argv is empty or its first word is not one of the nine modes above, there is no mode whose grammar applies, so `main()` prints exactly one stdout line, `PROBE: UNREADABLE reason=unknown_mode` (`# M:GAS-UNKNOWN-MODE`), before any parsing, then the usage on stderr and `[H-MAD] grok-audit-surface unknown_mode UNREADABLE` on stderr, and exits 2. `PROBE:` is owned by no mode, has this one form and no counts, and no mode prints it. This is the plan's extension (impl-plan Task 2, operator ruling); it keeps AC-5.1's "no exit without one [token]" true for the argv the D2 table cannot name.

**Usage errors inside a mode.** The parser is built with `add_help=False` (`# M:GAS-NO-HELP`) and `allow_abbrev=False` (`# M:GAS-NO-ABBREV`), and its `error()` raises `UsageError` (`# M:GAS-USAGE`) instead of exiting, so every argparse exit path, `--help` and an abbreviated flag included, reaches D1's last resort and ends on the mode's token: `<PREFIX> <WORD> reason=internal:UsageError` with no traceback, or, under `smoke`, `SMOKE: UNREADABLE reason=input_unparseable:<--data value>` (D1 channel 2). The paired-flag rules that argparse cannot express (`check-ledger`'s `--repo` with `--calibration-sha`, `extract`'s `--repo` with `--base-sha`, `score`'s `--calibration-sha` with `--score-sha`) are checked in `main()` through the same `parser.error`. v1.6 adds two more of them, checked the same way: `--work-dir` is required by every invocation that creates a directory (`build-root`, `main-leak`, `rescore`, and the `--repo` forms of `check-ledger` and `extract`; D5 "Where the probe writes"), and `build-root` requires exactly one of `--dest-parent` and `--reset` (both given stays `ResetArgsConflict`, D5; neither given is a usage error, because a missing parent used to mean system temp).

`--tree <dir>` is always a directory holding an exported commit tree (or a synthetic fixture shaped like one), never a work tree. `--repo . --calibration-sha` and `--repo . --base-sha` export that commit with `git archive` into a fresh `mkdtemp` directory under `--work-dir` and then run the same function the `--tree` form runs, so each check has one implementation and two front doors.

**Verbs that are not probe modes (v1.6).** The cycle-end scan, the canary and the session-store quarantine are not probe modes, so the probe keeps exactly the nine modes above and spec AC-5.1's and AC-5.5's "nine modes" stays true. The scan is `python3 h-mad/scripts/h_mad_tool_calls.py scan …` (token `TOOLSCAN:`, D19), and the probe imports the same `scan_log` function for its re-derivation. The canary is the wrapper verb `hmad-dispatch grok-canary` (token `GROK-CANARY:`, D18), because it launches grok and D1 forbids the probe to. The quarantine is `python3 h-mad/scripts/h_mad_grok_containment.py quarantine` (token `QUARANTINE:`, D20), and every `GROK-CANARY:`, `QUARANTINE:` and `TOOLSCAN:` token the runbook gates on is read by `h_mad_grok_containment.py require` (token `REQUIRE:`, v1.8, D8). Its scope is those three prefixes only: the runbook's other tokens (`ROOT:`, `RECORD:`, `COMMIT:`, `SMOKE:` and the rest) are read as their own sections state. None of these four prefixes is printed by a probe mode, and no probe published line starts with one.

### D3. Calibration directory layout (branch only)
Every path is under `docs/03-analysis/probes/grok-audit-surface/calibration/` in the branch's tree:

```
ledger.jsonl                         one JSON object per seed (AC-2.4)
seeded/<feature>.<phase>.md          the 9 seeded copies (AC-2.5)
s1/versions.txt                      grok_binary=<path> <grok --version line>, then agy and codex --version output (AC-3.6, D8)
s1/<surface>/                        surface ∈ {grok, agy, codex}; codex absent when not run (smoke commit f7520e72; superseded, byte-identical forever)
runs/<run-id>/                       one reading per run (v1.8, D8); every path below this line is under it
resmoke/versions.txt                 the AC-1.9 re-smoke's version record, same three lines (v1.6)
resmoke/run.txt                      the run record, one RUN: line (D8)
resmoke/<surface>/                   the re-smoke's cycles, same files as s1/<surface>/ plus p1.profile.txt for grok (v1.6)
resmoke/canary/                      the run's canary record (D18)
s2/run.txt                           the run record, the same RUN: line (D8)
s2/d<k>/v<N>/                        k ∈ 1..9; N ∈ {1, 2}; the fresh S2 of the re-smoke's run only
findings.jsonl                       {"id","doc","cycle","section","text","quotes":[...]}; shuffled; no surface field
key.jsonl                            {"id","doc","cycle","pass","surface","report"}, one record per finding and nothing else
labels.jsonl                         {"id","label","why"}; "why" required for UNDECIDABLE
extract.txt                          the extract command line verbatim, shuffle seed included
```

**Paths relative to the reading root (v1.8).** From here on, a path that begins `resmoke/` or `s2/`, or names `findings.jsonl`, `key.jsonl`, `labels.jsonl` or `extract.txt`, is relative to the reading root `runs/<run-id>/` (D8). In the synthetic fixtures, with no `--run-id`, it is relative to the calibration directory itself. `ledger.jsonl`, `seeded/` and `s1/` are always relative to the calibration directory.

A cycle directory (`s1/<surface>/`, `resmoke/<surface>/` or `s2/d<k>/v<N>/`) holds the following.

| File | From | Read by |
|---|---|---|
| `auditcycle.txt` | the wrapper's full stdout, captured with `tee` | smoke, extract, score (the `AUDITCYCLE:` line and the `Effort:` block) |
| `command.txt` | the exact dispatch command, verbatim | record-cycle, score (`--feature`, `--phase`, `--cycle`, `--surfaces`), measurement doc |
| `root.txt` (S1 and re-smoke cycles) | the `ROOT: READY` line of the one root the cycle ran in (`--root-record`) | rescore (`list_changed`), the scan (D19), measurement doc |
| `p<i>.root.txt` (S2 cycles, one per pass; v1.6, AC-3.8) | the `ROOT: READY` line of pass `i`'s own root (`--pass-root-record`, in pass order); an S2 cycle has no `root.txt` | rescore (`list_changed`), extract and score (AC-3.8 trigger (8), quote paths, the scan), measurement doc |
| `p<i>.scan.txt` (grok passes; v1.8) | the cycle-end `TOOLSCAN:` token, written by the runbook into the dest (D8) | `require` (D8); the measurement doc. The score re-derives the scan and never reads this file |
| `p<i>.profile.txt` (grok passes; v1.6) | the `GROK-PROFILE:` line `exec` wrote beside the pass log (D16), from the stem's `<stem>_p<i>.log.profile` | score (`CONTAINMENT:` lines, D13), measurement doc (AC-6.5) |

**What counts as calibration data** (spec AC-2.7). The set is every file under the calibration directory at the commit in question, except a file that has one of the names listed below (the metadata names) **and** carries none of the spec's three kinds of text (spec AC-2.7, verbatim: "A file is outside the set only when it carries none of these"). The test is per file and per commit, never by name alone. A file with one of the metadata names is in the set when its normalised content (the D6 normaliser) contains any of: (a) any seed's normalised `seeded` span; (b) any seed's normalised `expected` sentence; (c) the words of any finding filed on a seeded document. For every must and should finding that `report_findings` (D12) gives over every collected report in the same tree (`s1/*/collected/*.md`, and `runs/*/resmoke/*/collected/*.md` and `runs/*/s2/d*/v*/collected/*.md` across every reading; the two `runs/*` globs are new in v1.8, and the top-level `resmoke/` and `s2/` forms of v1.6 are kept for the synthetic fixtures), the needles are per line and never the joined group: the normalised `_gate._payload` of the finding's bullet line (its first line, for a finding that starts at a bullet, which is a flat finding or a collapsed group's parent), and, for a prose-only finding (D12 step 3, which starts at no bullet), the normalised `_gate._payload` of each of its lines. A finding's continuation lines (`class:`, `quote:`, `instance of:`) and a collapsed group's nested evidence bullets are not needles. Every collected report under the calibration directory is a report on a seeded document (S1 and the re-smoke audit `d1`'s seeded copy, S2 each `d<k>`'s), so (c) reads them all. Each metadata name is a candidate for exclusion for one stated reason:
- `command.txt`: the dispatch argv (feature name, phase, cycle, root paths, surfaces, timeout).
- `root.txt` and `p<i>.root.txt`: one `ROOT: READY` line (shas, a path and a count).
- `wall_seconds.txt`: one integer.
- `resolved_model.txt`: one `RESOLVED-MODEL` line or its refusal.
- `s1/versions.txt` and each reading's `resmoke/versions.txt`: three version strings, the first prefixed with the grok binary's path (D8).
- `extract.txt`: the extract argv.
- `p<i>.profile.txt` (v1.6): one `GROK-PROFILE:` line (D16).
- `p<i>.scan.txt` (v1.8): one `TOOLSCAN:` line (D19).
- each reading's `resmoke/run.txt` and `s2/run.txt` (v1.6): one `RUN:` line, two paths (D8).
- every file under a reading's `resmoke/canary/` (v1.6): the canary's prompt, log, token line, binary line, profile line and sentinel. Its working directory is an empty directory and its prompt names only run-directory paths (D18), so it is built to carry none of the three kinds; a canary file that does carry one is in the set like any other.

They are candidates because they are short metadata files that an unrelated `main` blob can equal byte for byte (a one-integer file is the extreme case), which would make trigger (i) refuse a clean `main`. Such a file that does carry (a), (b) or (c) is in the set whatever its name, so trigger (i) compares it with every `main` blob like any other calibration file; v1.2 excluded its six metadata names by name alone, which left a metadata file holding a finding's text (but no seed span) outside the whole-file check. Everything else is in the set, `auditcycle.txt` included: on a `PASS` or `FAIL` cycle the wrapper's stdout carries a `Premise checklist:` with one line per finding (`render` in `h_mad_audit_cycle.py`), and those findings quote seeded spans. v1.0 excluded `auditcycle.txt` on the premise that it carries no seed text; that premise was false. Triggers (ii) and (iii) scan every `main` blob for every seed's `expected` and `seeded` text whatever the file, independently of the set. One function, `calibration_data_files(tree)`, computes the set, and trigger (i) and its tests all call it (D9). Residual, stated exactly: (c) matches each needle as one substring of the normalised file, so a metadata file stays outside the set when it carries only a paraphrase or a fragment of a payload, or only a finding's continuation lines or a collapsed group's nested evidence bullets; this is AC-2.6's paraphrase residual, applied to finding text. The other direction is fail-closed: a short payload (a `- Build defects:` label parent is itself a finding, D12, so `Build defects:` is a needle) can bring a metadata file into the set, where trigger (i) compares it with every `main` blob; that over-includes and never leaks.

### D4. Ledger checks (`check-ledger`; AC-2.2–2.5)
- Records are read from `ledger.jsonl`. `ledger_counts` fires on each of these, each its own guard: a line that does not parse as one JSON object; a record lacking one of the nine AC-2.4 fields (`id source phase class origin section original seeded expected`); a `source` that is not one of the nine FR-2 documents; an empty `original`; an empty `expected` (an empty needle would match every file).
- **Per-document class rule** (spec AC-2.2, verbatim: "for every k, document k's multiset of seed classes must equal exactly the three classes other than `((k−1) mod 4) + 1`, one each"). The probe compares, for each `d<k>`, `sorted(classes of d<k>)` with `sorted({C1,C2,C3,C4} − {C((k−1) mod 4)+1})`. A mismatch refuses `ledger_counts`. The totals (C1=6, C2=7, C3=7, C4=7, sum 27) are then derived from the rule and compared with the ledger's; the numbers are not literals in the code. The per-document check is what catches the spec's balanced counterexample (d1 as C2, C2, C4 and d4 as C1, C3, C3), which keeps every document size and every total. The totals comparison is implied by the per-document rule (every document's multiset equal to its permitted one makes the summed multisets equal), so no ledger that passes the per-document guard can fail it: it is kept unmarked, with no fixture and no mutation row, and its residual is exactly that it is unreachable while the per-document guard stands.
- `ledger_origin`: `origin ∉ ORIGINS` (the imported 8-tuple).
- `seed_rebuild`: for each document, start from the archive source bytes in the exported calibration tree. For each seed, the exact (unnormalised) `original` must occur **exactly once** in the source, and it is replaced by `seeded`. The result must equal `seeded/<feature>.<phase>.md` byte for byte. The four AC-2.3 placement violations refuse `seed_rebuild` too, each its own guard (spec AC-5.4: "two seeds of one document in the same `##`/`###` section, a seed under `## Version History`, a record whose `section` does not name the heading its span sits under, or a `seeded` span that does not occur exactly once in its seeded document").

### D6. Content scan (AC-2.6 class closer)
- **Normaliser**, one function used for needle and haystack alike: `re.sub(r"\s+", " ", data.decode("utf-8", errors="replace"))`. There is no strip and no case folding.
- **Needles**: for all 27 seeds (every ledger record, not only the target's), the normalised `original` and the normalised `expected`. An empty needle has already refused `ledger_counts` (D4).
- **Walk**: `os.walk(root, followlinks=False)`. Every symlink, whether to a file or a directory, refuses `leak:<root-relative path>` whatever its target. Every regular file is read and scanned. The first hit in sorted path order refuses `leak:<root-relative path>`.
- **The one exemption**: a hit on seed `s`'s `original` in file `f` is exempt iff `f` sits at the live path where `s`'s own source document is placed as a paired copy, AND `sha256(f) == sha256(archive source of s)`. `expected` is never exempt. The seeded target sits at its source's live path, but its sha differs, so a hit there is a `leak` (spec: widen the span).
- **Residuals**, as the spec states them: paraphrase or partial copy; non-UTF-8 stored forms; reads outside the root by absolute path; name mentions; submodule paths, which `git archive` exports empty (a C2 seed must not name a path under `beautiful_prose`, `drawio-skills` or `humanizer`). ### D7. Git reach check
The check walks the root for any entry named `.git` (file or directory) at any depth; the first one in sorted order refuses `root_git:<root-relative path>`. It then runs `git -C <root> rev-parse --absolute-git-dir` in an environment with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` removed, which is the same environment the dispatch runs in. Exit 0 refuses `root_git:<the printed git dir>`.

  **The halt (spec AC-6.6; connected by two components in v1.8, design audit v3 p1).** A grok pass whose scan token is anything but `TOOLSCAN: CLEAN surface=grok …` is a containment failure. That includes an `OUT_OF_ROOT` or `UNREADABLE` token, any other last line, and no token line at all. The test sits at the launch and not at the cycle block's start, so a lane that built its roots before the halt still launches nothing after it. ### D9. Calibration data, the shas and the ref (`commit-data`, `main-leak`, `rescore`; AC-2.7)
- **No checkout anywhere.** `commit-data` builds each branch commit with plumbing in the operator's `main` clone. It uses a temporary index (`GIT_INDEX_FILE=<mkdtemp>/index`): `git read-tree <parent>`; `git hash-object -w` for each file under `--src`; `git update-index --add --cacheinfo 100644,<blob>,<calibration dir>/<rel>`; `git write-tree`; `git commit-tree <tree> -p <parent> -m <message>`; `git update-ref refs/heads/calibration/grok-audit-surface <new> <expected old>`. The expected old value is the parent when the ref exists, and the zero-oid form (`git update-ref <ref> <new> ""`) for the first commit. It refuses, and writes no ref, with `parent_unknown:<sha>` when `--parent` is not a commit, `ref_moved:<oid>` when the ref's current value is neither absent nor `--parent` (`<oid>` is that current value), and `outside_calibration_dir:<path>` when a `--src` path would land outside the calibration directory. **v1.6: commits are add-only outside the authoring set** (scope corrected in v1.8, design audit v3 p1, AC-2.7). It also refuses `would_replace:<path>` (`# M:GAS-COMMIT-REPLACE`) when the parent's tree already holds a blob at that calibration path whose id differs from the file's `git hash-object` id. The check runs for every `--src` file in sorted order, before any `update-index`. Re-adding an identical blob is a no-op and is not refused. The authoring set, `ledger.jsonl` and `seeded/`, is exempt (`# M:GAS-COMMIT-AUTHORING`), because S0b re-chose spans by later commits on those files before the calibration sha was fixed (never an amend). From the calibration sha on, that set's freeze is the drift check's step 3 below, which refuses any changed or absent file present at the calibration sha. That is spec AC-2.7's rule as written, which freezes "every file present at the calibration sha", and nothing earlier. This is the enforcement of spec AC-2.7's "later commits only add" and of AC-1.9's "the S1 records already at `f7520e72` stay byte-identical": the re-smoke's records go under `resmoke/`, and no commit can rewrite a file under `s1/`, or any other file a parent holds. The drift check below is the second, read-time half. It re-reads `git rev-parse refs/heads/calibration/grok-audit-surface` and prints `COMMIT: OK` only when that equals `<new>`, and `COMMIT: REFUSED reason=ref_unconfirmed` otherwise. The work tree and the real index are never touched. `$KEEP/authoring/` (the ledger and seeded copies as plain files) is deleted after the calibration sha is pushed and confirmed, so during S1 and S2 the ledger exists only as git objects (the AC-2.6 residual (3) and AC-2.7 residual (5) routes, which stay open).
- **The commits on the branch.** The first commit's parent is the `main` sha that holds S0. One or more commits follow while S0b answers refusals by re-choosing spans (never an amend). The **calibration sha** is the first one on which `check-ledger` reads `LEDGER: OK` and every `build-root` reads `ROOT: READY`. Next came the first **smoke commit**, `f7520e72`, holding `s1/` (each S1 cycle with its `root.txt`, and `s1/versions.txt`); spec AC-1.9 supersedes its reading, and its files stay byte-identical. **v1.6:** next comes the **re-smoke commit**, holding `runs/<run-id>/resmoke/` (each re-smoke cycle with its `root.txt`, `versions.txt`, `run.txt` and `canary/`), made with `commit-data --parent "$TIP" --src "$RUN/data"`, where `TIP` is the calibration branch tip at that moment: the runbook runs `git fetch --no-tags origin +refs/heads/calibration/grok-audit-surface:refs/heads/calibration/grok-audit-surface`, sets `TIP=$(git rev-parse refs/heads/calibration/grok-audit-surface)`, and confirms `git ls-remote origin refs/heads/calibration/grok-audit-surface` prints the same sha. For the first run that tip is `f7520e72`. For a later run it is the earlier run's last commit, so a later run **appends**: its namespace is new, and its parent is whatever tip it found. `commit-data`'s `ref_moved:<oid>` guard checks the expected old value, so a tip that moves between the fetch and the commit refuses (v1.10, design audit v4 p1; until v1.9 the parent was hard-wired to `f7520e72`). This is pinned by `test_commit_data_appends_a_second_reading_after_an_earlier_resmoke`: a temporary repository whose branch already holds `runs/<run-a>/resmoke/` takes a second commit adding `runs/<run-b>/resmoke/` with `--parent` its tip; `runs/<run-a>/` is byte-identical afterwards, and a stale `--parent` refuses `ref_moved:<tip>`. The commit is made while `$READING` holds only `resmoke/` and `s2/run.txt`, on every re-smoke outcome that derives to `PASS` or `FAIL`. It is the smoke commit every later reading cites (`--smoke-sha`). Last, on `SMOKE: PASS` of the re-smoke and a clean scan, comes the **score sha** holding `runs/<run-id>/s2/` (each cycle with its `p<i>.root.txt` files, and `s2/run.txt`), and `findings.jsonl`, `key.jsonl`, `labels.jsonl` and `extract.txt` beside them, made from the same `$RUN/data`, whose `resmoke/` files are then identical re-adds. A later run writes its own `runs/<run-id>/` (D8). Every commit after the calibration sha only adds files under the calibration directory. Each push is `git push origin refs/heads/calibration/grok-audit-surface:refs/heads/calibration/grok-audit-surface` (no force), confirmed by `git ls-remote origin refs/heads/calibration/grok-audit-surface` printing the expected sha. On a re-smoke failure the re-smoke commit is the branch tip and the measurement doc cites it (spec AC-1.8), with `f7520e72` cited as superseded (spec AC-6.5).
- **Ref and sha checks** (shared by `main-leak` and `rescore`), in this order. The first failure refuses.
  1. `git ls-remote --exit-code <remote> refs/heads/calibration/grok-audit-surface`: exit 2 refuses `calibration_ref:ref_absent`; any other non-zero exit (128 for a missing remote or an unreachable URL; Readings) refuses `calibration_ref:fetch_failed`. Then `git fetch --no-tags <remote> +refs/heads/calibration/grok-audit-surface:refs/h-mad-probe/grok-audit-surface/calibration`; a non-zero exit refuses `calibration_ref:fetch_failed`, and so does a missing local ref afterwards. The fetched tip is that ref. It is a private namespace, never a branch, so nothing is ever checked out from it.
  2. For each cited sha (calibration, smoke, then score when given): `git cat-file -e <sha>^{commit}` fails, which refuses `calibration_ref:sha_unknown:<sha>`; or `git merge-base --is-ancestor <sha> <tip>` exits 1, which refuses `calibration_ref:not_on_ref:<sha>`.
- **Drift check** (spec AC-2.7, "Two shas, and the smoke commit"), run for the smoke commit and, when given, the score sha, each against the calibration sha. **DECISION (design-author):** the score sha is also required to descend from the smoke commit, because the spec defines it as "the later branch commit, descending from the smoke commit"; that failure refuses `calibration_drift:not_descendant` too. For a later commit `L`:
  1. `git merge-base --is-ancestor <calibration> <L>` exits 1: `calibration_drift:not_descendant`.
  2. `git diff --name-only -z <calibration> <L>`, sorted: the first path not under the calibration directory refuses `calibration_drift:<path>`.
  3. For every blob under the calibration directory in `git ls-tree -r -z <calibration>`, sorted: absent at `L`, or present with a different blob id, refuses `calibration_drift:<path>`. This is the byte-identity rule ("every file present at the calibration sha … is byte-identical at the smoke commit and at the score sha"), so the ledger and seeded copies the roots were built from are the ones scored.
- **Main leak check** (`main-leak`, and step 4 of `rescore`). The data commit `D` is the score sha when one is given, and otherwise the smoke commit (spec AC-2.7: "or, when there is no score sha (a smoke failure), at the smoke commit"). `D`'s tree is exported into a fresh `mkdtemp` directory under `--work-dir` and the D7 reach check is run on it. Then every blob of `git ls-tree -r -z HEAD` is read through `git cat-file --batch`, and the first path in sorted order refuses `main_leak:<path>` on: (i) `sha256(blob)` equal to the sha256 of any file in `calibration_data_files(export of D)` (D3); (ii) the normalised blob containing any normalised `expected`; (iii) the normalised blob containing any normalised `seeded` span that does **not** occur in the normalised archived source of the same seed. `main-leak` prints `MAINLEAK: CLEAN scanned=<HEAD sha40> data=<D sha40> blobs=<n>`; `rescore` prints the same facts as the published line `SCANNED: main=<HEAD sha40> data=<D sha40> blobs=<n>`. **When it runs:** `main-leak` runs on every outcome before the measurement doc is committed to `main` (without `--score-sha` on a smoke failure, with it otherwise), and `rescore` runs the same function again. A refusal blocks that commit; the leak is removed from `main` and the check is run again.
- **`rescore` steps**, in AC-6.4's order:
  1. The ref and sha checks for the calibration, smoke and score shas.
  2. The drift check for the smoke commit and the score sha.
  3. Export the score sha into a fresh `mkdtemp` directory under `--work-dir` (outside system temp and, by D5's `WorkDirInGitTree` guard, outside every git work tree; spec AC-6.4 as amended in v1.9) and run the D7 reach check on it.
  4. The main leak check, with `D` = the score sha.
  5. **List check.** The recorded root lines are every root record under the export, in record order: `root.txt` of `s1/grok`, `s1/agy`, `s1/codex`, then, under the `--run-id` reading root, of `resmoke/grok`, `resmoke/agy`, `resmoke/codex`, then, for `s2/d1/v1`, `s2/d1/v2`, … `s2/d9/v2` (numeric in `k`), `p1.root.txt` … `p<P>.root.txt`, where `P` is the number of entries of that cycle's `command.txt` `--surfaces` list (v1.6, spec AC-3.8 and AC-5.4 `list_changed` trigger (a)). An S2 cycle whose `command.txt` gives no parseable `--surfaces` list has root records that cannot be enumerated, and refuses `list_changed:unrecorded` too; an S2 cycle's `root.txt`, if one is present, is not read. It prints `LIST: recorded=<oid>[,<oid>…] current=<oid>`, where `current` is `git rev-parse HEAD:docs/03-analysis/probes/grok-audit-surface/exclusions.txt`. The first recorded cycle whose `root.txt` is absent (`# M:GAS-LIST-UNRECORDED`), or holds no line starting `ROOT: READY ` or more than one, or whose one such line `parse_root_line` rejects (`# M:GAS-LIST-MALFORMED`; the D5 malformed-line rule, which includes a line with no `list_blob=` field; a plan extension, implemented) refuses `list_changed:unrecorded`; otherwise the first recorded blob that differs from `current` refuses `list_changed:<oid>` (spec AC-5.4).
  6. `check_ledger` on the export; `build-root --purpose rescore` for `d1`…`d9` from the calibration sha, with the list at `HEAD`, in process, under `--work-dir`, printing no `LEDGER:` or `ROOT:` token.
  7. `score` on the export, in process, which re-derives the AC-6.6 scan from every recorded S2 pass log (D13, D19).
  8. In a `finally`: remove every directory it created under `--work-dir`, re-list to confirm removal, and print the `[H-MAD]` marker on stderr. A removal failure is printed on stderr and never replaces the token.

### D11. Smoke mode (AC-1.7)
- **Inputs** (`--data <dir>`): `grok/` and `agy/`, which are required, and `codex/`, which is optional (its absence means "not run"). Each holds D3's cycle files. A cycle **reached dispatch** when its `AUDITCYCLE:` line carries a `delivered=` field: on a halt (`assemble_halt:pN`, `prompt_divergence`) the wrapper renders the line from no pass results, so it has no `delivered=` field and no `Effort:` block (Readings).
- **UNREADABLE first**, so that exactly one reason is printed. The inputs are checked in this fixed order, and the first problem wins:
  1. `grok/auditcycle.txt`: absent → `input_missing`; not exactly one line that `parse_auditcycle` accepts (`^AUDITCYCLE: (PASS|FAIL|UNVERIFIED)( \S+)*$`) → `input_unparseable`; a malformed `Effort:` block (below), whether or not the cycle reached dispatch → `input_unparseable:<grok/auditcycle.txt>` (`# M:GAS-SMOKE-EFFORT-MALFORMED`).

     **The `Effort:` block grammar**, the one reading `parse_effort_items` makes (smoke and score both call it; implemented as the plan's Task 4 states): the block opens at a line equal to `Effort:`; its items are the lines after it that begin `- `, up to the first line that does not; each item is that line without the `- `. A text with no `Effort:` line has no block and gives `[]` (a halted cycle, which `render` writes without one). It gives `None` (malformed) when there are two or more `Effort:` lines (`# M:GAS-PARSE-EFFORT-TWICE`), when an item does not begin `p<digits> ` (`# M:GAS-PARSE-EFFORT-ITEM`), or when the block has no item (`# M:GAS-PARSE-EFFORT-EMPTY`). This is the shape `h_mad_audit_cycle.render` writes: `Effort:`, then one `- <item>` per `_effort_items` entry, then the next block's heading or the `[H-MAD]` marker.
  2. `grok/p1.log`, when the grok cycle reached dispatch: absent → `input_missing`; no line that parses as a JSON object with a string `type` → `input_unparseable`. This type reading (`grok_log_types`) runs `json.loads` per line and skips a line that raises `ValueError` or `RecursionError`, exactly as `scan_grok` does; unlike `scan_grok`, it applies no `GROK_MAX_DEPTH` bound.
  3. The grok `Effort:` item for `p1`, when the grok cycle reached dispatch: absent (no item beginning `p1 `) → `input_unparseable:<grok/auditcycle.txt>` (the wrapper renders one for every pass that carried a log). Present, step 3 refuses only a **wrong-file rendering**, the item `_effort_items` gives when the measured file was not a readable grok transcript at all: `p1 unreadable (log named but not readable)` (shapes `missing` and `empty`) and the item beginning `p1 not measured (codex-text log` (shape `codex-text`); each refuses `input_unparseable:<grok/auditcycle.txt>`. Three renderings fall through to the reasons, each recognised positively: the **positive grok item**, which matches `^p1 tools=\d+ ok=\d+ unresolved=\d+ thinking=\d+ format=grok( |$)` (what `_effort_items` renders for shape `grok`, with its optional ` paths=… code=… other=… unmeasured=…` suffix from `format_targets` and its optional ` low-evidence (…)` suffix after the space); the **truncated item**, which begins `p1 not measured (grok log truncated` (shape `grok-truncated`); and the **non-grok counts item**, which matches `^p1 tools=\d+ ok=\d+ failed=\d+ thinking=\d+( |$)` (shapes `parsed` and `unparseable`, which `_effort_items` renders identically). A readable log that is not grok's shape is the AC-1.2 drift the smoke exists to report, so it must reach `FAIL` and not `UNREADABLE`, which the spec reserves for inputs that "could not be read". An item in none of these five forms (none today: the renderer pin below maps each of `measure_effort`'s seven shapes to exactly one form) also refuses `input_unparseable:<grok/auditcycle.txt>`, so a shape `_effort_items` adds later refuses until this design names it. AC-1.1 ("reports `format=grok` (shape `grok`), not `grok-truncated`") is therefore met only by the positive grok item, and a non-grok item that is not a wrong file **fails** the smoke rather than refusing it, with one exception: the truncated item fails through the `truncated` reason, and a non-grok counts item fails through `vocab_missing`, unless its log carries all three of those types, which step 3 refuses (below, v1.8). **v1.8 closes the two residuals v1.4–v1.7 stated here** (design audit v3 p1, AC-1.1: they let a non-grok item reach `SMOKE: PASS`, while AC-1.1 requires `format=grok`). The axis is "a non-grok counts item that no reason can fail". It is exactly the non-grok counts item (shapes `parsed` and `unparseable`) on a log whose step-2 type set holds all three of `end`, `tool_call` and `tool_call_update`, because then no `vocab_missing` fires and `truncated` cannot. Step 3 therefore refuses that combination with `input_unparseable:<grok/auditcycle.txt>` (`# M:GAS-SMOKE-EFFORT-NONGROK-CONTRADICTED`): the wrapper's own item says the log is not grok's shape, while the log carries grok's types, so the smoke cannot measure the pass. This is spec AC-1.7's "a form the smoke cannot measure", and it falls under the first member of its "What the restore remedy cannot clear" (a refused item the wrapper itself printed). The closed reason list is not widened, and no second log classifier is added: the rule reads the wrapper's `Effort:` item and the existing step-2 type set only. A non-grok counts item on a log missing any of the three types still **fails** with `vocab_missing`, so a drifted grok log still reaches `FAIL`. It follows that `SMOKE: PASS` is reachable only with the positive grok item, which is AC-1.1 as written.
  4. The grok collected report, when its `delivered=` value is `report-file` or `out`: absent → `input_missing` (spec AC-1.7: "a delivered pass's collected report, that the derivation needs, is absent"); `_gate_token` finds no `GATE:` line in the gate's stdout → `input_unparseable`.
  5. `agy/auditcycle.txt`, as in 1.
  6. The agy collected report, as in 4.
  7. `codex/auditcycle.txt` and the codex collected report, as in 1 and 4, when `codex/` is present.
  8. The two vocabulary sources: no `_GROK_TYPES` frozenset, or no `_GROK_TYPES_RE=` line → `input_unparseable`.

  The agy and codex pass logs are **not** smoke inputs (no smoke reason reads them), and no `Effort:` item is required of agy or codex, so a halted agy cycle or a `codex-text` log never makes the smoke UNREADABLE. v1.0 required both and over-refused.

- **The stands rule (AC-3.4, plan Risks).** For each document, `v1` is read. If its verdict word is `UNVERIFIED`, `v2` must exist and **the whole of `v2` stands for every surface**, including surfaces whose `v1` pass was fine; nothing in `v1` is scored. If `v1` is not `UNVERIFIED`, `v1` stands. If `v2` is also `UNVERIFIED`, it still stands: each pass that did not deliver (D11's `delivered`) contributes zero findings, and every delivered pass is scored even when its evidence was low.
- **Cycle-record refusals**, all `cycle_token:d<k>.v<N>`, exactly spec AC-5.4's eight triggers, each its own guard: (1) no recorded `AUDITCYCLE:` line; (2) a recorded line that does not parse; (3) `v1` is `UNVERIFIED` and no `v2` is recorded; (4) a `v2` is recorded although `v1` is not `UNVERIFIED`; (5) a `v3` or later; (6) a `command.txt` whose `--surfaces` is not exactly `codex,agy,grok` or `agy,grok`; (7) a pass whose `delivered=` value is `report-file` or `out` has no recorded collected report; (8) (v1.6, spec AC-3.8) the cycle's per-pass root records do not give exactly one root per pass, or two of them name the same `path=` or one inside the other, or they do not all name the same `calibration=` and `list_blob=`. Trigger (8) has one marked guard per shape, each its own fixture: `# M:GAS-CYCLE-ROOT-COUNT`, `# M:GAS-CYCLE-ROOT-SAME`, `# M:GAS-CYCLE-ROOT-NESTED`, `# M:GAS-CYCLE-ROOT-CALIBRATION`, `# M:GAS-CYCLE-ROOT-LIST`.
- **The containment checks (v1.6, spec AC-3.8, AC-5.4, AC-6.6)**, one function, `containment_checks(s2_dir, sources)`, which `extract` and `score` both call, so a run that cannot be scored is refused before labelling. It runs over **every recorded** S2 cycle, standing or re-dispatched, in document and cycle-number order, after triggers (1)–(7) have passed for every document, in three passes, the first failure refusing. (a) **Provenance records.** First the reading's run record `s2/run.txt` is read with `parse_run_line`. If it is absent or malformed, the checks refuse `list_changed:unrecorded` (`# M:GAS-CONTAIN-RUN-RECORD`). This is the orchestrator's v1.8 routing of design audit v3 p1's AC-5.4 finding: the run record is the dispatch's provenance record beside the root records, and `list_changed:unrecorded` is the closed reason the spec already gives an unrecorded provenance record, so `out_of_root` keeps exactly its two triggers. Then every pass's `p<i>.root.txt` is read with `parse_root_line` (`P` from the `--surfaces` list), and an absent or malformed one refuses `list_changed:unrecorded` (`# M:GAS-CONTAIN-ROOT-UNRECORDED`); (b) trigger (8) above; (c) for each grok pass, `h_mad_tool_calls.scan_log` (D19) on `p<i>.log` with that pass's root, and `checkout=`/`home=` from `s2/run.txt`: a token other than `CLEAN` refuses `out_of_root:<doc>.v<N>` (`# M:GAS-CONTAIN-SCAN`; AC-5.4 trigger (1) for `OUT_OF_ROOT`, trigger (2) for `UNREADABLE`). By the time (c) runs, the run record has parsed in (a), so `out_of_root` fires only on its two spec triggers. A codex or agy pass's scan never refuses.
- **Pass → surface** is read from `command.txt`'s `--surfaces` list by pass index (AC-10.1's sense: index, not time).
- **Findings: the gate's own decision structure, not a re-implementation of it** (spec AC-4.1: "Extraction uses the gate's own machinery (`h_mad_audit_gate.classify_detail`, or the same section walk)"). The gate counts a section in `_section_detail` (called by `classify_detail`, which `classify` calls): an all-`None` section is zero; otherwise, for each group of `_bullet_groups(content)`, a group for which `_collapses(group, acknowledged)` is true counts once (its parent), and any other group counts every finding `_flat_findings(group["lines"])` returns; when no group yields a finding, the non-`None` content counts once (the fail-safe). The probe's pure walk `report_findings(text) -> {"must": [...], "should": [...]}` makes the same calls in the same order, with the same empty acknowledged set `classify(text)` uses. It splits sections the way `classify_detail` does (a stripped line equal to a key of `_gate.BLOCKING_SECTIONS` opens that section, any other `## ` line closes it, blank lines are dropped), then for each section:
  1. If every line's `_gate._payload` is a `_gate._is_none_sentinel` payload, the section has no findings.
  2. For each group of `_gate._bullet_groups(content)`: if `_gate._collapses(group, set())` (the line marked `# M:GAS-COLLAPSE-WIRE`), the group is **one** finding, whose text is the group's lines joined with `\n`. Otherwise the group yields one finding per real bullet, which is exactly `len(_gate._flat_findings(group["lines"]))` of them: each line for which `_gate._bullet_remainder(line.strip())` is not `None` and whose payload is real (non-empty, not a `None` sentinel) starts a finding, whose text is that line and the following lines of the group up to the next bullet line. A `- None` bullet starts no finding, and the lines after it up to the next bullet belong to no finding, as they classify nothing in `_flat_findings`.
  3. If step 2 gave no finding, the section's non-`None` content is one finding, its lines joined.

  So the walk's per-section count equals `_section_detail(content, set())["count"]` by construction. That includes the two shapes the v1.2 walk (one finding per real-parent group) got wrong: a short `Label:` parent (`- Build defects:` with two nested children) does not collapse, so it is three findings, as `classify` counts it; and a real parent with a `- None` child and then a real child does not collapse (`none_child`), so it is two. The production caller `extract_report(text, report)` calls `report_findings` and then obtains both counts from one `_gate.classify(text)` call, written as these five lines in this order:

  ```python
  found = report_findings(text)
  must, should = found["must"], found["should"]
  _counts = _gate.classify(text)
  must_count = _counts["must_count"]  # M:GAS-MUST-COUNT-WIRE
  should_count = _counts["should_count"]  # M:GAS-SHOULD-COUNT-WIRE
  ```

  The `classify` call is on an unmarked line, so each marked wire is one line that holds one integer, and X1/X2 (must) and X5/X6 (should) mutate it without changing its type, which is what keeps every row a test kill and not a crash kill. It then asserts `len(must) == must_count`; a mismatch refuses `must_count_mismatch:<report tree path>`. Since the walk now agrees with the gate on every shape by construction, the assertion catches a gate change after this design and a severed connection, and it is tested three ways: direct parity fixtures with the real `classify` (Test Plan, the `test_extract_parity_*` tests), `_gate.classify` replaced, and mutation rows in both directions on each wire (X1/X2 on the must count, X3/X4 on `_collapses`, X5/X6 on the should count). Residual, stated exactly: the section split is the one piece the probe writes itself, because `classify_detail` keeps it inline and exports no function for it; the parity fixtures and the count assertion on every report are what check it.
- **Should-fix findings (spec AC-4.5: "Should-fix hits are published separately and never enter the bar").** The `## Should-fix` section goes through the same walk. Its findings are **always** written to `findings.jsonl` with `"section": "should"` (must findings carry `"section": "must"`), are labelled like every finding, and are counted only on the published `SHOULD:` lines (D13); no path drops them. `extract_report` also compares their number with `should_count`, taken from the same `classify` call on the line marked `# M:GAS-SHOULD-COUNT-WIRE`. A difference is not a refusal, because AC-5.4 is closed and should-fix never enters the bar: the findings are written as the walk gives them, and `extract` prints the published line `SHOULD-COUNT: <report> walk=<n> gate=<m>` before its token, which the measurement doc carries under its observational heading (D15). Because the walk is the gate's own decision structure, that line can appear only after a gate change, and the parity fixtures fail in CI first.
- **Blinding**: ids are `F%08x` from `random.Random(shuffle_seed).getrandbits(32)`, redrawn on collision, and the order is shuffled by the same generator. `findings.jsonl` carries `id doc cycle section text quotes` (the `quote:` lines) and no surface or pass. `key.jsonl` carries `id doc cycle pass surface report` and nothing else; the shuffle seed is in `extract.txt`, which nothing in `score` reads. **DECISION (design-author):** v1.0's `{"shuffle_seed": n}` record in `key.jsonl` is gone, so the key file has one record shape and `key_mismatch` keeps exactly the AC-5.4 triggers (answers the agy nit).
- **Hints (AC-4.4)** are printed to stdout only, as `HINT: <id> candidate-fabrication` or `HINT: <id> candidate-hit:<seed-id>`, and are never written to any file that `score` reads. A `quote:` line is `quote: <path> › <span>` (the grammar `h-mad/audit-prompt.template.md` prescribes), with one level of backtick fencing stripped from the span. The path is resolved to the exported tree before it is checked, because the reviewer saw the root, not the tree: (1) a path under the root of the pass that filed the finding (`p<i>.root.txt` `path=` for an S2 cycle from v1.6, `root.txt` otherwise) is made root-relative; (2) a root-relative path that is a key of `placements(doc, sources)` (D5) is mapped to its tree path, so the seeded target resolves to `seeded/<feature>.<phase>.md` and each paired copy to its `docs/archive/<yyyy-mm>/<feature>/` source; (3) any other path is looked up in the tree as given. `candidate-fabrication` fires when the normalised span is absent from the resolved file, or the file is absent; `candidate-hit:<seed-id>` fires when the span overlaps a seed's normalised `seeded` span in the resolved seeded copy. Residual: a quote that names a file by a spelling none of the three rules resolves (a bare basename, say) yields a `candidate-fabrication` hint, which is advisory and never moves the score.

### D16. grok's profile, prompt staging and `TMPDIR` in `exec` (spec FR-11, AC-11.1–11.3, AC-11.5; v1.6)
Every change below is in `_cmd_exec` of `h-mad/scripts/hmad-dispatch.sh`, and each marked line carries its `# M:` comment (the file's own convention, as in `# M:STEM-DIR`). The rule ranges over every verb that launches a grok process, which at `e3d84865` is `exec` and `audit-cycle` through `exec` (Readings), plus the new `grok-canary` through `exec` (D18).
- **The default.** After option parsing, for grok only, an empty `sandbox` becomes `strict` (`# M:GROK-SANDBOX-DEFAULT`), and grok's argv always carries `--sandbox "$sandbox"`, replacing today's `[ -n "$sandbox" ] && gargs+=(--sandbox "$sandbox")` (`# M:GROK-SANDBOX-ARG`). codex keeps its `workspace-write` default, and agy is unchanged.
- **The override flag is `--allow-weaker-sandbox`** (grok only; given with codex or agy it is an unknown option, exit 2). A grok `--sandbox` value other than `strict` without it is refused before anything is created or launched: exit 2, and on stderr `hmad-dispatch: exec: grok --sandbox <v> is weaker than strict or unknown; pass --allow-weaker-sandbox to run it, and it is recorded` (`# M:GROK-SANDBOX-WEAKER`). The flag with no `--sandbox`, or with `--sandbox strict`, is also exit 2 (`# M:GROK-SANDBOX-OVERRIDE-ALONE`), so `origin=override` always means a weaker profile ran.
- **The environment channel.** The grok child's `env` gets `-u GROK_SANDBOX` (`# M:GROK-SANDBOX-ENV`), so the inherited variable never selects a profile. Residual (spec AC-11.1): a profile set in grok's own configuration files is not inspected; the canary (D18) is what detects a profile that does not deny.
- **The profile record.** Before the launch, `exec` writes exactly one line, `GROK-PROFILE: profile=<p> origin=<default|override>`, to `<log>.profile`, where `<log>` is `exec`'s `--log` or its automatic log (`# M:GROK-PROFILE-RECORD`). `audit-cycle`'s grok log is `<stem>_p<i>.log`, so the record is `<stem>_p<i>.log.profile`, which `record-cycle` copies as `p<i>.profile.txt` (D3, D8), and the score reads it with `parse_profile_line` (D10, D13). A pass with no such file reads `profile=none`, never `strict`. With an automatic log, the record is removed with the log.
- **`audit-cycle` passes no profile**, as at `e3d84865`, and this design adds no pass-through, so every `audit-cycle` grok leg runs `strict` with `origin=default`.
- **Where grok's staging directory is (v1.7, orchestrator ruling 2026-10-20 on the v1.6 report's item 7; spec v1.13 encodes the same ruling).** An audit must leave `git status` unchanged, and a bare `<cd>/.tmp/` in a git checkout is an untracked directory, so it is a tree delta. So `exec` resolves, for grok only and before anything is created or launched, one **staging directory** `S`, which holds the staged prompt and is the grok child's `TMPDIR`:
  1. It runs `LC_ALL=C env -u GIT_DIR -u GIT_WORK_TREE -u GIT_COMMON_DIR -u GIT_OBJECT_DIRECTORY -u GIT_ALTERNATE_OBJECT_DIRECTORIES git -C "$cd_dir" rev-parse --show-toplevel`, with D7's environment, so an ambient `GIT_DIR` cannot pick the answer, and the C locale, so the message test below is stable.
  2. **Exit 0 (a git work tree).** Let `T` be the printed top level. Then:
     - if the `pwd -P` forms of `$cd_dir` and `T` differ, `exec` refuses with exit 2 (`# M:GROK-TMP-SUBDIR`), because `strict` grants only the working directory and system temp, so `T/.h-mad/` would lie outside a subdirectory's cwd and grok could not read its prompt;
     - if `git -C "$T" check-ignore -q .h-mad/tmp/hmad_exec_grok.probe` exits non-zero, `exec` refuses with exit 2 (`# M:GROK-TMP-IGNORED`), because a staging directory that git does not ignore would be a tree delta. This repository's `.gitignore` ignores `.h-mad/*` (Readings); another repository has to as well;
     - otherwise `mkdir -p "$T/.h-mad/tmp"` and `S=$(mktemp -d "$T/.h-mad/tmp/hmad_exec_grok.XXXXXX")`, one fresh directory per dispatch (`# M:GROK-TMP-GIT`).
  3. **Non-zero, and stderr contains `not a git repository` (an export root, or any directory outside a work tree).** `S="$cd_dir/.tmp"`, created with `mkdir -p` and shared by every dispatch in that root, exactly as spec AC-11.3 states it (`# M:GROK-TMP-ROOT`). Every calibration root is this case, because D7 refuses any root from which `rev-parse` succeeds.
  4. **Any other non-zero exit** (`git` absent, `dubious ownership`, a corrupt repository) makes `exec` refuse with exit 2 (`# M:GROK-TMP-GITFAIL`). That fails closed: no guess is made about where the tree is.

  Each refusal goes to stderr as `hmad-dispatch: exec: grok staging: <reason>`, and nothing is created or launched.
- **Prompt staging (spec AC-11.3).** For grok, the bounded prompt is staged with `mktemp "$S/hmad_exec_prompt.XXXXXX"` instead of `mktemp -t` (`# M:GROK-PROMPT-IN-CD`), because `strict` refuses a `--prompt-file` outside the working directory and system temp (incident record table). In both cases `S` lies inside the working directory. For codex and agy the prompt is staged beside the log, `mktemp "$(dirname -- "$log")/hmad_exec_prompt.XXXXXX"` (`# M:EXEC-PROMPT-BESIDE-LOG`). In calibration the log is in the stem dir under `$RUN`, so no prompt reaches system temp. With an automatic log the directory is system temp, as before. The existing `rm -f "$bounded_prompt"` removes the prompt. Between staging and that line the grok branch has no `return` (Readings), and the codex branch's one early return already removes it. The agy branch's `OVERSIZE` `return 2` does not, so v1.6 adds `rm -f "$bounded_prompt"` before it (`# M:EXEC-PROMPT-OVERSIZE-RM`).
- **`TMPDIR` and cleanup.** The grok child's `env` gets `TMPDIR=$S` (`# M:GROK-TMPDIR`).
  - **In a git work tree**, after the grok run and on every path out of `exec` after `S` is created, `exec` runs `rm -rf -- "$S"`. That removes grok's own temp files too. It runs only after re-checking that `S` begins with `$T/.h-mad/tmp/hmad_exec_grok.` (`# M:GROK-TMP-RMGUARD`), so a damaged variable can never widen the removal. The shared `$T/.h-mad/tmp/` is left; it is ignored.
  - **In an export root**, `$cd_dir/.tmp/` is not removed. A concurrent `exec` in the same root may be using it, and removing it between that exec's `mkdir -p` and `mktemp` would fail that exec. The S1 reset removes it (D5), and an S2 root is never reused.
  - Residual, stated exactly: a signal that kills the wrapper between creation and removal leaves `S` in place. In a work tree it lies under the ignored `.h-mad/`, so `git status` is still unchanged. In a root it is the root's `.tmp/`, which `record-cycle` never copies. A grok child that outlives `exec` and writes into `S` after removal recreates nothing, because `rm -rf` has removed the directory and a write into it fails.
- **codex's last-message file** goes beside the log, `mktemp "$(dirname -- "$log")/hmad_exec_last.XXXXXX"` (`# M:EXEC-LAST-BESIDE-LOG`), because it holds codex's findings (spec AC-11.2). **Whether codex can write it there is not measured**: `--output-last-message` is written by the codex CLI, and whether `workspace-write` confines the CLI's own write, not only its commands, has not been probed. So it is a Phase-5 **controlled tracer pair**, run once before the re-smoke (v1.10, design audit v4 p1, the plan's pair). Two otherwise identical dispatches run, with the same one-line prompt file and the same `--cd` under `$RUN/roots`. They differ only in where the last-message file lands, which `exec` places beside `--log` (above):
  - **the control** is `hmad-dispatch exec codex <prompt> --cd <dir> --log "$(mktemp -d)/codex-control.log"`, so its last-message file is in system temp, where codex has always written it;
  - **the treatment** is the same command with `--log "$RUN/work/codex-treatment.log"`, so its last-message file lies beside that log, outside system temp.

  Each **passes** when `exec` prints the reply on stdout and its stderr carries no `EMPTY final message` line. Both stdouts and stderrs are kept under `$RUN/work/`. The control's log holds only the one-line prompt's dispatch, and no calibration data. The decision table has four cells, and a failure is attributed to the last-message placement in exactly one of them:
  | control | treatment | decision |
  |---|---|---|
  | pass | pass | codex runs; the re-smoke and S2 use the codex shape |
  | pass | fail | codex cannot write its last message outside system temp; the runs use the codex-unavailable shape, and the spec is told (spec AC-11.2's instruction) |
  | fail | fail | codex is unavailable (authentication, dispatch or model), with no causal attribution; the codex-unavailable shape |
  | fail | pass | inconsistent; treated as unavailable, with no attribution; the codex-unavailable shape |

  The pair, its four outputs and the cell it landed in are recorded in the measurement doc.
- **Every system-temp write on the calibration path, classified (spec AC-11.2).** The axis is "a file the wrapper or the probe writes during a calibration run". In the wrapper, the nine system-temp `mktemp` sites at `e3d84865` (Readings): `hmad_exec_prompt` and `hmad_exec_last` move (above); `hmad_exec_log` stays, because `audit-cycle` and `grok-canary` always pass `--log`, so a calibration run never reaches it; `_cmd_env`, `_cmd_pin_agents` and `_cmd_pin` (a resolver's stderr, pin-file rewrites), `_cmd_probe` (a two-digit liveness prompt) and `_exec_wt_target` (`orca worktree ps` JSON) stay, carrying no calibration data by content; `hmad_pane_log` stays, because `exec-pane` is not on the calibration path. The `audit-cycle` stem default `/tmp` is never reached, because the runbook sets `HMAD_AUDIT_STEM_DIR="${STEM:?}"` (D8). The assembler's `/tmp` default prompt path is used only with neither `--out` nor `--report-file`, and `audit-cycle` passes both. In the probe, D5 "Where the probe writes". Residual (spec AC-11.2): a third-party tool's own temp writes (agy, codex, git, Python internals) are not controlled.
- **`exec-pane` keeps refusing grok.** It still accepts only `codex|agy` and prints `unknown agent 'grok' (expected codex|agy)` with exit 2; `test_exec_pane_still_refuses_grok` pins that branch of spec AC-11.1.

### D18. The per-run canary: `hmad-dispatch grok-canary` (spec AC-11.4, AC-11.6; v1.6)
- **Command.** `hmad-dispatch grok-canary --run-dir <abs> [--timeout <s>]` (default 300). A usage error (no `--run-dir`, a relative path, a missing directory, a directory inside system temp, or one with no `roots/`) prints usage on stderr, exits 2 and prints no `GROK-CANARY:` line, which spec AC-11.4 makes a refusal. Its last stdout line is the token. **Exit contract (v1.8, orchestrator ruling 1, the base invariant "Audit-gate signal discipline", spec v1.14):** it exits 0 on `GROK-CANARY: PASS` and on every `REFUSED` reason the verb determined, because a refusal is a measured verdict, not an operational error. It exits 2 only on a usage error or an internal error that escapes it; spec v1.14 defines no `internal` canary reason, so such an invocation may print no `GROK-CANARY:` line, which is a refusal. Callers read the token through `require --verb grok-canary` (D8), never `$?`. Until v1.7 this design exited non-zero on every refusal.
- **Layout**, all under `<run-dir>`: the canary's working directory `roots/gas-canary-XXXXXX/` (a fresh `mktemp -d` under `roots/`, the parent every root has, but **empty**: no export, so the canary never carries calibration data), with `.hmad-report/` created in it; and `canary/`, holding `sentinel.txt` (the read sentinel), `denied.txt`'s path (the denied target, which must never exist), `prompt.txt`, `log.ndjson` and its `log.ndjson.profile` (D16), `grok.txt` (`grok_binary=<path> <grok --version line>`) and `token.txt`. The sentinel lies under the run directory, outside the working directory, outside `roots/` and outside system temp; the denied target is a fresh path outside the working directory, under the run directory; the positive control is `<cwd>/.hmad-report/canary.report.md`, the placement of a grok report (D17).
- **Steps.** The verb runs `h-mad/scripts/h_mad_grok_containment.py canary-plant --run-dir <dir>`, then, only if that printed `PLANT: READY …`, `_cmd_exec grok canary/prompt.txt --cd <cwd> --log canary/log.ndjson --timeout <s>` with no `--sandbox`, so the canary runs under exactly the profile, `TMPDIR` rule and prompt staging of every grok leg (D16), then `canary-judge --run-dir <dir> --rc <exec's exit code>`. Every canary file is created exclusively (`O_CREAT|O_EXCL`), so a second canary in one run directory refuses before its grok call and overwrites nothing, and the run's canary record is the first.
- **The sentinel.** `secrets.token_hex(16)`, 128 bits as 32 hex characters, written to `sentinel.txt`, flushed and read back. **The expected value is never re-read from that file** (v1.10, design audit v4 p1). `canary-plant` writes the plant record `canary/plant.txt` exclusively, before the grok call. It holds one line: `PLANT: sha256=<sha256 of the token> sentinel=<path> denied=<path> cwd=<path>`. The plain token appears nowhere but in `sentinel.txt`. The record sits under `$RUN/canary/`, outside the canary's working directory and outside system temp, so it is outside every path `strict` lets grok write. `canary-judge` reads the expected value only from `plant.txt`. The prompt names the sentinel's path and never its content; it asks for three shell commands, each its own tool call, and the reply `DONE`: write `canary` to the denied target, write `canary` to the positive control, and `cat` the sentinel.
- **The seven forms, in spec AC-11.4's order, the first that applies winning.** `canary-plant` decides the ones that need no call, and makes no grok call when one applies: `target_preexisting` (the denied target exists, by `lstat`); `cannot_run:grok_absent` (no `grok` on `PATH`); `no_read_check:sentinel_unplanted` (the sentinel cannot be freshly created with its token). `canary-judge` decides the rest, in order:
  1. `escaped`: the denied target exists;
  2. `read_escaped`: some maximal run of exactly 32 lowercase hex characters in `log.ndjson` (the regex `(?<![0-9a-f])[0-9a-f]{32}(?![0-9a-f])`, over the log read as bytes and searched whole, so every event, tool result, message and non-JSON line is covered) has the planted `sha256`. So a log that carries the original token is caught even after the sentinel was replaced or deleted (`# M:CANARY-READ-BY-HASH`);
  3. `cannot_run:<kind>`: `timeout` when `exec` returned 124 (its deadline), `grok_rc:<n>` for any other non-zero `<n>`, and `truncated` when the log is readable and no line parses as an object with `type == "end"`. `<n>` is `exec`'s exit code, which is grok's own except that `exec` returns 3 for a grok that exited 0 with no final message (its `EMPTY` rule; Readings);
  4. `no_read_check:<kind>`: `log_unreadable` (the log is absent or cannot be read); `sentinel_changed` (the sentinel is absent, or the sha256 of its bytes is not the planted one, `# M:CANARY-SENTINEL-BY-HASH`); `not_attempted` (no `tool_call` event names the sentinel's path, by D19's `named_paths` over its `rawInput` and `locations`);
  5. `no_control`: the positive control is absent;
  6. `no_denial`: no `tool_call` names the denied target's path, or none of those calls has a `tool_call_update` with the same `toolCallId` whose `rawOutput` or `content` strings contain `Operation not permitted`.

  Otherwise `PASS`. The token goes to stdout and to `canary/token.txt`. The record (`canary/`) is copied into `$READING/resmoke/canary/` before the re-smoke commit (D9) and cited in the measurement doc (D15).
- **Residuals, beyond spec AC-11.4's.** The denial is attributed to the write through `toolCallId` (measured on both event types; Readings); a grok that drops it reads `no_denial`, which fails closed. The working directory is empty, so the canary does not test reads of seeded content inside a root, which the root itself shows. `grok_rc:3` names `exec`'s code, not grok's.
- **Tests** (`h-mad/tests/test_grok_audit_surface_containment.py`, a stub `grok` on `PATH` that plants one outcome each, and a stand-in run directory): one fixture per form and per kind, `test_canary_target_preexisting`, `test_canary_escaped` (planted with the denial text logged, so the order is pinned), `test_canary_read_escaped_in_tool_result` and `test_canary_read_escaped_in_message_text` (each with the control present and the denial logged), `test_canary_grok_absent`, `test_canary_grok_rc`, `test_canary_timeout`, `test_canary_truncated`, `test_canary_sentinel_unplanted`, `test_canary_log_unreadable`, `test_canary_sentinel_changed`, `test_canary_not_attempted`, `test_canary_no_control`, `test_canary_no_denial`, `test_canary_pass` (whose prompt is asserted not to contain the token), and `test_canary_second_run_overwrites_nothing`, and the two expected-value fixtures (v1.10), each driven through the real plant → exec → judge path with a stub grok: `test_canary_replaced_sentinel_is_sentinel_changed` (the stub overwrites `sentinel.txt` with another 32-hex token and logs nothing: `sentinel_changed`) and `test_canary_deleted_sentinel_with_token_in_log_is_read_escaped` (the stub prints the original token in a tool result and then deletes the sentinel: `read_escaped`). Each asserts that `plant.txt` holds no plain token. Every fixture asserts the exit code beside the token (v1.8, spec v1.14 AC-11.6): 0 for `PASS` and for every reason form. Two more fixtures exit 2: `test_canary_usage_error_exits_2` and `test_canary_injected_exception_exits_2` (the judge replaced in process by one raising). The pair the spec asks for, `test_require_canary_without_a_token_is_stop` parametrized over a token file from a run that exited 0 and from one that exited 2, asserts `REQUIRE: STOP` both times.

### D19. The out-of-root tool-call scan: `h-mad/scripts/h_mad_tool_calls.py` (spec AC-6.6, AC-5.4 `out_of_root`; v1.6)
One stdlib module holds the parsers, the path grammar and the classification, so the cycle-end verb and the score's re-derivation are one function, `scan_log(text, surface, *, root, checkout, home, needle_dirs)`. The probe imports it (D1); the runbook runs its CLI.
- **CLI.** `python3 h-mad/scripts/h_mad_tool_calls.py scan --surface <grok|codex|agy> --log <file> --root <abs> --checkout <abs> --home <abs> [--needle-dir <tree path>]…`. The last stdout line is the token: `TOOLSCAN: <CLEAN|OUT_OF_ROOT|UNMEASURED> surface=<s> calls=<n> out_of_root=<n> checkout=<n> exempt=<n> nonjson=<n>` (codex: `mcp_unmeasured=<n>` in place of `nonjson=`), exit 0; or `TOOLSCAN: UNREADABLE reason=<log_absent|log_unreadable|no_event|internal:<E>>`, exit 2 (a usage error is `internal:UsageError`). Callers read the token, never `$?`.
- **Parsers and their event shapes** (Readings, over the 2026-10-20 kept logs). The unit is tool calls, never log lines.
  - **grok** (NDJSON): every line is `json.loads`ed on its own; a line raising `ValueError` or `RecursionError` is skipped and counted in `nonjson`. Each object with `type == "tool_call"` is one call, and its strings are every string value, recursively, of its `rawInput` and its `locations`. A reader that parses the whole log as one JSON stream is never used. A log with no parseable object is `no_event`.
  - **agy** (NDJSON, the same per-line rule): an object with `event == "step_update"` whose `step_update.step_type` is `tool` belongs to the call keyed by `(step_update.conversation_id, step_update.step_index)`; each key is one call (an `ACTIVE` event and its `DONE` or `ERROR` event share it), and its strings are every string value of `step_update.tool_info.parameters` over the call's events.
  - **codex** (text): the scan starts after the last line equal to the dispatch boundary (`$HMAD_DISPATCH_BOUNDARY`, default `===HMAD-DISPATCH-BOUNDARY===`), which ends codex's echo of the prompt, or at line 1 when there is none. A line equal to `exec` opens a call, whose one string is the following lines up to the first line equal to `exec`, `codex`, `thinking` or `user`, or matching `^ (succeeded|exited -?[0-9]+|declined|failed)\b`, or the end; that string holds the command and its ` in <cwd>` suffix. `mcp_unmeasured` counts the lines after the start matching `^tool [A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\(`, which are never scanned.
- **The path grammar**, over each string. A path starts at the string's start or after whitespace or one of ``"'`=(<>|;&,[{``, in one of four spellings: `~/`, `$HOME/`, `${HOME}/`, or `/` followed by a first component of `[A-Za-z0-9._-]+`. It runs to the next whitespace or one of ``"'`;|&<>(){}[],``. The first three spellings are rewritten to `<home>/`, where `<home>` is the run's `$HOME` from `run.txt`; the result is `posixpath.normpath`ed (lexical, so `..` inside a spelled path is folded and no symlink is followed). `named_paths(strings, home)` returns them.
- **Classification of one path.** Inside the root when it equals the root's recorded `path=` or begins with it followed by `/`. Otherwise it is exempt when it is `/dev` or below it (every surface), or, for grok only, when it is at or below `<home>/.grok/sessions/<key>`, with `<key>` `urllib.parse.quote(<root>, safe="")` of that recorded path, or at or below `<home>/.grok/skills`. Every other path is out of root, `<home>/.grok/sessions` itself and every other session directory included, and for codex and agy every `<home>/.grok/` path. **Per call:** it counts in `out_of_root` when any of its paths is out of root, else in `exempt` when any is exempt; of the `out_of_root` calls, it counts in `checkout` when an out-of-root path is at or below `checkout=` or contains `<needle>/` for a `--needle-dir` (the three source archive directories, which hold every ledger `source`).
- **The word.** grok: `OUT_OF_ROOT` when `out_of_root > 0`, else `CLEAN` (a log with parseable events and no tool call is `CLEAN calls=0`). codex and agy: `UNMEASURED` when no call is found, never `CLEAN` with 0 (spec AC-6.6 residual (4)), else `OUT_OF_ROOT` or `CLEAN`.
- **The halt** (D8): every grok pass is scanned when its cycle ends, and any grok token but `CLEAN` halts the run. A codex or agy count is a published finding (D13), never a halt.
- **Positive controls.** (1) On `main`, `test_scan_counts_an_escape_after_a_non_json_line`: a grok log whose out-of-root `tool_call` follows a non-JSON line counts `out_of_root=1` and `nonjson=1`. (2) Before the fresh S2's scan is published, the operator runs the shipped CLI on the kept `$KEEP/run-ab2c85dc2e25/data/s2/d5/v1/p3.log` with `--root` from that cycle's `root.txt` `path=`, `--checkout` the live checkout and `--home "$HOME"`; its `checkout=` must be above 0 (the incident's own predicate reads 14 calls there; spec Premises). Its token line is published with the scan. A control that reads 0 makes the scan invalid: no scan line of the run is published, the scan is repaired and run again.
- **Residuals, stated exactly.** Spec AC-6.6's four, plus these, which the grammar adds: (5) a path that follows `:` (a `PATH`-style list, `file://`) is not seen; (6) a bare `/` (`find /`) and `/` followed by a character outside the name class are not counted; (7) a regular expression or an expression spelled `/name…` after a delimiter counts as a path, which over-counts and so fails closed, as a grok halt; (8) the codex MCP header shape is not measured: no kept codex log holds a line of the counted shape (Readings), and a tool-output line of that shape inflates `mcp_unmeasured`, which is published only; (9) `locations` is scanned beside `rawInput`, which only adds paths.
- **Tests** (`test_grok_audit_surface_containment.py`): one per token value and per exempt class, each alone: `test_scan_grok_clean`, `test_scan_counts_an_escape_after_a_non_json_line`, `test_scan_grok_live_checkout_counts_checkout`, `test_scan_grok_absent_log_is_unreadable`, `test_scan_grok_no_event_is_unreadable`, `test_scan_dev_path_is_exempt`, `test_scan_own_session_dir_is_exempt` and `test_scan_grok_skills_is_exempt` (each parametrized over the four spellings), `test_scan_other_session_dir_is_out_of_root`, `test_scan_sessions_dir_itself_is_out_of_root`, `test_scan_other_grok_path_is_out_of_root`, `test_scan_mixed_exempt_and_out_of_root_counts_out_of_root`, `test_scan_codex_own_looking_session_path_is_out_of_root`, `test_scan_codex_no_call_is_unmeasured`, `test_scan_codex_skips_the_prompt_echo`, `test_scan_agy_groups_active_and_done_events`, and `test_scan_cli_and_function_agree`. The probe's side is AC-5.5's `out_of_root` fixtures (Test Plan).

### D20. The grok session-store quarantine (spec AC-11.7; v1.6)
- **Command.** `python3 h-mad/scripts/h_mad_grok_containment.py quarantine`. It reads `$HOME` from the environment, so a fixture runs it against a stand-in `$HOME`. The store is `$HOME/.grok/sessions/`; the quarantine is `$HOME/.local/state/h-mad/grok-audit-surface/grok-quarantine-<yyyymmddThhmmssZ>/`, one per invocation, under the run directory's parent, outside every run's `roots/` and outside system temp.
- **Steps, each measured before the next.** (1) The parent is created with its parents if absent, and the quarantine with `os.mkdir`, which refuses an existing path. (2) The store is listed with `os.scandir`, and every entry whose name matches `*gas-root-*`, of any kind and never followed, is listed. (3) Each is moved with `os.rename` into the quarantine under its own name; nothing is ever copied or deleted, so a move across file systems fails rather than becoming a copy. (4) The store and the quarantine are listed again.
- **Token**, the last stdout line, after one published `MOVED: <name>` line per moved entry: `QUARANTINE: VERIFIED moved=<n> dest=<abs>` (`moved=0` when nothing matched), or `QUARANTINE: REFUSED reason=<r>`. **Exit contract (v1.8, orchestrator ruling 1, spec v1.14):** exit 0 on `VERIFIED` and on each of the five ordered reasons the step determined; exit 2 only on a usage error or an escaping internal error, which still prints its `internal:<ExceptionName>` line (until v1.7 every refusal exited 2), with `<r>` the first that applies of spec AC-11.7's five, in its order: `quarantine_exists` (`os.mkdir` found the path); `move_failed:<n>` (`<n>` renames raised); `residue:<n>` (`<n>` matching entries remain in the store); `count_mismatch` (the listed entries present in the quarantine are not exactly the listed count); `unreadable` (a listing in step 2 or 4 raised, an absent store included). A reason whose measurement could not be taken does not apply, so a failed first listing reads `unreadable`. **The sixth form**: a usage error or an escaping exception prints `QUARANTINE: REFUSED reason=internal:<ExceptionName>`, which is a refusal like the others. Spec v1.13 AC-11.7 encodes it ("It is the sixth form, a last resort that none of the five names"); v1.6 had reported it as owed, which is now settled.
- **The token consumer, `require` (v1.8, D8).** `python3 h-mad/scripts/h_mad_grok_containment.py require --verb <toolscan|grok-canary|quarantine> --token-file <file> [--halt-file <file>]` prints `REQUIRE: OK` or `REQUIRE: STOP reason=<last line | no_token:<file>>`. It exits 0 on both, and 2 only on a usage or internal error, after writing the halt file when one was named. It reads the last line of the file and nothing else: `OK` needs exactly `GROK-CANARY: PASS`, a line beginning `QUARANTINE: VERIFIED moved=`, or one beginning `TOOLSCAN: CLEAN surface=grok `, for the verb named. For `toolscan` a `STOP` first appends to `--halt-file`. Tests: `test_require_ok_per_verb`, `test_require_stop_on_another_token`, `test_require_stop_on_an_empty_file`, `test_require_stop_on_an_absent_file`, `test_require_toolscan_stop_writes_the_halt_file`, `test_require_internal_error_still_writes_the_halt_file`, and the canary pair of D18.
- **Where it runs** (D8): before the canary, and again before the fresh S2's first cycle; a refusal means that stage does not start, and no grok call of the run is made until a later invocation verifies.
- **Residuals, beyond spec AC-11.7's four.** The quarantine name has one-second resolution, so a second invocation within the same second refuses `quarantine_exists`, which fails closed. The canary's own session directory is keyed by `gas-canary-…`, not `gas-root-`, so the second quarantine leaves it; it holds only the canary's prompt, which carries no calibration data (D18).
- **Tests** (`test_grok_audit_surface_containment.py`, stand-in `$HOME`): `test_quarantine_verifies_and_moves_every_match`, `test_quarantine_verifies_zero_matches`, `test_quarantine_refuses_an_existing_quarantine`, `test_quarantine_refuses_a_failed_move`, `test_quarantine_refuses_residue` (a matching directory planted after the move: `residue:1`), `test_quarantine_refuses_a_count_mismatch`, `test_quarantine_refuses_an_unreadable_store`, `test_quarantine_never_deletes`, and the two `internal` fixtures spec v1.13 AC-11.6 requires (v1.8, design audit v3 p1 and p2): `test_quarantine_internal_on_an_injected_exception` (the move step replaced in process by one raising `RuntimeError`: last line exactly `QUARANTINE: REFUSED reason=internal:RuntimeError`, exit 2, and every matching entry still in the store) and `test_quarantine_internal_on_a_usage_error` (an unknown flag: exactly `QUARANTINE: REFUSED reason=internal:UsageError`, exit 2, no quarantine created, nothing moved). Every quarantine fixture asserts the exit code beside the token: 0 for `VERIFIED` and the five reasons, 2 for the two `internal` fixtures. The last-resort wire carries `# M:QUARANTINE-LAST-RESORT`, and its row targets the injected-exception fixture.

## Error Handling Strategy
- Every refusal is a token line in its mode's D2 grammar, read by callers from stdout and never from `$?` (base §"Audit-gate signal discipline").
- **AC-5.4 reasons, and where each fires** (the checking modes' `UNREADABLE` tokens):
  - `ledger_counts`, `ledger_origin`, `seed_rebuild`: D4
  - `leak:<path>`: D5, D6
  - `root_git:<path>`: D5 (the reset target precondition), D7, D9
  - `must_count_mismatch:<report>`, `key_mismatch`, `label:<id>`: D12, D13
  - `calibration_drift:<path>`, `calibration_drift:not_descendant`, `calibration_ref:<kind>`, `main_leak:<path>`, `list_changed:<oid>`: D9; `list_changed:unrecorded` also in D12's containment checks
  - `cycle_token:<cycle>`: D12 (triggers (1)–(8))
  - `out_of_root:<doc>.v<N>`: D12's containment checks (v1.6, through D19)
  - `internal:<ExceptionName>`: D1, every mode (D2 `UsageError`; D5's reset and parent-directory classes)

  The order inside each mode is the order listed in its section.
- **Smoke**: `SMOKE: UNREADABLE reason=input_missing:<path>|input_unparseable:<path>` (exit 2) is decided before any FAIL reason (D11).
- **Recording modes**: `RECORD: REFUSED` and `COMMIT: REFUSED`, with the D2 reason sets (D8, D9).
- **The v1.6 verbs outside the probe**: `TOOLSCAN:` (D19), `GROK-CANARY:` (D18) and `QUARANTINE:` (D20), each one token line read from stdout, never from `$?`, and every `GROK-CANARY:`, `QUARANTINE:` and `TOOLSCAN:` token the runbook gates on is read by `h_mad_grok_containment.py require` (`REQUIRE: OK|STOP`, v1.8, D8, D20); the runbook stops at any `STOP`. `GROK-CANARY:`, `QUARANTINE:` and `REQUIRE:` exit 0 on every verdict they determined and 2 only on a usage or internal error (v1.8, ruling 1). `exec` refuses a weaker grok profile with exit 2 and a stderr message and launches nothing (D16), and `audit-cycle` refuses a bad `--pass-root` set with exit 2 before assembly (D17).
- **Unexpected errors.** An exception that escapes a mode's own checks prints the mode's refusal token with `reason=internal:<ExceptionName>` (for `smoke`, `input_unparseable:<path>`), exit 2 (D1); its traceback goes to stderr unless it is one of the declared `ProbeRefusal` classes (D1, "Traceback scope"). An argv that names no mode prints `PROBE: UNREADABLE reason=unknown_mode`, exit 2 (D2). There is no exit without a token. v1.0's no-token traceback branch is removed (spec AC-5.1, AC-5.4 `internal:<ExceptionName>`).

## Test Strategy
- **Synthetic only, never the network or the real ref** (AC-2.7). Every AC-2.7 fixture builds `tmp_path/origin.git` (bare) and `tmp_path/work` with `origin` pointing at it, and creates the branch inside that repo. Each test whose clean case depends on `tmp_path` lying outside a work tree first asserts that `git -C tmp_path rev-parse --git-dir` fails; it does not skip.
- **The probe is driven as a subprocess** (`sys.executable` plus the literal path), so the exit code and the token are asserted together, and every refusal test asserts the **exact** last stdout line (prefix, word and reason). Pure helpers (the normaliser, `d3`, `verdict`, `calibration_data_files`, the token parsers) are also imported for unit tests, by path, through `importlib.util.spec_from_file_location`. Tests that must replace a function (`_gate.classify`, a mode handler) call `main(argv)` in process with `monkeypatch` and `capsys`.
- **Archive survival.** Each probe test module defines `PROBE = REPO / "docs/03-analysis/probes/grok-audit-surface/grok_audit_probe.py"` as a single literal, which is what `h_mad_archive_feature.probe_readers` matches (needle `docs/03-analysis/probes/grok-audit-surface` followed by a path boundary).
- **Tests over unchanged code** (FR-8, FR-9, FR-10, AC-7.2's stamp pin, the kept doc pins) are shown able to fail only by their mutation rows. **New probe guards** are RED first, and then each gets a row.
- **Incident replay** (base §"Incident replay"). The real artefacts are the archived documents and the live runs. AC-2.7 forbids real calibration data in the suite, so the replay is the S0b `check-ledger`/`build-root` run and the S3 `main-leak` and `rescore` runs over the real ref, whose token lines the measurement doc records.

## Invariant Compliance
- **Audit-gate signal discipline**: complies. Every verdict is a stdout token in its mode's D2 grammar, with exit 0 on success, PASS, FAIL, MISS and INCONCLUSIVE. Exit 2 is used only for a refusal, and every exit carries a token (D1, Error Handling).
- **Single-source contract**: complies. The probe imports `classify`, `_gate_token`, `ORIGINS` and `_GROK_TYPES`, reads `_GROK_TYPES_RE` from its file, and reads wrapper verdicts from tokens through one parser per token kind (D10). There is one normaliser for the scan and the main leak check (D6), one placement function for root building and quote resolution (D5, D12), one extraction function for `extract` and re-extraction (D12), and, from v1.6, one tool-call module: `h_mad_tool_calls.scan_log` serves the cycle-end verb and the score's re-derivation, and its `named_paths` serves the canary judge's path reading (D18, D19). The canary itself is never scanned (spec AC-6.6).
- **Standalone / no plugin dependency**, and **No new external dependency**: complies. The probe uses the stdlib, `git` and pytest. No agent CLI is invoked by the probe or by any test; the wrapper tests use the existing stubs.
- **Portable time bounds**: complies. Live cycles are bounded by the wrapper's `--timeout`, and no design command uses `timeout`/`gtimeout`.
- **Doc-template superset compliance**: complies. This document carries the Phase 4 template's sections, and none of the plan-plus literals.
- **Operator-override preservation; Backward compatibility**: complies, with one stated behaviour change. There is no change to the gate, the sidecar or any verdict. The stub knob is opt-in, so existing tests' prompts are unchanged. FR-11 changes `exec grok` for every caller (the `strict` default, and the prompt and `TMPDIR` staged under `<top level>/.h-mad/tmp/hmad_exec_grok.XXXXXX/` in a git work tree, or under `<cd>/.tmp/` outside one, D16), as the spec requires; the operator keeps the override through `--allow-weaker-sandbox`, which is recorded, and D16 lists what reaches production. `audit-cycle` without `--pass-root` behaves as before.
- **Marker discipline**: complies. Every probe mode writes an `[H-MAD]` marker to stderr (D1).
- **Mutation verification**: complies. `commit-data` re-reads the ref, `build-root` re-walks after each removal, `record-cycle` re-lists its dest, every push is confirmed by `ls-remote`, `rescore` re-lists after cleanup, the quarantine re-lists the store and the quarantine after its moves (D20), and the canary reads the sentinel back after planting it (D18).
- **Test discrimination; Connection enforcement**: complies. New guards go RED first and get a P-row per alternative. Tests over unchanged code get W/G/C/K rows, and each wire is mutated in both directions (W1/W2, W4/W5, W9/W10, G3/G4, C1/C4, X1/X2, X3/X4, X5/X6).
- **Incident replay; Reimplementation parity**: the replay is the operator's S0b and S3 runs over the real archive and the real ref (Test Strategy), because AC-2.7 forbids real data in the suite. The extractor makes the gate's own per-group calls (`_bullet_groups`, `_collapses`, `_flat_findings`) rather than re-implementing them, and its count is checked against `classify` on every report (D12); the one piece it writes itself, the section split, is stated as D12's residual and covered by the parity fixtures.
- **Regression provenance; Both halves of a doc change**: no existing test is edited to pass. AC-6.2a replaces the command with a working one (`hmad-dispatch audit-cycle`, which parses `--surfaces`) in the same change, and its new test asserts the new path is present, not only that the old one is gone.
- **Project: skill self-containment**: complies. No skill imports another skill. The probe lives under `docs/`, not in a skill. The mutation spec's absolute interpreter path is test infrastructure under `h-mad/tests/`, with 11 committed precedents (9 `/opt/anaconda3/bin/python3` and 2 `/opt/anaconda3/bin/python3.11`).
