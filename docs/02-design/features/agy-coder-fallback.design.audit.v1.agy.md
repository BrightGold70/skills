AUDIT-agy-coder-fallback-design-v1-BEGIN
## Summary
The design is thorough and faithfully carries most obligations from spec v1.6 and plan v1.4, but three build-class defects in the FR-6 import-error guard and FR-4 target/workdir handling would break existing mutation rows (`M:G2`, `M:G5`), cause out-of-root writes (`/tmp`, `artifactDirectoryPath`) to raise `ValueError` in `_is_shell_allowance`, and diverge from the Codex gate on `run_command` directory resolution. Two additional should-fix items cover a non-dict guard and property-order constraint in FR-1 and the `hooks.json` fixture needed by `test_prompt_file_is_agent_independent` under AC-9.1.

## Must-fix
- FR-6 specifies that `h-mad-codex-tdd-gate.py` catches import failures from `h_mad_target_identity` into `_POLICY_IMPORT_ERROR` at module top and that `main` denies with `kind=judge-error` *before* calling `_main_guarded` whenever `_POLICY_IMPORT_ERROR` is set — in `h-mad/tests/test_h_mad_codex_tdd_gate_judge.py`, `test_codex_gate_kind[judge-error]` copies `hooks/h-mad-codex-tdd-gate.py` into `tmp_path / "B/hooks/h-mad-codex-tdd-gate.py"` with only `B/scripts/h_mad_tdd_judge.py` and no `B/scripts/h_mad_target_identity.py`, while row `G2` in `h-mad/tests/mutation-specs/codex_gate_judge_wiring.json` mutates `except Exception as exc:  # M:G2` around `_main_guarded()` in `main()` to `except ZeroDivisionError as exc:  # M:G2` and runs that exact test; returning in `main()` before `_main_guarded()` makes `test_codex_gate_kind[judge-error]` pass on the mutant without ever reaching `# M:G2`, so `G2` survives (`MUTATION: SURVIVED`) and breaks AC-6.1 (and also denies all calls when `step5` is inactive). Raising `_POLICY_IMPORT_ERROR` inside `_main_guarded()` preserves `M:G2`.

- FR-4's Class (b) target-judging sequence calls `_is_shell_allowance(root, resolved)` before checking whether `resolved.target` is inside `root` and omits three rules from the Codex gate's in-root target evaluation — (1) `_is_shell_allowance` (moved byte-for-byte from `h-mad-codex-tdd-gate.py` by FR-6) calls `candidate.relative_to(root)` without catching `ValueError`, so calling it on `/tmp` or `artifactDirectoryPath` targets outside `root` raises `ValueError` and triggers step 6's top-level `kind=judge-error` deny on every out-of-root write in AC-4.1; (2) inside `root`, checking only a single `relative` path instead of iterating `resolved.names` and picking `min(production)` as `h-mad-codex-tdd-gate.py` does lets a hard-linked test alias (`src/test_a.py` linked to `src/z.py`, where `'test_a.py' < 'z.py'`) bypass `_is_production_python`; (3) passing `read_chain(root, absolute)` directly to `judge(root, absolute, ...)` without branching on `chain.value` (`"unreadable"` -> `kind=judge-error`; `!= "active"` -> allow) or running `read_chain` on in-root production `.py` targets before any `rglob`-based inactive shortcut misses unsearchable `docs/` (`chmod 000`, guarded by `M:G5` in `codex_gate_judge_wiring.json`) and mis-judges multi-subproject trees; and (4) `artifactDirectoryPath` must be checked as a non-empty `str` before `Path(artifactDirectoryPath)` because `Path("")` resolves to `Path.cwd()`.

- FR-4's Class (c) `run_command` handling calls `os.chdir` to the command's `Cwd` before judging and leaves `Cwd == ""` (empty string) unmatched in its three-case definition — (1) when `Cwd` is `""`, `MALFORMED_WORKDIR` (e.g. `0`), or a non-existent path (`str(root / "no-such-dir")`, as in `test_a_workdir_outside_the_root_stays_refused`), `os.chdir` raises `FileNotFoundError` or `TypeError` and denies with `kind=judge-error` before `_safe_shell_command` or `_operator_allowed` runs, whereas the Codex gate never `chdir`s to `workdir`, treats `""` as `root`, still honors read-only commands (`ls`) and `.h-mad/phase5-shell-allow` prefixes, and denies relative `.venv` tokens under a bad `workdir` as a policy refusal rather than `judge-error`; and (2) because agy runs the hook in `<root>/.agents`, calling `os.chdir(args.Cwd)` on a relative `args.Cwd` resolves it against `<root>/.agents` instead of `root`, and changing the process working directory to a subdirectory before calling `_safe_shell_command(command, root, cwd)` breaks `_cwd_escapes_root(root, cwd)` (`Path(cwd).expanduser().resolve() != root`) and `_safe_hmad_script` (`_path_within("docs/.bkit-memory.json", root / "docs")`).
