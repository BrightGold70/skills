AUDIT-doc-block-exec-design-v69-BEGIN
## Summary
The design for `doc-block-exec` is highly rigorous, but the audit surfaced cross-document inconsistencies between the implementation plan and the actual `h-mad` test suite (referencing non-existent test functions for Phase 5 and Zero Script QA). Additionally, there are adversarial contradictions in how the CLI handles empty substitution keys if validation is strictly delegated to the API, and some omissions in the Error Handling Strategy summary table compared to the Detailed Design.

## Must-fix
- **Cross-doc consistency / Implementation plan:** In FR-6 AC-6.1 and AC-6.2 (Task 6), the implementation plan references `test_the_phase_5_design_system_examples_are_live` and `test_the_zero_script_qa_examples_are_live` as existing tests in `tests/test_h_mad_collect_report_docs.py` from which it will remove `re.findall(r"```bash")`. However, these tests do not exist anywhere in the `h-mad` suite. Furthermore, `test_h_mad_collect_report_docs.py` currently only contains two instances of `re.findall(r"```bash")` (at line 270 in `_gate_bash_block` and line 412 in `test_exec_codex_dispatch_carries_out_log_and_timeout`), so it is impossible to remove two and leave exactly one at line 412 as stated.
- **Adversarial consistency:** The design states: "The empty-key rule lives in the API, not only the CLI: `substitute(block, subs)` raises `BadSubstArg(\"\")` for an empty key... `main` reaches the same rule through `substitute`." However, if `main` delegates empty-key validation to `substitute`, the `raw` argument (e.g., `--subst =V`) is already split and lost; `substitute` only knows the key is `""`. Therefore, `main` cannot format the specified CLI refusal `BAD_SUBST arg=<raw>` (it would print `arg=`). Either `main` must validate empty keys itself before calling `substitute` (contradicting "the one rule lives in the API"), or it delegates it and violates the AC formatting.

## Should-fix
- **Adversarial consistency:** In the "Error Handling Strategy" exception table, the mapping description for `LaunchFailed(stage, err, pgid=None)` states "a non-ESRCH killpg error, or an OSError from communicate/the drain/pipe close/wait (collect)". It omits `subprocess.TimeoutExpired` from the post-kill `wait` which maps to `stage=reap`, despite this being correctly specified in the "Two races remain" text body ("on its TimeoutExpired the pending outcome becomes LaunchFailed('reap', <the TimeoutExpired>)").
- **Adversarial consistency:** In the "Error Handling Strategy" exception table, the mapping description for `StreamPathUnwritable` states "the two-arm os.open create-or-open loop itself ... also its bounded-retry exhaustion". It omits the `stat.S_ISREG` check (refusing FIFOs, sockets, etc.), which the Detailed Design explicitly states will also be refused as `StreamPathUnwritable`.

## Nit
- **Adversarial consistency:** In the helper mutation spec table, the `empty-key-accepted-by-api` mutation describes `substitute` as calling `str.replace("", v)`. However, the Detailed Design states that `substitute` performs a single compiled regex alternation (`re.sub`). The description should clarify that `str.replace` is just the conceptual equivalent of the vulnerability.
