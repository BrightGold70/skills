## Nit
- The `_mechanism` text of `at-line-broken-argument-passes-the-gate` says the mutant "forges a PASS line". Under that mutant, with the ` ` parametrisation the row names, the run halts `task_not_found` and `_enc` prints ` ` escaped, so nothing is forged. The kill comes from the halt-reason mismatch, which is a legitimate reason, just not the one the text describes.
- `_enc` prints a code point above U+FFFF as `\u` followed by 5 hex digits: `_enc('a\U000e0001b')` gives `a1b`, which a reader parses as `` + `1`. `_enc` also leaves backslashes alone, so a literal `\x0a` and an escaped newline print identically (`_enc('a\\x0ab') == _enc('a\nb') == 'a\x0ab'`). Both are cosmetic and forge nothing. Using `\U%08x` above 0xFFFF fixes the first.
- The gate refuses every non-printable character (NBSP, U+202F, ZWJ, bidi controls), which is more than the stated rationale, line forging, requires. It matches the existing `M:RV-BASE-LINE` choice and the documentation ("not one printable line"), so it is consistent. Expect that a pasted macOS-style name containing U+202F gets refused as `argument_not_printable`.
