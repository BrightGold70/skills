## Summary
The implementation plan successfully operationalizes the design's two-process boundary, cleanly splitting the workload between shell assembly/dispatch and Python collection/verdict generation. However, it suffers from a regression in Task 7 that undoes the bash array fix established in Task 5, and it carries contradictory claims regarding the force-direction mutations in Tasks 3 and 8 that must be corrected to prevent the mutation harness from silently passing over broken or mis-anchored logic.

## Must-fix
- Task 7 re-introduces the scalar variable bug fixed in Task 5 — Task 5 explicitly converted the per-pass paths into bash arrays (e.g., `report[$i]`, `out[$i]`) to prevent variables from holding stale state across passes. However, Task 7's helper invocation loop (`args+=(--pass "${i}:${report_i}:${out_i}:${rc[$i]}")`) still uses the old `${report_i}` and `${out_i}` scalars. Since these are now undefined, the shell will dispatch empty paths to the helper, breaking the cycle. Change Task 7 to use `${report[$i]}` and `${out[$i]}`.
- Task 3 AC 4 cites an impossible force-direction test (Contradiction) — The plan claims that mutating Rung 3's empty-slot guard to `if True:` breaks `test_collect_report_file_present`. Because Rung 1 short-circuits and returns early when the report is present, Rung 3 is dead code for that test. Mutating dead code will survive silently in the harness and the test will still pass. The failing test must be one where execution actually falls through to Rung 3 (e.g., `test_collect_none` rigged with an `--out` sentinel, or a fixture where the report fails Rungs 1 and 2 but has an `--out` sentinel).
- Task 8 Row 12 uses an ambiguous/incorrect anchor name (Contradiction) — Row 12 targets the shell's HALT branch, and the rationale below the table explicitly states "row 12 removes the HALT branch." However, the anchor column in the table calls it the "`ASSEMBLE:`-token guard". The verb has an actual token-emptiness guard (`[ -n "${tok[$i]}" ] || exit 4`) distinct from the HALT branch (`if [ -n "$halt_pass" ]; then`). Calling the HALT branch the "`ASSEMBLE:`-token guard" conflates the two and will cause the mutation harness to target the wrong line. Correct Row 12's anchor name to explicitly cite the HALT branch.

## Nit
- Task 6 AC-4.1 phrasing for collection calls — The AC claims "every dispatch is reaped before any collection call is made, asserted by ordering in the stub's invocation log." Since the verb does not make collection calls directly (it invokes the Python helper, which then makes the calls), the verb's test can technically only assert that `_cmd_exec` completes before the helper itself is invoked. Refining the phrasing to specify that the helper invocation happens post-reap would make this more precise.
