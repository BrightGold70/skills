# Spec: grok-audit-surface

## Executive Summary
Measure grok's audit recall and fabrication rate against agy on a fixed seeded-defect set, publish the result either way, and only if grok clears the D3 bar against agy (fabrication rate no higher, recall no lower, and recall strictly higher when the fabrication rates are equal, so a full tie does not promote), make grok a standing third leg on a document's first gating cycle (`--surfaces codex,agy,grok`), leaving revision cycles, the exit streak and the round cap as they behave today.

## Goal
Measure grok as an audit surface, ending the **unmeasured** label on its audit precision, and add a third model family to each document's first gate when, and only when, the measurement supports it.

## Decisions carried in (operator-approved 2026-10-18, binding)
- **D1 Role.** grok becomes a standing third leg on a document's FIRST gating cycle only. Revision cycles are unchanged: codex gates and the `doc-auditor` does an ADVISORY delta review. Out of scope: grok as implementer, grok as doc author, and a grok TDD write gate.
- **D2 Calibration.** A seeded-defect set built from copies of archived phase documents that have already been audited, with a ground-truth label per seed. grok and agy run on identical seeded prompts through the normal audit-cycle path, and codex runs as the reference ceiling when it is available. The scorer is a committed probe, the result is a committed measurement doc, and both can be re-run after a grok upgrade.
- **D3 Promotion bar (amended by operator decision, 2026-10-18: strict tie rule).** Compared with agy on the same seeds, grok passes only when its fabrication rate is ≤ agy's AND its recall is ≥ agy's, AND, when the two fabrication rates are equal, grok's recall is STRICTLY greater than agy's. Stated as one predicate: `(fab_grok < fab_agy AND recall_grok ≥ recall_agy) OR (fab_grok = fab_agy AND recall_grok > recall_agy)`. A full tie (equal fabrication rate and equal recall) does NOT promote. The amendment supersedes the looser reading of the original D3 (≤ and ≥ alone, under which a full tie passed) and adopts the brainstorm's Risks-row rule. Every statement of the bar in this spec (Executive Summary, AC-5.3, AC-5.5, FR-6, FR-7) refers to this predicate. On a miss grok stays fallback-only, and the numbers are still published. "Unmeasured" is retired either way. The routing change (FR-7) ships only on a pass.
- **D4 Re-smoke.** The re-smoke on grok 1.0.62 covers the AUDIT PATH ONLY. The host-mode adapter is out of scope.

## Functional Requirements

### FR-1: Audit-path re-smoke on grok 1.0.62 (D4)
- **Description**: Before any calibration dispatch, run one real grok audit pass through `hmad-dispatch audit-cycle --passes 1 --surfaces grok` against one seeded document from FR-2, in that document's AC-2.6 export root, and record what the audit path actually does on 1.0.62. The smoke covers four things: the `exec grok` audit dispatch, the NDJSON event types, `scan_grok` evidence, and report-file delivery. It covers nothing in host mode (hooks, `spawn_subagent`, the TDD gate, session id).
- **Acceptance Criteria**:
  - AC-1.1: The smoke's pass log holds at least one `end` event, and the cycle's `Effort:` block reports `format=grok` (shape `grok`), not `grok-truncated`. A `grok-truncated` reading fails the smoke. It is not retried as a pass.
  - AC-1.2: Every distinct `type` value in the live log is listed in the measurement doc and classified as in-vocabulary or out-of-vocabulary against BOTH `_GROK_TYPES_RE` (`hmad-dispatch.sh`) and `_GROK_TYPES` (`h_mad_review_evidence.py`). If the two vocabularies differ from each other at the smoke sha, the smoke fails. An out-of-vocabulary type does not fail the smoke, but it is published together with whether it carries tool or usage data. If `end`, `tool_call` or `tool_call_update` is missing, the smoke fails.
  - AC-1.3: Report delivery is shown by `COLLECT: OK`, or by a non-`none` `delivered=` field on the `AUDITCYCLE:` line, together with a `GATE:` token scored from the report file. A verdict read from grok's final message alone does not count.
  - AC-1.4: The measurement doc records the `RESOLVED-MODEL` line from `h_mad_resolved_model.py grok --log <pass log>`, the pass's wall time, and the `--timeout` chosen for FR-3. The timeout is derived as `ceil(1.5 × measured wall seconds / 60) × 60` with a floor of the wrapper's default 900 s, and the derivation is printed beside the result.
  - AC-1.5: `h-mad/references/grok-runtime.md` §"Version and compatibility" gains one sentence saying that the audit path (the `exec grok` audit leg, the event vocabulary, `scan_grok` and report delivery) was re-smoked against grok 1.0.62, and naming the measurement doc. The existing sentence "These mappings were checked against grok 1.0.41." stays **unchanged**, because the host-mode mappings it covers were not re-checked (D4). This sentence ships only when the smoke passes (AC-1.7) and the score is not `UNREADABLE` (see "Delivery by outcome").
  - AC-1.6: Non-git root acceptance is MEASURED, not assumed. In the same export root as the grok smoke, S1 also runs one `hmad-dispatch audit-cycle --passes 1 --surfaces agy` cycle, and one `--passes 1 --surfaces codex` cycle when codex is available. codex's `--skip-git-repo-check` is a claim about the code and is measured the same way, not taken as given. A surface **accepts** the root when its pass delivers a report (the AC-1.3 evidence) AND the cycle's `AUDITCYCLE:` is not `UNVERIFIED`, so the agent read files inside the root and did not merely answer. A surface **refuses** the root on anything else: a non-zero agent exit with no delivered report, a delivered report on an `UNVERIFIED` cycle, or agent output that rejects the working directory. A refusal by grok or agy is a smoke failure with reason `nongit_root_refused:<agent>`. A codex refusal is published, and FR-3 then runs the codex-unavailable shape (`--passes 2 --surfaces agy,grok`) with the codex ceiling published as not run. **No surface ever falls back to a git work tree or a worktree root.** A refusal halts or drops that surface. It never re-runs the cycle in a root where git history is reachable.
  - AC-1.7: The smoke ends on one line in the measurement doc: `SMOKE: PASS` or `SMOKE: FAIL reason=<r>[,<r>…]`. It is derived from the passes' `AUDITCYCLE:` and `COLLECT:` lines and their logs, never typed by hand, and the design names the component that derives it. `reason=` lists every failing check, in this order:
    - `truncated`: the grok log is `grok-truncated` (AC-1.1).
    - `vocab_split`: `_GROK_TYPES_RE` and `_GROK_TYPES` differ from each other at the smoke sha (AC-1.2).
    - `vocab_missing:<type>`: `end`, `tool_call` or `tool_call_update` is absent from the live log, one reason per missing type (AC-1.2).
    - `no_delivery`: the AC-1.3 evidence is absent for the grok pass.
    - `nongit_root_refused:<agent>`, where `<agent>` is `grok` or `agy` (AC-1.6).

    There is no other reason value. An out-of-vocabulary type is published, and it is not a reason (AC-1.2).

    **Exit contract**, in the same style as AC-5.1: the component prints its token on stdout, and callers read the token, never `$?`. `SMOKE: PASS` and `SMOKE: FAIL reason=…` are both verdicts, and both exit 0. A non-zero exit is reserved for an operational error, where the inputs could not be read. In that case the component exits 2 and prints `SMOKE: UNREADABLE reason=<r>`. That token carries neither PASS nor FAIL, and `<r>` is exactly one of two values:
    - `input_missing:<path>`: a pass log, or a pass's `AUDITCYCLE:` or `COLLECT:` line, that the derivation needs is absent.
    - `input_unparseable:<path>`: such an input is present, but it cannot be parsed.

    There is no other UNREADABLE reason. An UNREADABLE smoke is not a smoke failure, and it is never written to the measurement doc as `SMOKE: FAIL`. S2 does not start, and nothing in "Delivery by outcome" ships on its account. The operator restores the input and derives again from the same passes. If the passes themselves are lost, the operator runs a new smoke, which is a new reading. Each of the two UNREADABLE reasons, `PASS`, and each `FAIL` reason gets its own fixture test, run with that trigger alone.
  - AC-1.8: **What ships when the smoke fails.** S2 does not start. No calibration runs, no findings are labelled, and no `SEEDSCORE:` line exists. What ships:
    - The measurement doc `docs/03-analysis/grok-audit-surface.measurement.md`, holding the `SMOKE: FAIL` line, the AC-1.2 vocabulary table, the AC-1.4 `RESOLVED-MODEL` line and wall time, and the AC-1.6 acceptance outcome per surface. It cites the calibration ref and the full calibration sha the smoke's export root was built from (AC-2.7), and there is no score sha. It holds no recall or fabrication figure, and it says so.
    - `h-mad/references/grok-runtime.md` §"Version and compatibility" gains one sentence: the audit path re-smoke against grok 1.0.62 failed, with the `reason=` values, naming the measurement doc. The AC-1.5 "re-smoked" sentence does **not** ship, and the 1.0.41 sentence stays unchanged.
    - In `h-mad/SKILL.md`, both AC-6.2 sites keep audit precision in grok's **unmeasured** list. Each gains the measurement-doc pointer and one clause saying that the 1.0.62 audit-path smoke failed. D3's "'Unmeasured' is retired either way" ranges over the three scored verdicts (PASS, MISS, INCONCLUSIVE), and on a smoke failure there is nothing to retire it with.
    - The AC-6.2 correction of the teammate-section command, and AC-9.5, ship as on every other branch (see "Delivery by outcome").
    - The codex-unavailable route itself (`--surfaces agy,grok`) is not changed by this feature (Out-of-Scope). Whether to stop routing to grok after a failed audit-path smoke is a follow-up, and the measurement doc records it as one.

### FR-2: The seeded-defect set
- **Description**: Build the ground truth: N = **27** planted build-class defects across **9** seeded documents, 3 seeds per document. Each document is a copy of one archived, already-audited phase document, and each seed has a label.
- **Source documents (Q2 decision)**: the plan, design and impl-plan of these three archived features, giving 3 × 3 = 9 documents:
  - `docs/archive/2026-09/audit-report-docs-copy/` (small: about 20–37 KB per document; collected legs `codex` + `p1` on all three phases)
  - `docs/archive/2026-09/tdd-gate-fail-opens/` (medium: about 88–109 KB; legs `p1`, `p2`, `agy`)
  - `docs/archive/2026-10/agy-coder-fallback/` (larger: about 92–152 KB; legs `agy`, `p1`, `p2`)

  *Why these three:* each one was gated by at least two collected legs, so its unseeded body has already survived audit, which keeps unplanted findings down. Each has a complete paired set (spec, plan, design), which the assembler requires. Their largest assembled prompt is the agy-coder-fallback design with its paired spec and plan (the assembler pairs a design with the spec and plan, and an impl-plan with the design only; see Premises). Its documents come to 317,110 bytes, under a third of the 1,048,576-char exec ceiling. The bytes are an upper bound on chars, and the archived files are frozen. *Excluded:* `doc-block-exec`, whose documents are around 5,000 lines and whose prompts sit near the ceiling (the brainstorm's reason for deferring corpus replay). Also excluded are features with no paired spec in the archive, because the assembler cannot build their prompts.
- **Why N = 27**: one dispatch per (document, surface) keeps the cost at 9 grok + 9 agy (+ 9 codex) dispatches. 27 seeds give each surface a recall denominator in which a gap of one seed (about 3.7 points) can be published as a count, and four seed classes each appear at least 6 times. A per-phase split (9 seeds per phase) is published for observation only, and no decision reads it (see FR-7).
- **Acceptance Criteria**:
  - AC-2.1: Seed classes. The rule for a seed is that it must be `class: build` under the audit template's test, meaning a 5d/5e implementer's code or tests would differ if the defect were fixed. There are four classes:
    - **C1 contract-token**: a verdict token, reason value, exit code or CLI flag in a contract is changed so that it contradicts the paired spec or another statement of the same contract.
    - **C2 dead-reference**: a `path:symbol`, function or flag the document names is renamed to one that does not exist in the calibration tree.
    - **C3 dropped-failure-mode**: one enumerated failure mode of a contract (an error token, a cannot-judge branch, a refusal) is deleted, so the contract no longer states it.
    - **C4 unsatisfiable-requirement**: an AC is changed so that no implementation can satisfy both it and another AC or enumeration in the same document. This is the 88-vs-94 shape from SKILL.md §"Document-audit round cap".

    The residual is any defect class outside these four, for example measurement-class, prose or ordering defects. None of these is seeded, and the measurement doc says so.
  - AC-2.2: Class distribution. Number the documents 1 to 9 in the order the source list above gives them (feature order, then plan, design, impl-plan). Document k omits class `((k−1) mod 4) + 1` and carries one seed of each of the other three. That yields C1 = 6, C2 = 7, C3 = 7, C4 = 7, which sums to 27. The probe derives these counts from the ledger, never carries them, and refuses a ledger whose counts differ.
  - AC-2.3: Placement. Each seed sits in a distinct `##`/`###` section of its document and outside `## Version History`. No seed lives in the paired documents, which are byte-identical copies of the archive. Each seed's seeded span is unique within its document.
  - AC-2.4: The ledger is committed only on the calibration branch (AC-2.7), under `docs/03-analysis/probes/grok-audit-surface/calibration/` in that branch's tree, as one JSON record per seed with these fields: `id`, `source` (archive path), `phase`, `class` (C1–C4), `origin` (one of the eight `ORIGINS` in `h_mad_audit_origins.py`, naming the real must-fix shape the seed imitates), `section` (heading text), `original` (verbatim pre-seed span), `seeded` (verbatim post-seed span), and `expected` (the finding a correct auditor files, in one sentence). The probe refuses an `origin` outside `ORIGINS`.
  - AC-2.5: The seeded documents are the archive copies with the ledger's edits applied. The probe re-derives every seeded document from `source` + ledger and fails if the result differs from the seeded copy committed on the calibration branch (AC-2.7) by even one byte.
  - AC-2.6: Leak control (operator decision 2026-10-18; replaces the v1.1 worktree rule). The axis is: **any route by which a reviewer with tools, working from the dispatch root, can recover a seed's `original` span or its `expected` finding.** It has three routes, and each one is closed:
    - **(a) This feature's own answer key**: the ledger, the findings, labels and key (the AC-2.7 calibration data, which sits under the excluded probes directory in the calibration branch's tree), and this feature's spec, plan, design, impl-plan and measurement doc.
    - **(b) Git history**: any object store from which `git show <sha>:<archived path>` recovers an original.
    - **(c) Verbatim copies**: `docs/03-analysis/agy-coder-fallback.authoring/`, which quotes the seeded feature's documents, and any other file that copies a seed's original text, named or not.

    The rule over the axis has four parts.
    - **Export root.** Every dispatch (FR-1 and FR-3) runs in a **non-git export root**: a plain directory built from the calibration sha's tree (the AC-2.7 commit on `calibration/grok-audit-surface`; `git archive <sha>` or an equivalent tree export), one root per seeded document. It has no `.git` entry at any depth, and it shares no object store. It is placed outside every git work tree, so no ancestor repository is reachable. It is never a `git worktree`, a clone, or a checkout.
    - **Declared exclusions.** The root builder removes a committed, declared exclusion list before placing any document. The list holds at least each source feature's `docs/archive/*/<feature>/` directory, `docs/03-analysis/probes/grok-audit-surface/`, every path anywhere in the tree whose final component begins with `grok-audit-surface` (this covers `grok-audit-surface-brainstorm.md` as well as the `grok-audit-surface.<phase>.md` files and the measurement doc), and `docs/03-analysis/agy-coder-fallback.authoring/`. The list is published in the measurement doc. It then places the seeded target document, and only the paired documents the assembler reads for that target's phase (Premises), at their live paths.
    - **Content scan, the class closer.** Before any dispatch, the probe reads every regular file in the root, decodes it as UTF-8 with replacement, and collapses every whitespace run to one space. It refuses with `leak:<path>` when a file contains any seed's `original` span or any seed's `expected` sentence, normalised the same way. The scan covers all 27 seeds in every root, not only the target's seeds. There is exactly **one exemption**: a seed's `original` inside the paired copy of that seed's own source document. The design root's paired plan and the impl-plan root's paired design must carry the plan's and the design's seed originals, because AC-2.3 requires them to be byte-identical to the archive. The exemption applies only to a file whose sha256 equals the archived source's, and it never covers `expected`. A hit on the seeded target itself is a `leak:<path>` as well, and it means the seed's `original` span must be widened until it no longer occurs in the seeded document. A scan hit is answered by adding the path to the declared exclusion list or by re-choosing the seed's span, never by an automatic exclusion. Any symlink in the root is a `leak:<path>`, whatever its target. 0 are tracked today (Premises), and the rule does not depend on that zero.
    - **Git reach check.** Before any dispatch, the probe refuses with `root_git:<path>` if the root holds a `.git` entry (file or directory) at any depth, or if `git -C <root> rev-parse --git-dir` succeeds, in which case the path names the repository it found. Every S1 and S2 dispatch command unsets `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`, and the measurement doc records each dispatch command verbatim.

    **Residuals, stated exactly.**
    - (1) A paraphrase, or a copy shorter than the whole span, of a seed's original. The scan matches whole normalised spans only.
    - (2) Content that is not UTF-8 text in its stored form: compressed, base64-encoded or binary files.
    - (3) Reads outside the root by absolute path, such as the operator's own checkout or another clone on the same machine. Neither the root nor the scan closes this route, the agents' sandboxes are not measured to prevent it, and the measurement doc names it.
    - (4) Name mentions of a source feature that carry no seed text. These are not a leak, because they recover nothing.
    - (5) Submodule paths, which `git archive` exports empty. A C2 seed must not name a path under the three submodule entries.
  - AC-2.7: **Where calibration data lives** (operator decision 2026-10-18, answering plan audit cycle 2). *Calibration data* means five artifacts: the ledger (AC-2.4), the seeded copies (AC-2.5), the findings file and the id-to-surface key (AC-4.2), and the labels (AC-4.3). Any other file that carries a seed's `seeded` span or `expected` sentence also counts as calibration data and follows the same rule.
    - **The branch.** Calibration data is committed only on the dedicated branch `calibration/grok-audit-surface`, pushed to origin as `refs/heads/calibration/grok-audit-surface`, under `docs/03-analysis/probes/grok-audit-surface/calibration/` in that branch's tree. The branch starts from a `main` commit that already holds the S0 probe. It is never merged into `main` or into any branch that is merged into `main`. It is never rebased, force-pushed or deleted, and archiving this feature on `main` leaves it alone. A later calibration adds commits to it and never rewrites earlier ones.
    - **What `main` holds.** `main` holds the FR-5 probe, its AC-5.5 fixture tests and the FR-6 measurement doc, and no calibration data. Every fixture is synthetic, made of invented text, and never a copy or excerpt of a real seed, ledger record, finding, key or label. The measurement doc cites the calibration data by ref and sha and never quotes it.
    - **Two shas.** The *calibration sha* is the branch commit that holds the ledger and the seeded copies. Every AC-2.6 export root is built from it before any dispatch, the FR-1 smoke included. The *score sha* is the later branch commit that adds the findings file, the key and the labels. The score sha must descend from the calibration sha and differ from it only under `docs/03-analysis/probes/grok-audit-surface/calibration/`, so an export root rebuilt from either sha is the same root. The probe refuses with `calibration_drift:<path>` when a path outside that directory differs, naming the first such path in sorted order, and with `calibration_drift:not_descendant` when the score sha does not descend from the calibration sha. A smoke failure (AC-1.8) produces no score sha.
    - **Main leak check.** The probe scans every blob in the tree of the commit checked out where it runs (`HEAD`, read through `git ls-tree -r`, never the work tree). The commit it scanned is printed and recorded in the measurement doc. It refuses with `main_leak:<path>` on any one of three triggers: (i) the blob's sha256 equals that of a calibration data file at the score sha, or at the calibration sha when there is no score sha; (ii) after AC-2.6 whitespace normalisation, the blob contains any seed's `expected` sentence; (iii) the blob contains any seed's normalised `seeded` span, unless that span also occurs in the normalised archived source document of the same seed. Residuals, stated exactly: (1) a `seeded` span that also occurs in its own archived source, which (iii) cannot tell apart from archive text; (2) a partial copy of a calibration data file that carries no whole `seeded` span and no whole `expected` sentence; (3) content that is not UTF-8 text in its stored form, as in AC-2.6 residual (2); (4) uncommitted files in the work tree and commits other than the scanned one; (5) calibration objects fetched into a local clone's object store, which are not in `main`'s tree and which the non-git export roots cannot reach (AC-2.6 route (b)).
    - **Ref failure modes.** The probe reaches calibration data only through the ref. It refuses with `calibration_ref:<kind>`, and `<kind>` takes exactly one of four values:
      - `fetch_failed`: `git ls-remote` or the fetch of `refs/heads/calibration/grok-audit-surface` from origin did not complete (network, authentication, or no `origin` remote).
      - `ref_absent`: origin answered, but it has no such ref.
      - `sha_unknown:<sha>`: after the fetch, a cited sha does not resolve to a commit.
      - `not_on_ref:<sha>`: a cited sha is neither the fetched ref's tip nor an ancestor of it, which means the branch was rewritten.

      There is no other kind. On any of them, no reading is reproduced and the published reading stays unverified. The operator restores the ref, and never edits the measurement doc's shas to make them fit.

### FR-3: Calibration dispatch through the normal audit-cycle path
- **Description**: Each seeded document is audited once per surface, in one cycle, through `hmad-dispatch audit-cycle`. With codex available the call is `--passes 3 --surfaces codex,agy,grok`, which is the same shape as a production first gate. With codex unavailable it is `--passes 2 --surfaces agy,grok`. The project root is the seeded document's AC-2.6 export root, never a git work tree, and every NDJSON log is kept.
- **Acceptance Criteria**:
  - AC-3.1: Every assembly reads `ASSEMBLE: PASS`. Any other token halts the run for that document and is published, never skipped silently.
  - AC-3.2: The prompts are identical across surfaces. Within one cycle, the per-pass prompts may differ **only in lines that contain a per-pass report path**. The probe applies the wrapper's own `prompt_divergence` rule (Premises). Comparing pass 1 with each later pass, there must be at least one differing line, and every differing line must contain, as a fixed string, one of the two passes' report paths. An empty diff fails the cycle, and so does any other differing line. **Sentinel lines are not masked**: the wrapper passes no `--sentinel`, so every pass in one cycle carries the same `AUDIT-<feature>-<phase>-v<cycle>`, and a sentinel difference is a real divergence. Prompts are compared within one cycle only, because a re-dispatched cycle (AC-3.4) has a new cycle number and therefore a new sentinel.
  - AC-3.3: Every pass keeps its pass log, and the measurement doc records each log's `log_sha256` from the pass's `.effort.json` sidecar.
  - AC-3.4: Re-dispatch rule. A cycle whose `AUDITCYCLE:` is `UNVERIFIED` (any `reason=`) is re-dispatched once as a fresh cycle number. The second outcome stands. A pass whose report was never delivered (`no_report`, `unscorable_report`, or `delivered=none`) counts as zero findings, so its seeds are misses for that surface. A delivered report is scored even when its pass read `low_evidence`, and the measurement doc publishes per-surface delivery and evidence outcomes as counts.
  - AC-3.5: `--timeout` is the FR-1 derived value, given explicitly, and is the same for every pass.
  - AC-3.6: The calibration ref `refs/heads/calibration/grok-audit-surface`, the full 40-hex calibration sha and score sha (AC-2.7), the grok, agy and codex versions, and each surface's `RESOLVED-MODEL` line are recorded once in the measurement doc.

### FR-4: Finding classification and fabrication confirmation (Q3 decision)
- **Description**: Every must-fix is classified **by hand**, against the calibration tree and the assembled prompt, with the reviewer surface hidden from whoever labels it. Mechanical checks do two things only: they extract findings, and they propose candidates. They never decide a label. *Why:* `docs/03-analysis/hmad-audit-evidence-gate.measurement.md` measured the best automatic span rule catching 4 of 6 fabrications while killing 13 of 31 real must-fixes, and it found two fabrications that no occurrence check can see: one quotes nothing, and one paraphrases.
- **Acceptance Criteria**:
  - AC-4.1: Extraction uses the gate's own machinery (`h_mad_audit_gate.classify_detail`, or the same section walk). For every report, the probe asserts that its extracted must-fix count equals `classify(text)["must_count"]`. A mismatch makes the run `UNREADABLE`.
  - AC-4.2: Blinding. The probe writes every must-fix to a findings file under an opaque id that does not encode the surface, in a shuffled order, and writes the id-to-surface key to a separate file. The labeler works from the findings file alone. The findings file, the key and the labels are calibration data: they are committed only on the calibration branch, at the score sha (AC-2.7).
  - AC-4.3: Each must-fix gets exactly one label:
    - `HIT:<seed-id>`: the finding locates the seed's section, or quotes inside its `seeded` span, AND it states the seed's `expected` defect.
    - `REAL`: its premise holds against source, and it is not a seed.
    - `FABRICATED`: its premise fails against the calibration tree or the assembled prompt.
    - `UNDECIDABLE`: the labeler cannot settle it, and records one sentence saying why.

    Any other label value makes the run `UNREADABLE`.
  - AC-4.4: Candidate hints are advisory only. For a `quote:` line whose span is absent from the file it names, the probe may print a `candidate-fabrication` hint, and for a `quote:` span overlapping a seed's `seeded` span it may print a `candidate-hit:<seed-id>` hint. Hints are printed beside a finding and never written as labels. A test asserts that changing or removing every hint leaves the score unchanged.
  - AC-4.5: Counting rules. A seed hit by several findings from one surface counts once toward that surface's recall. One finding can hit at most one seed. Recall counts must-fixes only, because the gate is on must-fixes. Should-fix hits are published separately and never enter the bar.

### FR-5: The scorer probe
- **Description**: A committed, stdlib-only probe under `docs/03-analysis/probes/grok-audit-surface/` that builds the seeded documents, checks leak control, extracts and blinds findings, and computes the verdict from the ledger, the labels and the key. The probe lives on `main`; the data it scores lives only on the calibration branch (AC-2.7). It is tested in the suite.
- **Acceptance Criteria**:
  - AC-5.1: The probe ends on one token line: `SEEDSCORE: PASS|MISS|INCONCLUSIVE|UNREADABLE`, with `reason=` on every verdict other than PASS. It exits 0 on PASS, MISS or INCONCLUSIVE and 2 on UNREADABLE, and callers read the token, never `$?`.
  - AC-5.2: The fields per surface are `recall=<hits>/27`, `musts=<n>`, `fabricated=<f>`, `undecidable=<u>` and `fab_rate=<f>/<n−u>`, each written as an exact fraction. A surface with no decidable must-fix (`n − u = 0`) prints `fab_rate=0/0`, which compares as zero fabrications.
  - AC-5.3: Verdict rules are computed with exact rational comparison and no rounding. "D3 holds" means the amended D3 predicate is true: `(fab_grok < fab_agy AND recall_grok ≥ recall_agy) OR (fab_grok = fab_agy AND recall_grok > recall_agy)`. Equality of fabrication rates is equality of the reduced rationals (`0/0` compares as zero, AC-5.2), so `1/4` and `2/8` are equal. A full tie on both quantities makes the predicate false.
    - **PASS**: D3 holds when every one of grok's UNDECIDABLE is counted as fabricated and every one of agy's is counted as not fabricated.
    - **MISS**: D3 fails when the opposite worst case is taken (grok's undecidables counted as not fabricated, agy's as fabricated).
    - **INCONCLUSIVE**: covers every other case. That includes `reason=undecidable_flips` and `reason=seeds_undetected`. The second applies when no surface, codex included, hit any seed, which means the seeds measure nothing.
  - AC-5.4: UNREADABLE reasons, all fail-closed:
    - `ledger_counts` (AC-2.2)
    - `ledger_origin` (AC-2.4)
    - `seed_rebuild` (AC-2.5)
    - `leak:<path>` (AC-2.6 content scan or symlink)
    - `root_git:<path>` (AC-2.6 git reach check)
    - `must_count_mismatch:<report>` (AC-4.1)
    - `label:<id>` (an unknown label, an unlabeled finding, or a `HIT` naming an unknown seed)
    - `key_mismatch` (the findings ids and the key ids differ)
    - `calibration_drift:<path>` and `calibration_drift:not_descendant` (AC-2.7 two-sha rule)
    - `main_leak:<path>` (AC-2.7 main leak check)
    - `calibration_ref:<kind>`, where `<kind>` is `fetch_failed`, `ref_absent`, `sha_unknown:<sha>` or `not_on_ref:<sha>` (AC-2.7 ref failure modes)
  - AC-5.5: Every verdict and every UNREADABLE reason has a fixture test. Each branch of an alternation gets its own fixture, run with that branch alone. The D3 predicate's two branches and its tie boundary each get a fixture with no undecidables: fabrication strictly lower with recall equal gives `PASS`; fabrication equal with recall strictly greater gives `PASS`; fabrication equal with recall equal (the full tie) gives `MISS`; fabrication equal with recall lower gives `MISS`; and fabrication equal as unreduced fractions (for example `1/4` against `2/8`) with recall equal gives `MISS`. The AC-2.6 refusals get one fixture per trigger, each run with that trigger alone. For `leak:<path>`: an `original` hit, an `expected` hit, a hit only after whitespace normalisation (a re-wrapped copy), a symlink, an `original` in a paired copy whose sha256 differs from the archive (the exemption must not apply), and an `expected` in a byte-identical paired copy (the exemption never covers `expected`). One more fixture, with an `original` in a byte-identical paired copy of its own source, must NOT refuse. For `root_git:<path>`: a `.git` directory, a `.git` file, and a root nested inside a git work tree. The AC-2.7 refusals likewise get one fixture per trigger, run with that trigger alone. They are built in a temporary git repository with a local bare repository as its `origin`, so no fixture needs the network or the real ref. For `calibration_drift`: a score sha that differs outside the calibration directory, and a score sha that does not descend from the calibration sha. For `main_leak:<path>`: triggers (i), (ii) and (iii) each alone, plus one fixture where a `seeded` span also occurs in its own archived source, which must NOT refuse. For `calibration_ref`: one fixture for each of the four kinds. Every fixture is synthetic (AC-2.7). The tests live in the suite under `h-mad/tests/`, so the probe directory is kept at archive time (`h_mad_archive_feature.py` keeps a probes directory that live code reads).

It holds the `SEEDSCORE:` line, the per-surface fields, the codex reference ceiling, the observational per-phase and per-class split, the FR-1 smoke result, the stated residuals, and one re-run command. It sits on `main` and holds no calibration data.
- **Acceptance Criteria**:

  - AC-6.2a: **Correct the pre-existing command in §"Teammate audit leg — when codex is unavailable"** (operator decision 2026-10-18). ### FR-7: Routing change on PASS only (D1; Q5 decision)
- **Description**: The routing change happens only on `SEEDSCORE: PASS`, which is the amended D3 predicate holding under AC-5.3's worst case; a full tie scores `MISS` and does not route. On a pass, the first gating cycle of **every** phase document (plan, design and impl-plan) runs as ONE call, `hmad-dispatch audit-cycle --passes 3 --surfaces codex,agy,grok`, whenever codex and grok are both available. Revision cycles stay codex-gated with the doc-auditor ADVISORY delta review. The codex-unavailable route in §"Teammate audit leg" is unchanged.

  *Why all three phases, and not a subset:* the per-phase split carries 9 seeds, which is too small to separate surfaces, so a per-phase rule would be fitted to noise. The cost is one dispatch per document, paid once, because revisions are unchanged: about three extra dispatches per feature. Disjoint must sets between model families were the measured property behind the two-surface rule (SKILL.md §"Document-audit round cap"), and nothing in that measurement limits it to one phase.
- **Acceptance Criteria**:
  - AC-7.1: SKILL.md §"Never gate on one audit pass", at the bold "**Which two surfaces …**" paragraph, names `--surfaces codex,agy,grok` for the first gate with codex available and points to the measurement doc. The sentence ending "that is three reports, of which two share a model family" is reworded so that the prohibition is on two reports sharing a family, not on three reports. The teammate-full-pass-plus-codex case stays prohibited.
  - AC-7.2: Availability. If `command -v grok` fails, the first gate runs `--passes 2 --surfaces codex,agy`. The same applies when the grok pass is the `pN` named in an `UNVERIFIED reason=…:pN` on both the first run and its one re-dispatch: the cycle is then re-run as `codex,agy`. Either way the stamp records the legs that actually ran (wrapper default), so the record is the stamp. No new state field is added.
  - AC-7.3: Doc tests in the `test_grok_fallback_docs.py` style pin `--surfaces codex,agy,grok` in §"Never gate on one audit pass" and keep the existing `--surfaces agy,grok` pins.
  - AC-7.4: On MISS or INCONCLUSIVE, none of AC-7.1–7.3 ships. A test, or the measurement doc's verdict line, is the evidence the branch was taken, and §"Never gate on one audit pass" is byte-unchanged except for the FR-6 pointer, if one is placed there.

### FR-8: Union gate across three surfaces (Q4 decision)
- **Description**: Nothing changes in how the gate works. With three passes, the gate is the union of all three must-fix sets, and every grok must-fix is falsified against source before it is acted on, the same as any other leg. Promotion does not relax the evidence check on grok.
- **Acceptance Criteria**:
  - AC-8.1: A fixture three-pass cycle (codex, agy, grok) in which only the grok pass files a must-fix gives `AUDITCYCLE: FAIL`. The same cycle with all three passes clean gives `PASS`.

  - AC-8.3: The SKILL.md text at AC-7.1 says that grok must-fixes go through §"Verifying a review finding before acting on it", and that a rejected one is recorded per §"Record a rejected finding in the rejections ledger, never in a gated document". **PASS only**: this sentence is anchored at the AC-7.1 text, which exists only on PASS, so it ships with AC-7.1–7.3 and never on MISS, INCONCLUSIVE, UNREADABLE or a smoke failure.

### FR-9: Exit streak and round cap across leg sets (Q1 decision)
- **Description**: The rule is that **the exit streak counts only among consecutive cycles with an identical leg set**. A first gate stamped `agy+codex+grok` and revision cycles stamped `codex` are different sets, so the first gate never pairs with a revision. This is the same refusal class that `agy+codex → codex` already gets today (probed; see Premises). **No change to `exit_check` or `round_check`.** This feature does not change how a phase decides to exit, which remains SKILL.md §"Document-audit round cap". *Why no new rule:* the leg-set check exists so that a streak never spans two different questions (#11/H3). Exempting the first gate would reopen that case, and the probe shows the third leg adds nothing the two-leg first gate does not already trigger.
- **Acceptance Criteria**:
  - AC-9.1: A test with real-grammar stamps: v1 p1–p3 with legs `agy,codex,grok` and v2 p1 with legs `codex` gives `EXIT: BLOCKED reason=legs_changed:agy+codex+grok|codex`.
  - AC-9.2: v2 and v3 stamped `codex` give `EXIT: READY … legs=codex`.
  - AC-9.3: `--round-cap 2` over v1 p1–p3 plus v2 gives `ROUNDS: OK cap=2 cycles=2`. The three first-gate legs count as one cycle.
  - AC-9.4: Three v1 stamps on which one leg records `agy,codex` and the others `agy,codex,grok`, plus one v2 stamp with legs `codex`, give `EXIT: BLOCKED reason=legs_disagree:design.v1`. The v2 stamp is there because a single cycle on its own would give `not_two_cycles:1` before any legs are compared. This is why AC-7.1 requires the three first-gate legs to run as one wrapper call and not as separately collected legs.
  - AC-9.5: The SKILL.md bullet "**Name the reviewer legs with `--legs`…**" in §"What you NEVER do" gains one sentence: the first gate and the revisions run different leg sets by design, so the streak, when it is reached, is among revision cycles. **Unconditional, at S0**: the sentence is already true today (the first gate is `agy+codex` and revisions are `codex`, Premises), so it ships in every branch, including a smoke failure.

## Delivery by outcome
The outcome is read from token lines, never from `$?`: first the AC-1.7 `SMOKE:` line, then, only if it reads `SMOKE: PASS`, the AC-5.1 `SEEDSCORE:` line. Both components exit 0 on every verdict and 2 on UNREADABLE (AC-1.7, AC-5.1). Every outcome ships the unconditional S0 set to `main`: the FR-5 probe and its synthetic AC-5.5 fixtures, the AC-8.1/8.2, AC-9.1–9.4 and FR-10 tests, AC-9.5, and AC-6.2a. The FR-2 ledger and seeded copies exist on every outcome as well, because the FR-1 smoke's export root is built from them, but they go only to the calibration branch and never to `main` (AC-2.7).

| Outcome | Measurement doc | `grok-runtime.md` | SKILL.md unmeasured sites (AC-6.2) | Routing (AC-7.1–7.3) and AC-8.3 |
|---|---|---|---|---|
| `SMOKE: UNREADABLE` | not published until the smoke derives again to `PASS` or `FAIL` (AC-1.7) | not shipped | not shipped | not shipped |
| `SMOKE: FAIL` | smoke result only, no `SEEDSCORE:` (AC-1.8) | smoke-failure sentence (AC-1.8) | audit precision stays unmeasured; pointer plus failure clause | not shipped |
| `SEEDSCORE: PASS` | full (FR-6) | AC-1.5 sentence | retired to the measured fractions | shipped |
| `SEEDSCORE: MISS` | full (FR-6) | AC-1.5 sentence | retired to the measured fractions | not shipped (AC-7.4) |

## Non-Functional Requirements
- Performance: the calibration costs 9 grok + 9 agy dispatches, plus 9 codex when available, plus at most one re-dispatch per document (AC-3.4). The FR-1 smoke costs one grok and one agy dispatch, plus one codex dispatch when codex is available (AC-1.6). The FR-1 timeout bounds each pass. In production, one more dispatch per document first gate after a PASS (FR-7). Revisions cost the same as today.
- Security: audits run read-only in the AC-2.6 non-git export roots, which sit outside every git work tree. The export roots are never committed anywhere. All calibration data (the seeded copies, the ledger with its `original`, `seeded` and `expected` fields, the findings, the key and the labels) is committed only on `refs/heads/calibration/grok-audit-surface` and never merged into `main` (AC-2.7). The AC-2.7 main leak check enforces this, with its residuals stated there. The ledger and the labels hold no secrets.
- Compatibility: no change to `exit_check`, `round_check`, `combine`, `scan_grok` or the wrapper's `--surfaces` grammar. The codex-unavailable routing and the `fallback_agent` semantics are unchanged.

## Out-of-Scope
- grok as Phase-5 implementer, as doc author, or as the subject of a TDD write gate (D1).
- The host-mode adapter: hooks, `spawn_subagent`, the TDD gate, session id and the 1.0.41 mapping line (D4).
- Replacing the doc-auditor delta review or agy with grok (brainstorm, Alternatives).
- Replaying the gateway-consolidation corpus.
- Changing the codex-unavailable route, or adding a `grok_status` state field.
- Seeding measurement-class, prose or ordering defects (AC-2.1 residual).
- Preventing a reviewer from reading outside the export root by absolute path (AC-2.6 residual 3), and changing the codex-unavailable route after a failed smoke (AC-1.8 follow-up).
- Server-side protection of `refs/heads/calibration/grok-audit-surface` on origin. The spec states the failure mode instead (AC-2.7 `calibration_ref:<kind>`).

## Assumptions
- grok 1.0.62 and agy are on PATH at calibration time. codex is optional, and when it is absent the reference ceiling is published as not run.
- The audit template's `class:` and `quote:` contract is the one at the calibration sha, and every surface receives it identically (AC-3.2).
