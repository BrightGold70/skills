## Should-fix
- The `intersect:` offset definition is not generalised to the multi-span case the document's own lookahead enumeration creates, and the spec published that generalisation in the same batch. The impl-plan defines `offset` as the smallest index "the two spans" share, which is well defined only when one key pair yields exactly one intersecting span pair; under `re.finditer(r"(?=" + re.escape(k) + r")", text)` a key has several spans, so one unordered key pair can intersect at several offsets while the grammar emits one line per pair. I checked both siblings: the strings `several offsets` and `any intersecting` occur 0 times in the impl-plan and once in the design, in its Version History only, so the generalisation currently lives in no document body. Prescription: restate `offset` as the smallest index shared by any intersecting span pair of those two keys, and carry the spec's diagnostic-completeness residual beside it.
