# Plan: grok-audit-surface

## Executive Summary
Build and test a seeded-defect scorer that measures grok against agy on 27 planted build-class defects. An operator then runs a live smoke and, if it passes, the calibration. The result is published whatever the outcome. grok becomes a third leg on each document's first gating cycle only if the smoke prints `SMOKE: PASS` and the probe then prints `SEEDSCORE: PASS`. That token means the amended D3 predicate `(fab_grok < fab_agy AND recall_grok ≥ recall_agy) OR (fab_grok = fab_agy AND recall_grok > recall_agy)` held under the worst case. A full tie does not promote. The probe, its synthetic fixtures and the measurement doc live on `main`; every piece of calibration data lives only on the never-merged branch `calibration/grok-audit-surface` (spec AC-2.7).

**Containment comes first (spec v1.9–v1.13, FR-11).** On 2026-10-20 a grok S2 auditor ran `git checkout` against the operator's live checkout from inside its export root, and grok passes read the unseeded originals in the live checkout in 11 of the 12 recorded S2 cycles (incident record `docs/03-analysis/grok-audit-surface.incident-2026-10-20-grok-root-escape.md`; R16). That S2 run is incident evidence only and is never scored. Before any further grok dispatch against a seeded document, FR-11 ships green on `main`: grok runs `--sandbox strict` by default, roots and calibration files leave system temp, grok's prompt and temp files stay in its root, each pass of a cycle gets its own root (AC-3.8), every grok pass is scanned for out-of-root tool calls at cycle end (AC-6.6), and each run starts with a session-store quarantine (AC-11.7) and a fail-closed canary (AC-11.4). Then the S1 smoke is re-run (AC-1.9) and a fresh S2 of all nine documents is run as `v1` in a new run directory. The S4 routing never ships before FR-11, whatever the verdict.

## Overview
grok's audit precision is labelled **unmeasured** in two places in `h-mad/SKILL.md`, so a third independent model family sits idle on every normal run. This plan turns that label into a number. It does so through a committed probe and a committed measurement doc on `main`, and a pushed calibration branch that holds the data, all of which can be re-run after a grok upgrade. The routing change is gated on that number, not on the build of the instrument. The work therefore splits into an unconditional, CI-tested half (the instrument, pins on existing gate behaviour, and two SKILL.md text fixes that are true today) and a conditional half (the "unmeasured" text and the routing text), with operator-run steps between them: building and pushing the calibration branch, and the live dispatches. Every live dispatch runs in a non-git export root, so neither git history nor this feature's answer key is reachable through git from inside it. The spec's sentence on what that does not do is quoted verbatim: "The export root bounds what an auditor is shown. It does not bound what the auditor can read or where it can write." (AC-2.6 residual (3)). For grok, FR-11's `strict` profile is that bound; for codex and agy there is none that has been verified, and the AC-6.6 scan publishes what each of their passes named outside its root.

Added by spec v1.9–v1.13: FR-11 grok containment (AC-11.1–11.7: the `strict` default with a recorded override, calibration data out of system temp, grok's prompt and `TMPDIR` placed by working directory (in the root for an export root, under `<git toplevel>/.h-mad/` in a git work tree), the per-run canary, the published "not contained" residuals, their tests, and the session-store quarantine); one export root per pass (AC-3.8); the out-of-root tool-call scan with its cycle-end halt for grok (AC-6.6) and the probe's `out_of_root:<doc>.v<N>` refusal; the published containment record (AC-6.5); the S1 re-smoke under containment (AC-1.9); and a fresh S2 of all nine documents (FR-3, "Which S2 run is scored").
- **User-visible behaviour on PASS**: a document's first gating cycle with codex and grok both available runs `hmad-dispatch audit-cycle --passes 3 --surfaces codex,agy,grok`. Revision cycles stay codex-gated with the doc-auditor ADVISORY delta review.
- **User-visible behaviour on MISS or INCONCLUSIVE**: routing is unchanged. SKILL.md gains the measured fractions and a pointer to the measurement doc in place of "audit precision … unmeasured".
- **User-visible behaviour on a smoke failure**: routing is unchanged and no calibration runs. Audit precision stays in grok's unmeasured list at both SKILL.md sites, each gaining the measurement-doc pointer and a clause saying the audit-path smoke of the recorded grok version failed (AC-1.8).
- **User-visible behaviour on every outcome**: the §"Teammate audit leg — when codex is unavailable" command names `hmad-dispatch audit-cycle … --surfaces agy,grok` instead of a script that does not parse `--surfaces` (AC-6.2a). From FR-11, `hmad-dispatch exec grok` runs `--sandbox strict` for every caller, production included; a weaker `--sandbox` exits 2 unless `--allow-weaker-sandbox` is also given (design D16), and each launch writes a `GROK-PROFILE:` record. Where grok's prompt and `TMPDIR` go depends on the working directory. **In production** (a `--cd` inside a git work tree, or no `--cd`, which falls back to the git top level), both go under `<git toplevel>/.h-mad/`, never `<cd>/.tmp/` (spec v1.13 AC-11.3; design v1.7 stages under `<top level>/.h-mad/tmp/hmad_exec_grok.XXXXXX/` and removes it, so `git status` is unchanged). A `--cd` below the top level fails closed, because `strict` refuses a prompt file outside the working directory (spec v1.13 AC-11.3 residual). `.h-mad/` is ignored in this repository: `git check-ignore -v .h-mad/x` prints `.gitignore:34:.h-mad/*`. **In a calibration export root**, which is not a git work tree, both stay in `<root>/.tmp` (spec AC-11.3). The design states which production grok paths lose `report-file` delivery under `strict` (D16, "What reaches production").
- **User-visible behaviour on a containment halt (AC-6.6)**: the run stops dispatching, is not scored, and is recorded as an incident on `main`. Nothing in S3 or S4 ships on its account; FR-11 has already shipped.

## Goals
- Re-smoke the grok audit path in a non-git export root, measure whether grok, agy and codex accept that root, derive the calibration `--timeout` from measured wall time, and end on one derived `SMOKE:` line whose verdicts exit 0 and whose UNREADABLE exits 2 (FR-1). No phase document names a target grok version." Everywhere below, "the recorded grok version" means that recorded line.
- Build a ground truth: 27 seeds in 9 documents, four classes, with a ledger that the probe can rebuild byte for byte; close the leak axis with export roots, declared exclusions, a content scan and a git reach check; and keep every piece of calibration data off `main` on a pushed, never-merged branch cited by two full shas (FR-2).
- Dispatch every seeded document once per surface through the production wrapper, with identical prompts across surfaces as the wrapper itself decides them (FR-3).
- Label every must-fix and every should-fix finding by hand, blinded, and use mechanical hints only as advisories (FR-4). Should-fix labels are published separately and never enter the bar (AC-4.5); labelling them adds S2 labeller effort.
- Ship a stdlib-only scorer whose verdict is exact rational arithmetic over the amended D3 predicate, with one fixture per verdict, per UNREADABLE reason, per leak, git-reach, drift, main-leak and ref trigger, per predicate branch, and on the tie boundary (FR-5).
- Publish the reading on every outcome, retire "unmeasured" for audit precision on PASS, MISS and INCONCLUSIVE, and correct the teammate-section command unconditionally (FR-6).
- Ship the first-gate routing change on `SEEDSCORE: PASS` only (FR-7).
- Pin that the three-surface gate is the union, that the evidence floors hold at pass index 3 (FR-8), and that the exit streak and round cap behave across leg sets exactly as today (FR-9), each pin shown able to fail by a scoped mutant.
- Show end to end that `--passes 3 --surfaces codex,agy,grok` dispatches three distinct surfaces (FR-10), with the surface wiring mutated in both directions.
- Contain grok before it is dispatched against a seeded document again (FR-11): ship the `strict` default, the system-temp moves, in-root prompt staging, the canary and the quarantine with their AC-11.6 tests green; run every pass in its own root (AC-3.8); scan every grok pass at cycle end and halt the run on any out-of-root call outside the three exempt classes (AC-6.6); then re-smoke (AC-1.9) and run a fresh S2.

1. **Setup.** A **new run directory**, `$KEEP/run-<cal12>-<UTC timestamp>` (design D8), never `run-ab2c85dc2e25`. 2. **The codex last-message tracer, as a controlled pair** (design D16; orchestrator ruling 2026-10-20). Two otherwise identical `exec codex` dispatches run with a one-line prompt and `--cd` under `$RUN/roots`. In the **control**, the last-message file is in system temp. In the **treatment**, it sits beside a `--log` under `$RUN/work/`. Each passes when `exec` prints the reply and no `EMPTY final message` line, and both artifacts are inspected.

   | control | treatment | decision |
   |---|---|---|
   | pass | pass | codex runs; the re-smoke and S2 use the codex shape |
   | pass | fail | codex cannot write its last message outside system temp; the runs use the codex-unavailable shape, and the spec is told (spec AC-11.2's instruction) |
   | fail | fail | codex is unavailable (authentication, dispatch or model), with no causal attribution; the codex-unavailable shape |

The pair, its four outputs and its cell are recorded in the measurement doc.

3. **The first quarantine.** `h_mad_grok_containment.py quarantine`, its token read by `require --verb quarantine`, which must print `REQUIRE: OK` (the last line begins `QUARANTINE: VERIFIED moved=`).

**S2 in detail.** In the **same** new run directory, in order:
1. **The second quarantine.** `h_mad_grok_containment.py quarantine` again, read by `require --verb quarantine`, which must print `REQUIRE: OK`.
2. **FR-3.** All 9 documents on all surfaces, every document's first cycle numbered `v1`: `codex,agy,grok`, or `agy,grok` when codex is unavailable, refused the root at the re-smoke, or failed the tracer. Each pass gets its own fresh export root built from the calibration sha and passed as `audit-cycle --pass-root`, one per pass (AC-3.8, design D17). Each AC-3.4 re-dispatch is built the same way.
3. **The cycle-end scan and the halt** (design v1.8 D8, D17). `h_mad_tool_calls.py scan` runs on every grok pass once its cycle ends, writing its token to the cycle's scan file. The scan's exit code is never read. Two pieces gate on that token:
   - **The consumer.** Right after the scan, `h_mad_grok_containment.py require --verb toolscan --token-file <scan file> --halt-file "$RUN/HALT"` runs. On anything but `TOOLSCAN: CLEAN surface=grok` (another token, an empty file, an absent file), it appends that line or `no_token:<file>` to the halt file, then prints `REQUIRE: STOP`.
   - **The launch boundary.** Every cycle runs `audit-cycle --halt-file "$RUN/HALT"`. Immediately before launching its passes, it tests the halt file. If the file exists, it launches no pass and prints no `AUDITCYCLE:` line.

   The leading `[ -e "$RUN/HALT" ] && exit 1` in each cycle block is kept only as an early courtesy. A run that omits `--halt-file` or the consumer is still never scored, because the score refuses `out_of_root` (branch below).
4. **The positive control on the kept d5/v1 log** (design D8, D19). It runs after the S2 scans and before `extract`.

### One authority per wrapper verdict (AC-3.2, and the class it belongs to)
- **The authority for AC-3.2 is the wrapper, and the probe consumes its verdict.** `_cmd_audit_cycle` in `h-mad/scripts/hmad-dispatch.sh` diffs pass 1's prompt against each pass i ≥ 2 before any dispatch. When the diff is empty, or when any differing line contains neither pass's report path (a `grep -F` fixed-string match on `${report[1]}` and `${report[$i]}`), it calls `h_mad_audit_cycle.py --halt-reason prompt_divergence`, which prints `AUDITCYCLE: UNVERIFIED reason=prompt_divergence passes=<n> …` and no agent is dispatched. The plan adopts spec AC-3.2 (v1.5) verbatim: "**The wrapper is the single authority for this check** (single-source contract)" and "**The probe does not diff prompts and carries no report-path mask.** It decides AC-3.2 per cycle from that cycle's recorded `AUDITCYCLE:` line (AC-2.7) alone: a `reason=prompt_divergence` line fails the cycle, which is published and goes through AC-3.4, and a cycle that reached dispatch passed the wrapper's check. A cycle with no recorded `AUDITCYCLE:` line, or one that does not parse, is never read as passing (AC-5.4 `cycle_token:<cycle>`)." The wrapper's check is already discrimination-tested: R12.
- **A missing or unparseable token is UNREADABLE (AC-5.4 `cycle_token:<cycle>`).** The wrapper prints no `AUDITCYCLE:` line when it exits 4 on an assembly failure (the `exit 4` lines after `h_mad_assemble_audit.py` in `_cmd_audit_cycle`), and an operator can fail to record one. A cycle with no recorded line at the score sha, or whose recorded line does not parse as an `AUDITCYCLE:` token, makes the probe print `SEEDSCORE: UNREADABLE reason=cycle_token:<cycle>`, never PASS, and never reads it as AC-3.4 `UNVERIFIED`. Spec AC-5.4 (v1.12, unchanged at v1.13) names exactly eight triggers for `cycle_token:<cycle>`: these two, plus a first cycle `UNVERIFIED` with no second recorded, a second cycle recorded although the first is not `UNVERIFIED`, a third or later cycle, a recorded dispatch command whose `--surfaces` is neither FR-3 shape, a pass with `delivered=report-file` or `delivered=out` and no recorded collected report, and (8, added in spec v1.10 for AC-3.8) root records that do not give exactly one root per pass, or name one `path` twice or one inside another, or disagree on `calibration` or `list_blob`. (1)–(7) are the pre-v1.9 seven; the v1.9 void triggers are withdrawn. Its AC-5.5 fixtures are one per trigger, each run alone, with trigger (8) getting one fixture per shape (five) plus a must-not-refuse cycle whose passes each have their own identically built root. The count is R20.
- **AC-3.2 applies to S2 only.** The wrapper skips the diff at `--passes 1`, so the S1 smoke cycles carry no AC-3.2 reading, and the probe's smoke mode does not claim one.
- **The class.** The axis is *a verdict that the wrapper or the gate already computes and that the probe also needs*. The rule over it: the probe reads each such verdict from the token line the wrapper printed or by importing the authority's function, and re-derives none. Members today: AC-3.2 `prompt_divergence`; AC-3.1 `ASSEMBLE:` / `assemble_halt:pN`; AC-1.1 `format=grok` against `grok-truncated` in the cycle's `Effort:` block; AC-1.3 delivery (the `delivered=` field of the `AUDITCYCLE:` line, plus the `GATE:` token of the pass's collected report; the audit-cycle path prints no `COLLECT:` line); AC-1.6 and AC-3.4 `UNVERIFIED`; AC-4.1 `must_count` (imported `classify_detail`). The design enumerates the final list and names, per member, which token or function the probe reads.
- **Enforcement: one opposed-input fixture pair per token-read member.** For each member read from a token, one fixture whose raw inputs say one thing while the recorded token says the opposite, in each direction. For AC-3.2 the raw inputs of each fixture are ones on which the wrapper's own rule gives the verdict opposite to the recorded token. Direction 1, token says dispatched, prompts say halt: (a1) retained prompts that differ on a line containing neither pass's report path, and (a2) byte-identical retained prompts, each alone beside a recorded `AUDITCYCLE:` line that reached dispatch, where the probe must NOT fail AC-3.2. Direction 2, token says halt, prompts say clean: (b) retained prompts that differ only on lines containing one of the two passes' report paths, beside a recorded `AUDITCYCLE: UNVERIFIED reason=prompt_divergence`, where the probe MUST fail AC-3.2. A probe carrying a faithful copy of the wrapper's rule fails AC-3.2 on (a1) and (a2) and passes it on (b), so all three go red; a probe that reads prompts through a report-path mask only (treating an empty diff as clean) passes (a2) and still goes red on (a1) and (b). The wrapper's verdict on each raw shape is **recorded, not reproducible from this document**: the scratch probe that produced it was deleted, and no command here rebuilds it. It was observed, not reasoned: driving the real `_cmd_audit_cycle` at `--passes 2` through `install_audit_cycle_stubs` and `run_audit_cycle` from `h-mad/tests/test_hmad_dispatch_audit_cycle.py` at `2f7bf7ae` (cited as `611c299d` before the 2026-10-18 rebase; contents byte-identical), report-path-only differences printed `AUDITCYCLE: PASS … passes=2 …` with 2 dispatches, while byte-identical prompts and a foreign line (`HMAD_ASSEMBLE_DIVERGE_P2`) each printed `AUDITCYCLE: UNVERIFIED reason=prompt_divergence passes=2 size_status=verified` with 0 dispatches (scratch probe, deleted after the run). The reproducible evidence that the wrapper's rule is enforced is R12, the committed mutation row, and the impl-plan's (a1)/(a2)/(b) fixtures. Those fixtures run each authority on the raw inputs first. Imported members (AC-4.1) are covered by the import itself, plus the existing `must_count_mismatch:<report>` fixture.
- **Residual, stated exactly.** A second copy placed outside the probe, in a file the probe does not call, is not seen by the pairs. A copy inside the probe that is computed but never consulted is not seen either, because it moves no output. The rule binds the design and the impl-plan; the pairs are the only executed check.

### The `SMOKE:` component (AC-1.7)

Before that token it publishes its observation lines in design D11's order: the `VOCAB:` lines (sorted by distinct type), then `ROOT-ACCEPT:`, `TIMEOUT:` and `GROK-BINARY:`. The shipped interface is pinned by `test_smoke_pass` in `h-mad/tests/test_grok_audit_surface_smoke.py` ("published lines must follow the D11 order and end on the smoke token"). ### Calibration data and its two shas (AC-2.7)
- **What counts.** Spec v1.6 AC-2.7 names the set explicitly: the ledger and the seeded copies; the findings file, the key and the labels; and, for every S1 and S2 cycle, every pass's report (the agent's report file and the collected copy), every pass log, every kept prompt, every pass's captured agent output, and the cycle's captured wrapper stdout (`auditcycle.txt`). The wrapper stdout is calibration data, not only a token carrier: on a `PASS` or `FAIL` cycle `render` in `h-mad/scripts/h_mad_audit_cycle.py` prints a `Premise checklist:` with one line of finding text per must-fix and should-fix of every pass (`premise_items`), and those findings quote seeded spans. AC-2.7's catch-all still covers any other file carrying a seed's `seeded` span, its `expected` sentence, or the text of a finding filed on a seeded document. All of it goes only to the branch, under `docs/03-analysis/probes/grok-audit-surface/calibration/`, never to `main`. The recorded `AUDITCYCLE:` line of each cycle sits inside that cycle's `auditcycle.txt`, which AC-3.2 and AC-6.4 read from the score sha.
- **S0b, the calibration sha.** From the `main` commit that holds S0: `git switch -c calibration/grok-audit-surface <that main sha>`; author the ledger and the seeded copies under the calibration directory; commit; run the probe's ledger counts (AC-2.2), origin (AC-2.4) and rebuild (AC-2.5) checks and build every export root with its content scan and reach check. A refusal (`leak:<path>` and the rest) is answered by a **new branch commit** that widens or re-chooses a span, or by extending the declared exclusion list, which lives on `main` beside the probe (a new `main` commit, which becomes the list commit; see "Leak control", "Which list version"). It is never answered by an amend, a rebase or a force-push, because AC-2.7 forbids rewriting the branch. The calibration sha is the first branch commit on which every root reads clean. Then `git push -u origin calibration/grok-audit-surface`, and `git ls-remote origin refs/heads/calibration/grok-audit-surface` must print that sha in full; the full 40-hex sha is recorded for the measurement doc.
- **S1, the smoke commit.** The first smoke commit is `f7520e72c87e1c3c34e1c5f25fb3807343d84782`; it is superseded (spec AC-1.9) and its records stay byte-identical. The re-smoke's smoke commit is **a later branch commit** that adds the re-smoke's records beside them and never overwrites them (spec AC-1.9, AC-2.7). Its parent is **the calibration branch tip fetched and confirmed at that moment**, passed as `commit-data --parent <tip>`, not a hard-wired `f7520e72`. For the first run that tip happens to be `f7520e72`. A later run **appends**: its namespace is new, and its parent is whatever tip it found, which is the earlier run's last commit. `commit-data`'s `ref_moved:<oid>` guard refuses when the ref has moved between the fetch and the commit (design v1.10 D9, pinned by `test_commit_data_appends_a_second_reading_after_an_earlier_resmoke`). The commit goes up together with the run's canary record (prompt, log, `GROK-CANARY:` line, grok binary path and `--version` line), which carries no calibration data (AC-11.4). The probe's `calibration_drift` covers only files present at the calibration sha, so it does not enforce that the `f7520e72` records stay untouched; the design may add that check (spec v1.10 author report, judgement call 5). The design names the re-smoke's layout and how the smoke mode is pointed at it. On a smoke that derives to `PASS` or `FAIL`, that commit adds the S1 cycle records (each S1 cycle's calibration data, its `auditcycle.txt` with its `AUDITCYCLE:` line, and the record of the root it ran in, a per-cycle `root.txt` holding that root's one `ROOT: READY` line, which replaces the `roots.jsonl` of design v1.0; design D8) under the calibration directory, touching nothing outside it. Push, and confirm with the same `ls-remote`. On a smoke failure it is the branch tip and is cited (AC-1.8).
- **S2, the score sha.** The findings file, the key, the labels, and every FR-3 cycle's records (its `auditcycle.txt` with its recorded `AUDITCYCLE:` line, its dispatch command, its reports, logs, prompts and captured agent output, and one root record per pass, AC-3.8, at the per-pass path the design names) are committed on the branch under the run's reading namespace `calibration/runs/<run-id>/` (design v1.8 D8; spec v1.15), as one or more commits descending from the re-smoke's smoke commit that touch nothing outside it (AC-2.7 drift rule; the probe's `calibration_drift:<path>` and `calibration_drift:not_descendant` enforce it). Extraction runs before the score sha exists, so the design's `extract` reads two places: the exported tree of the smoke commit (`--base-sha <smoke commit>`) for the ledger, seeded copies and archive sources, and the kept S2 cycle records (`--s2 <dir>`) (design D12). Push, and confirm with the same `ls-remote` that the tip is the score sha.
- **S3, the main leak check before the measurement-doc commit.** On every outcome, the probe's `main-leak` mode runs before the measurement doc is committed to `main`: with `--calibration-sha` and `--smoke-sha`, plus `--score-sha` when a score sha exists, and without it on a smoke failure (design D9). A refusal blocks that commit; the leak is removed from `main` and the check runs again.
- **S3, the re-score.** The AC-6.4 command is the design's `rescore --repo . --calibration-sha <sha40> --smoke-sha <sha40> --score-sha <sha40> --run-id <run-id> --work-dir <dir>` (design v1.8 D2, D9, D15; spec v1.15 AC-6.4), run from a `main` checkout: it fetches the ref, checks both shas are on it, exports the score sha with `git archive` into a fresh directory outside every work tree and **outside system temp** (spec AC-6.4, AC-11.2; the export holds calibration data) and reads the ledger, seeded copies, findings, key, labels and recorded `AUDITCYCLE:` lines from there, runs the two-sha check and the main leak check over `HEAD`'s tree, compares the list blob at its own commit with every recorded root's list blob (`list_changed:<oid>`), rebuilds the roots from the calibration sha with that list, re-derives the AC-6.6 scan from every recorded pass log (`out_of_root:<doc>.v<N>`), re-scores, and removes the export directory. It never checks the ref out in `main`'s work tree and never uses a `git worktree`.
- **The shas the measurement doc must cite**: the ref `refs/heads/calibration/grok-audit-surface`; the full calibration sha; the full sha of the re-smoke's smoke commit (AC-2.7, AC-3.6), with `f7520e72` cited as superseded (AC-6.5); the full score sha (absent on a smoke failure, AC-1.8); the full sha of the `main` commit whose probe produced the score; the full sha of the list commit and that list's blob id (AC-3.6; see "Leak control", "Which list version"); and the commit the main leak check scanned, as the probe printed it.

Uncommitted files, other commits, and calibration objects fetched into a local clone's object store are outside it (AC-2.7 residuals (4) and (5)). Server-side protection of the ref is out of scope; its loss is the named `calibration_ref:<kind>` refusal.
- **The 2026-10-20 S2 run** (`run-ab2c85dc2e25/data/s2/` in the kept directory) is never committed under the calibration directory at a path the probe reads as an S2 cycle record. If it is preserved on the branch at all, the design names a path no probe mode reads as a cycle (spec FR-3).

### Discrimination for tests over unchanged code
- **The axis.** A test whose subject already exists cannot be seen RED by writing the test first: FR-8 (`combine`, the evidence floors), FR-9 (`exit_check`, `round_check`, `_leg_key`), FR-10 (`_cmd_audit_cycle`'s `--surfaces` mapping and stamping), and every pin that keeps an existing assertion (AC-6.2a's kept `test_teammate_section_documents_the_grok_leg`, AC-6.2's kept `unmeasured` term, AC-7.3's kept `--surfaces agy,grok` pins). Writing them first shows green on arrival and proves nothing.
- **The rule.** Each such test is shown to fail by a scoped mutant in a committed `h_mad_mutation_harness.py` spec under `h-mad/tests/mutation-specs/`. Every row names the one test it must turn red in its `test` key. The procedure per row is: baseline GREEN; the harness applies the mutant and the named test goes RED; the harness restores; GREEN again. The run is accepted only on `MUTATION: ALL_CAUGHT` with `untargeted=0/<n>` and `crash_kills=0`, read from the token line, never from `$?`; a crash kill is a mutant that broke an import, not the assertion, and measures nothing about the test. `--check-anchors` (the pre-push sweep) must print `ANCHORS: ANCHORS_OK` with the new spec included.
- **Connection tests mutate both directions.** A test that pins a wire gets two rows: one that removes the wire and one that forces it. For FR-10 that is (remove) pass i no longer takes its agent from `_surf[i-1]` in `_cmd_audit_cycle`'s `agent[$i]` assignment, which AC-10.1's "once each, in that pass order" assertion must catch; and (force) every pass takes one fixed surface, which AC-10.1 must catch and AC-10.2's "no `one surface repeated` line" must catch separately. For AC-10.2's stamp, (remove) the wrapper no longer defaults `--legs` from `_surf`, so the stamp records no legs, and (force) it defaults `--legs` to one fixed list; a third, single-site row drops the sort in `_leg_key` (`h_mad_audit_gate.py`), which the `["agy","codex","grok"]` order must catch. For AC-9.4, (remove) `exit_check`'s per-cycle legs comparison never refuses, and (force) it always refuses with `legs_disagree:<phase>.v<N>`, whatever the leg sets. "Treats every leg set as equal" is not a force row: in `exit_check` it is the same mutant as the remove row (the `if len(distinct) > 1:` refusal never fires). The design names each row's find string and the test that catches it.
- **Single-site pins get one row.** FR-8 union (AC-8.1): `combine` drops the must-fixes of one pass index. Floors at index 3 (AC-8.2): the floor loop stops before the last pass. FR-9 AC-9.1–9.3: `legs_changed` not raised; a v1 three-leg cycle counted as three cycles. AC-10.3: the passes/surfaces count check removed. Kept doc pins: delete the pinned substring from SKILL.md.
- **New code keeps ordinary TDD.** The probe's own guards (each AC-1.7 and AC-5.4 refusal) are written RED first against an absent behaviour; Phase 5e then adds them to the same spec as rows, one per guard, so that a later edit that disarms one is caught.
- **Residual, stated exactly.** A mutant shows the named test can fail on that one change; a property the test asserts that no row disturbs stays unshown. The harness's anchors check catches a row that no longer lands; it does not catch a row that lands somewhere harmless.
- **Interpreter constraint (R13).** Most committed specs name a bare `python3.11` first in `command`, so a spec's baseline depends on what that name resolves to on the machine that runs it. On this machine it now resolves to `/opt/anaconda3/bin/python3.11`, which has pytest; v1.3's "absent" was a PATH condition of that shell, not a property of the machine. Where the name does not resolve, or resolves to an interpreter without pytest, the spec cannot reach a GREEN baseline (`MUTATION: BASELINE_NOT_GREEN`). The design pins the interpreter the new spec names and where Phase 5e runs it.

### Leak control (AC-2.6): what the plan carries
Spec v1.2 settles the axis and the rule, so this section stages it and names the constraints it puts on the work. The axis: **any route by which a reviewer with tools, working from the dispatch root, can recover a seed's `original` span or its `expected` finding**, through (a) this feature's own answer key, (b) git history, or (c) verbatim copies, named or not.

- **Order of operations per root.** Export the calibration sha's tree (the S0b commit on `calibration/grok-audit-surface`) into a fresh directory outside every git work tree (never a `git worktree`, clone or checkout) and outside system temp, under the run directory's `roots/` (spec AC-2.6, AC-11.2). There is one root per pass: each pass of an S2 cycle gets its own, all built identically for the cycle's seeded document (AC-3.8). Remove every path on the declared exclusion list. Its required contents are spec AC-2.6's, quoted: "The list holds at least each source feature's `docs/archive/*/<feature>/` directory, `docs/03-analysis/probes/grok-audit-surface/`, every path anywhere in the tree whose final component begins with `grok-audit-surface` (this covers `grok-audit-surface-brainstorm.md` as well as the `grok-audit-surface.<phase>.md` files and the measurement doc), and `docs/03-analysis/agy-coder-fallback.authoring/`." The probes entry covers the calibration directory under it. Place the seeded target and only the paired documents the assembler reads for its phase. Run the content scan and the git reach check. Only on a clean result, dispatch with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` unset, recording the command verbatim. Every S1 and S2 root goes through the same order, and records the list blob id it was built with (AC-3.6). The probe's check refuses with `leak:<path>` or `root_git:<path>`, which are AC-5.4 UNREADABLE reasons and carry AC-5.5 fixtures at S0.
- **Which list version.** The list lives on `main` beside the probe. Every root build consumes the list as committed at one `main` commit, the *list commit*: the `main` commit whose list the root builds that fixed the calibration sha read. S0b may move the list commit, by a new `main` commit that extends the list, only until the calibration sha is fixed. After that, S1, S2 and the AC-6.4 re-score consume the list at the list commit and no other version. Every export root records the list blob id it was built with, and that record goes to the branch with the cycle that ran in the root, as the cycle's `root.txt` (AC-3.6; design D5). The re-score runs from the `main` commit named in the measurement doc (AC-6.4) and compares the list blob at its own commit with every recorded root's list blob; a difference, or a root record that is absent or names no list blob, refuses `SEEDSCORE: UNREADABLE reason=list_changed:<oid>`. Spec v1.14 AC-5.4 gives `unrecorded` two triggers, (a) an absent root record and (b) a malformed one. Design v1.8 added a third, which spec v1.15 adopts: (c) the reading's run record `s2/run.txt` is absent, or does not yield exactly one parseable `RUN:` line with exactly the keys `checkout` and `home`. That makes three triggers (spec v1.15). The reason-form count stays sixteen, because (c) is a trigger, not a form (design v1.8 D2). So the check is a probe refusal with its own AC-5.5 fixtures, not an operator step. The list path is pinned by the design. The measurement doc cites the full list commit sha and the list blob id.
- **The scan has no "excluding the seeded target" carve-out.** Every regular file in the root is scanned, the seeded target included, for all 27 seeds' `original` and `expected`, after decoding as UTF-8 with replacement and collapsing whitespace runs. The single exemption is narrow: a seed's `original` may appear only inside the paired copy of **that seed's own source document**, and only when that file's sha256 equals the archived source's. `expected` is never exempt. A hit on the seeded target means the seed's `original` span must be widened until it no longer occurs there.
- **Which roots need the exemption.** The assembler pairs a plan with the spec, a design with the spec and plan, and an impl-plan with the design only (R2 command; read in `assemble`'s `slots[...]` block). So the 3 design roots carry the archive plan (which holds the plan seeds' originals), and the 3 impl-plan roots carry the archive design (which holds the design seeds' originals). 6 of the 9 roots are buildable only with the exemption. The 3 plan roots need none.
- **A constraint on seed choice the scan enforces.** The paired spec in every plan and design root is not seeded and is not anyone's own source, so the exemption never covers it. A plan or design seed whose `original` span also occurs verbatim in that feature's spec gives `leak:<spec path>`. The answer is to re-choose or widen the span, never an automatic exclusion. The same holds for any other tree file that quotes a source document (R6 shows the scale for the one directory the spec already excludes). These hits surface at S0b, when the roots are first built from the calibration branch.
- **What the git reach check proves about placement.** It refuses a root holding a `.git` entry at any depth, and a root inside a work tree (`git -C <root> rev-parse --git-dir` succeeds). The design pins the root's parent directory. Whatever it pins, the check, not the choice, is the evidence.
- **Residuals carried as spec-stated**: paraphrase or partial copies; non-UTF-8 stored forms; reads and writes outside the root by absolute path (AC-2.6 residual (3), quoted: "The export root bounds what an auditor is shown. It does not bound what the auditor can read or where it can write." For grok it is bounded by `strict` and checked by the canary and the AC-6.6 scan; for codex and agy it is UNVERIFIED and published per surface, AC-11.5); name mentions with no seed text (R4 counts those mentions and is not a leak); submodule paths, which `git archive` exports empty, so a C2 seed must not name a path under the three gitlink entries (R11).

## Architecture Considerations
- **One wrapper call per first gate (AC-9.4).** The three first-gate legs must run as one `audit-cycle --passes 3` call so that every stamp in the cycle records the same leg set. Separately collected legs can disagree within a cycle, which gives `legs_disagree:<phase>.v<N>`. Stamps are written through `_leg_key` in `h_mad_audit_gate.py` (sorted and deduped), so a `codex,agy,grok` surfaces list stamps `["agy","codex","grok"]`, as AC-10.2 expects.
- **"In that pass order" means pass index, not wall-clock order (AC-10.1).** `_cmd_audit_cycle` launches every pass in the background (`&`) and then waits on each one. The test asserts the pass-i → agent mapping and the per-pass report path. It does not assert invocation time order, which is nondeterministic.
- **The scorer is a pure function of two trees.** It takes the `main` probe and the exclusion list at the list commit ("Leak control"), and the score sha's tree (ledger, seeded copies, reports, findings, labels, key, recorded `AUDITCYCLE:` lines) together with the archive sources, and returns one token line. That makes AC-6.4's re-run possible with no dispatch (it rebuilds the export roots from the calibration sha and re-runs their scan and reach check), and it makes every verdict testable from synthetic fixtures.
- **Exact rationals.** Fabrication rates compare as reduced fractions (`fractions.Fraction`), and `0/0` compares as zero (AC-5.2). The worst-case bounds of AC-5.3 are two predicate evaluations: grok's undecidables counted as fabricated against agy's counted as not fabricated, and the reverse.
- **Blinding is procedural, and it has a residual.** Opaque ids and a shuffled order hide the surface label. They do not hide each model's writing style, so the labeller may still be able to infer the surface. The measurement doc names this residual. The labeller is a fresh context that holds the findings file and the export roots, and not the key.
- **Calibration uses the production path, as FR-11 changes it for every caller, in a non-git root.** From S0c, production `exec grok` and calibration `exec grok` are the same code under the same `strict` default; the calibration runbook adds only the run-directory placement, the quarantine, the canary and the scan. Seeded documents sit at the assembler's live paths in each export root (`docs/01-plan/features/`, `docs/02-design/features/`, under the source feature's name), with byte-identical paired copies. That works only because the tree has no live copy of any source feature's phase documents (R3), so nothing collides. The wrapper's own root handling is already git-optional on the code side: `_cmd_exec` passes codex `--skip-git-repo-check`, passes grok `--cwd`, and prints `tree delta: n/a (… not a git repo)` for a non-git root. Whether each agent actually accepts the root is the AC-1.6 measurement at S1, not a premise, and under `strict` it is re-measured by the AC-1.9 re-smoke.
