# Plan: grok-audit-surface

## Executive Summary
Build and test a seeded-defect scorer that measures grok against agy on 27 planted build-class defects. An operator then runs a live smoke and, if it passes, the calibration. The result is published whatever the outcome. grok becomes a third leg on each document's first gating cycle only if the smoke prints `SMOKE: PASS` and the probe then prints `SEEDSCORE: PASS`. That token means the amended D3 predicate `(fab_grok < fab_agy AND recall_grok ≥ recall_agy) OR (fab_grok = fab_agy AND recall_grok > recall_agy)` held under the worst case. A full tie does not promote. The probe, its synthetic fixtures and the measurement doc live on `main`; every piece of calibration data lives only on the never-merged branch `calibration/grok-audit-surface` (spec AC-2.7).

## Overview
grok's audit precision is labelled **unmeasured** in two places in `h-mad/SKILL.md`, so a third independent model family sits idle on every normal run. This plan turns that label into a number. It does so through a committed probe and a committed measurement doc on `main`, and a pushed calibration branch that holds the data, all of which can be re-run after a grok upgrade. The routing change is gated on that number, not on the build of the instrument. The work therefore splits into an unconditional, CI-tested half (the instrument, pins on existing gate behaviour, and two SKILL.md text fixes that are true today) and a conditional half (the "unmeasured" text and the routing text), with operator-run steps between them: building and pushing the calibration branch, and the live dispatches. Every live dispatch runs in a non-git export root, so neither git history nor this feature's answer key is reachable from it.

## Scope
- **In**: the audit path of grok 1.0.62 (`exec grok` audit leg, NDJSON vocabulary, `scan_grok`, report delivery); non-git root acceptance by grok, agy and (when available) codex; the `SMOKE:` derivation with its exit contract; the seeded-defect ledger and seeded copies of 9 archived documents, committed only on the calibration branch; the export-root builder with its declared exclusion list, content scan and git reach check; the AC-2.7 two-sha, main-leak and ref checks; the scorer probe and its synthetic suite tests; the mutation-spec rows that show each test over unchanged code can fail; calibration dispatches through `hmad-dispatch audit-cycle`; blinded hand labelling; the measurement doc; the SKILL.md "unmeasured" text at both sites (every outcome except an UNREADABLE one); the AC-6.2a teammate-section command correction (every outcome); the first-gate routing text (PASS branch only); tests that pin existing three-pass union, evidence floors, and exit/round behaviour across leg sets.
- **User-visible behaviour on PASS**: a document's first gating cycle with codex and grok both available runs `hmad-dispatch audit-cycle --passes 3 --surfaces codex,agy,grok`. Revision cycles stay codex-gated with the doc-auditor ADVISORY delta review.
- **User-visible behaviour on MISS or INCONCLUSIVE**: routing is unchanged. SKILL.md gains the measured fractions and a pointer to the measurement doc in place of "audit precision … unmeasured".
- **User-visible behaviour on a smoke failure**: routing is unchanged and no calibration runs. Audit precision stays in grok's unmeasured list at both SKILL.md sites, each gaining the measurement-doc pointer and a clause saying the 1.0.62 audit-path smoke failed (AC-1.8).
- **User-visible behaviour on every outcome**: the §"Teammate audit leg — when codex is unavailable" command names `hmad-dispatch audit-cycle … --surfaces agy,grok` instead of a script that does not parse `--surfaces` (AC-6.2a).

## Goals
- Re-smoke the grok 1.0.62 audit path in a non-git export root, measure whether grok, agy and codex accept that root, derive the calibration `--timeout` from measured wall time, and end on one derived `SMOKE:` line whose verdicts exit 0 and whose UNREADABLE exits 2 (FR-1).
- Build a ground truth: 27 seeds in 9 documents, four classes, with a ledger that the probe can rebuild byte for byte; close the leak axis with export roots, declared exclusions, a content scan and a git reach check; and keep every piece of calibration data off `main` on a pushed, never-merged branch cited by two full shas (FR-2).
- Dispatch every seeded document once per surface through the production wrapper, with identical prompts across surfaces as the wrapper itself decides them (FR-3).
- Label every must-fix by hand, blinded, and use mechanical hints only as advisories (FR-4).
- Ship a stdlib-only scorer whose verdict is exact rational arithmetic over the amended D3 predicate, with one fixture per verdict, per UNREADABLE reason, per leak, git-reach, drift, main-leak and ref trigger, per predicate branch, and on the tie boundary (FR-5).
- Publish the reading on every outcome, retire "unmeasured" for audit precision on PASS, MISS and INCONCLUSIVE, and correct the teammate-section command unconditionally (FR-6).
- Ship the first-gate routing change on `SEEDSCORE: PASS` only (FR-7).
- Pin that the three-surface gate is the union, that the evidence floors hold at pass index 3 (FR-8), and that the exit streak and round cap behave across leg sets exactly as today (FR-9), each pin shown able to fail by a scoped mutant.
- Show end to end that `--passes 3 --surfaces codex,agy,grok` dispatches three distinct surfaces (FR-10), with the surface wiring mutated in both directions.

**The live dispatches in S1 and S2, and the branch work in S0b and S2, are operator-run steps. They are not CI tests.** No suite test dispatches grok, agy or codex for real, and no suite test reads the real calibration ref. The suite tests the probe against synthetic fixtures (S0), including the AC-6.4 re-run path against a temporary repository whose `origin` is a local bare repository holding invented content. A test that needed a live agent would go red on any machine without grok and would bill a dispatch on every run. A test that needed the real ref would go red offline and would put calibration data inside the suite's reach.

**The outcome branch** is read from token lines, never from `$?`: first the AC-1.7 `SMOKE:` line, then, only if it reads `SMOKE: PASS`, the AC-5.1 `SEEDSCORE:` line. Both components exit 0 on every verdict and 2 on UNREADABLE (AC-1.7, AC-5.1). Every branch also carries the unconditional S0 set, which includes AC-9.5 and AC-6.2a. This follows the spec's "Delivery by outcome" table, which is the authority; the plan does not restate its cells beyond what staging needs.

- **`SMOKE: UNREADABLE reason=input_missing:<path>|input_unparseable:<path>` → nothing ships on its account.** It is not a smoke failure and is never written as `SMOKE: FAIL`. S2 does not start. The operator restores the input and derives again from the same passes; if the passes are lost, a new smoke is a new reading.
- **`SMOKE: FAIL reason=<r>[,<r>…]` → the smoke result ships, and nothing is scored.** S2 does not start, no findings are labelled, and no `SEEDSCORE:` line or score sha exists (AC-1.8). S3 ships the measurement doc holding the `SMOKE: FAIL` line, the AC-1.2 vocabulary table, the AC-1.4 `RESOLVED-MODEL` line and wall time, and the AC-1.6 per-surface acceptance outcome, citing the ref, the calibration sha, the smoke commit that holds the S1 records, and the list commit and list blob the root was built with, and saying it holds no recall or fabrication figure. The main leak check runs against the smoke commit's calibration data (AC-2.7). It also ships the `grok-runtime.md` smoke-failure sentence (the AC-1.5 "re-smoked" sentence is withheld; the 1.0.41 sentence stays unchanged). At both AC-6.2 SKILL.md sites, audit precision **stays unmeasured**, and each site gains the measurement-doc pointer and the smoke-failure clause. S4 does not run, and none of AC-7.1–7.3 or AC-8.3 ships. A smoke failure is not retried as a pass. Any new smoke is a new reading at a new sha. The reason set is closed: `truncated`, `vocab_split`, `vocab_missing:<type>`, `no_delivery`, `nongit_root_refused:<agent>` with `<agent>` grok or agy. A codex refusal is not a smoke failure. It is published, and S2 runs the codex-unavailable shape with the codex ceiling published as not run. No surface ever falls back to a git work tree or a worktree root.
- **`SEEDSCORE: PASS` → routing ships.** S3 ships the AC-1.5 sentence and the AC-6.2 retirement to the measured fractions. S4 ships AC-7.1 (SKILL.md §"Never gate on one audit pass", the "**Which two surfaces …**" paragraph, names `--surfaces codex,agy,grok` and rewords the "three reports, of which two share a model family" sentence), AC-7.2 (availability fallback to `codex,agy`), AC-7.3 (doc-test pins), and AC-8.3 (the grok-must-fix falsification sentence at the AC-7.1 site).
- **`SEEDSCORE: MISS` or `INCONCLUSIVE` → numbers are published and routing is unchanged.** S3 ships as on PASS; INCONCLUSIVE additionally carries its `reason=` into the SKILL.md text (AC-6.3). None of AC-7.1–7.3 or AC-8.3 ships (AC-7.4). §"Never gate on one audit pass" stays byte-unchanged except for the FR-6 pointer, if one is placed there. The evidence that this branch was taken is the measurement doc's `SEEDSCORE:` line, plus a section-scoped diff of §"Never gate on one audit pass" against the S0 base that shows no other change. The design pins whether a test asserts this.
- **`SEEDSCORE: UNREADABLE` → nothing in S3 or S4 ships.** The cause (`ledger_counts`, `ledger_origin`, `seed_rebuild`, `leak:<path>`, `root_git:<path>`, `must_count_mismatch:<report>`, `label:<id>`, `key_mismatch`, `calibration_drift:<path>`, `calibration_drift:not_descendant`, `main_leak:<path>`, `calibration_ref:<kind>`, `cycle_token:<cycle>`, `list_changed:<oid>`, `internal:<ExceptionName>`) is fixed, and the probe is re-run until it prints a non-UNREADABLE token. A `calibration_ref:<kind>` is fixed by restoring the ref, never by editing the measurement doc's shas.

AC-8.3 is PASS-only and AC-9.5 is unconditional at S0; spec v1.2 states both stagings with reasons. AC-6.2a is unconditional at S0 for the same reason as AC-9.5: the corrected command is true today, whatever the measurement says.

### Where the tests live (AC-5.5, settled here)
- **Directory**: every scorer test lives in the suite under `h-mad/tests/`, never next to the probe. The probe directory is not collected, and a test there would be a second, untested harness.
- **Archive survival is a constraint on the test's source text.** `h_mad_archive_feature.py` `probe_readers` keeps a probes directory only when a tracked non-markdown file outside it spells `docs/03-analysis/probes/grok-audit-surface` followed by a path boundary (`/`, `"`, `'`, whitespace or end of line). So the scorer test file must name the probe through that literal string, for example `ROOT / "docs/03-analysis/probes/grok-audit-surface"`. A path assembled from parts (`"docs" / "03-analysis" / …`) is invisible to `probe_readers`, so the directory would be archived and the test would break at Phase 7. Archiving acts on `main` only and leaves the calibration branch alone (AC-2.7).
- **The probe file is not named `test_*.py`** and imports only the stdlib plus `h_mad_audit_gate` / `h_mad_audit_origins` / `h_mad_review_evidence` from `h-mad/scripts/` (AC-4.1 reuses `classify_detail`, AC-2.4 reuses `ORIGINS`, and AC-1.2 reads `_GROK_TYPES`). `_GROK_TYPES_RE` is read from the text of `hmad-dispatch.sh`, never copied.
- **Every fixture is synthetic** (AC-2.7): invented text, never a copy or excerpt of a real seed, ledger record, finding, key or label. The AC-2.7 fixtures build a temporary git repository with a local bare repository as its `origin`, so none needs the network or the real ref.
- **The design pins**: the scorer test module's file name; the AC-6.2a doc-test module; whether the FR-8, FR-9 and FR-10 tests extend the existing `test_h_mad_audit_cycle_grok.py`, `test_h_mad_audit_gate.py` and `test_hmad_dispatch_audit_cycle_grok.py` or go in new modules; and the fixture layout per AC-1.7 and AC-5.5 branch, including the leak, git-reach, drift, main-leak and ref triggers (each run with that trigger alone) and the must-not-refuse fixtures.

### One authority per wrapper verdict (AC-3.2, and the class it belongs to)
- **The authority for AC-3.2 is the wrapper, and the probe consumes its verdict.** `_cmd_audit_cycle` in `h-mad/scripts/hmad-dispatch.sh` diffs pass 1's prompt against each pass i ≥ 2 before any dispatch. When the diff is empty, or when any differing line contains neither pass's report path (a `grep -F` fixed-string match on `${report[1]}` and `${report[$i]}`), it calls `h_mad_audit_cycle.py --halt-reason prompt_divergence`, which prints `AUDITCYCLE: UNVERIFIED reason=prompt_divergence passes=<n> …` and no agent is dispatched. The plan adopts spec AC-3.2 (v1.5) verbatim: "**The wrapper is the single authority for this check** (single-source contract)" and "**The probe does not diff prompts and carries no report-path mask.** It decides AC-3.2 per cycle from that cycle's recorded `AUDITCYCLE:` line (AC-2.7) alone: a `reason=prompt_divergence` line fails the cycle, which is published and goes through AC-3.4, and a cycle that reached dispatch passed the wrapper's check. A cycle with no recorded `AUDITCYCLE:` line, or one that does not parse, is never read as passing (AC-5.4 `cycle_token:<cycle>`)." The wrapper's check is already discrimination-tested: R12.
- **A missing or unparseable token is UNREADABLE (AC-5.4 `cycle_token:<cycle>`).** The wrapper prints no `AUDITCYCLE:` line when it exits 4 on an assembly failure (the `exit 4` lines after `h_mad_assemble_audit.py` in `_cmd_audit_cycle`), and an operator can fail to record one. A cycle with no recorded line at the score sha, or whose recorded line does not parse as an `AUDITCYCLE:` token, makes the probe print `SEEDSCORE: UNREADABLE reason=cycle_token:<cycle>`, never PASS, and never reads it as AC-3.4 `UNVERIFIED`. Spec v1.6 AC-5.4 names seven triggers for `cycle_token:<cycle>`: these two, plus a first cycle `UNVERIFIED` with no second recorded, a second cycle recorded although the first is not `UNVERIFIED`, a third or later cycle, a recorded dispatch command whose `--surfaces` is neither FR-3 shape, and a pass with `delivered=report-file` or `delivered=out` and no recorded collected report. Its AC-5.5 fixtures are one per trigger, each run alone.
- **AC-3.2 applies to S2 only.** The wrapper skips the diff at `--passes 1`, so the S1 smoke cycles carry no AC-3.2 reading, and the probe's smoke mode does not claim one.
- **The class.** The axis is *a verdict that the wrapper or the gate already computes and that the probe also needs*. The rule over it: the probe reads each such verdict from the token line the wrapper printed or by importing the authority's function, and re-derives none. Members today: AC-3.2 `prompt_divergence`; AC-3.1 `ASSEMBLE:` / `assemble_halt:pN`; AC-1.1 `format=grok` against `grok-truncated` in the cycle's `Effort:` block; AC-1.3 delivery (the `delivered=` field of the `AUDITCYCLE:` line, plus the `GATE:` token of the pass's collected report; the audit-cycle path prints no `COLLECT:` line); AC-1.6 and AC-3.4 `UNVERIFIED`; AC-4.1 `must_count` (imported `classify_detail`). The design enumerates the final list and names, per member, which token or function the probe reads.
- **Enforcement: one opposed-input fixture pair per token-read member.** For each member read from a token, one fixture whose raw inputs say one thing while the recorded token says the opposite, in each direction. For AC-3.2 the raw inputs of each fixture are ones on which the wrapper's own rule gives the verdict opposite to the recorded token. Direction 1, token says dispatched, prompts say halt: (a1) retained prompts that differ on a line containing neither pass's report path, and (a2) byte-identical retained prompts, each alone beside a recorded `AUDITCYCLE:` line that reached dispatch, where the probe must NOT fail AC-3.2. Direction 2, token says halt, prompts say clean: (b) retained prompts that differ only on lines containing one of the two passes' report paths, beside a recorded `AUDITCYCLE: UNVERIFIED reason=prompt_divergence`, where the probe MUST fail AC-3.2. A probe carrying a faithful copy of the wrapper's rule fails AC-3.2 on (a1) and (a2) and passes it on (b), so all three go red; a probe that reads prompts through a report-path mask only (treating an empty diff as clean) passes (a2) and still goes red on (a1) and (b). The wrapper's verdict on each raw shape was observed, not reasoned: driving the real `_cmd_audit_cycle` at `--passes 2` through `install_audit_cycle_stubs` and `run_audit_cycle` from `h-mad/tests/test_hmad_dispatch_audit_cycle.py` at `2f7bf7ae` (cited as `611c299d` before the 2026-10-18 rebase; contents byte-identical), report-path-only differences printed `AUDITCYCLE: PASS … passes=2 …` with 2 dispatches, while byte-identical prompts and a foreign line (`HMAD_ASSEMBLE_DIVERGE_P2`) each printed `AUDITCYCLE: UNVERIFIED reason=prompt_divergence passes=2 size_status=verified` with 0 dispatches (scratch probe, deleted after the run). Imported members (AC-4.1) are covered by the import itself, plus the existing `must_count_mismatch:<report>` fixture.
- **Residual, stated exactly.** A second copy placed outside the probe, in a file the probe does not call, is not seen by the pairs. A copy inside the probe that is computed but never consulted is not seen either, because it moves no output. The rule binds the design and the impl-plan; the pairs are the only executed check.
- **The design pins**: how prompts are retained (the wrapper writes them under `HMAD_AUDIT_STEM_DIR`, default `/tmp`, and does not delete them, so S2 points that variable at a kept calibration directory outside every export root; the FR-4 labeller reads them); where each cycle's `AUDITCYCLE:` and `Effort:` lines and each pass's collected report are recorded for the probe; and the per-member fixture pairs.

### The `SMOKE:` component (AC-1.7)
- **The component is the FR-5 probe's smoke mode**, on `main`, stdlib-only like the rest of the probe. It reads each S1 cycle's recorded `AUDITCYCLE:` line (its verdict word, its `delivered=` field and its `Effort:` block), the `GATE:` token of each delivered pass's collected report (AC-1.3), and the pass logs, never a `COLLECT:` line, which the audit-cycle path does not print (spec AC-1.7 v1.6). It reads the two vocabularies from their sources (`_GROK_TYPES` by import, `_GROK_TYPES_RE` from the shell file's text), and prints exactly one line on stdout: `SMOKE: PASS`, `SMOKE: FAIL reason=<r>[,<r>…]` with reasons in the AC-1.7 order, or `SMOKE: UNREADABLE reason=<r>`. Root acceptance (AC-1.6) is read from tokens per "One authority per wrapper verdict".
- **Exit contract**: 0 on `SMOKE: PASS`, 0 on `SMOKE: FAIL`, 2 on `SMOKE: UNREADABLE` with `<r>` exactly `input_missing:<path>` or `input_unparseable:<path>`. Callers read the token, never `$?`. The measurement doc copies the printed line; nobody types it.
- **Fixtures**, each run with its trigger alone: `PASS`; `truncated`; `vocab_split`; `vocab_missing:end`, `vocab_missing:tool_call` and `vocab_missing:tool_call_update` as three separate fixtures (one per alternative); `no_delivery`; `nongit_root_refused:grok`; `nongit_root_refused:agy`; `input_missing:<path>`; `input_unparseable:<path>`. Two more must NOT fail the smoke: a codex refusal (published, not a reason) and an out-of-vocabulary type (published, not a reason). One more drives two reasons at once and asserts their AC-1.7 order. Each exit code is asserted beside its token.
- **The design pins**: how the vocabulary sources are injected so `vocab_split` can be driven from a fixture; the smoke mode's command line; and whether `truncated` and `vocab_missing:end` read separate observations (the first is the `Effort:` shape, which `scan_grok`'s `complete` decides; the second is the log's type set), so that a fixture can drive each alone.

### Calibration data and its two shas (AC-2.7)
- **What counts.** Spec v1.6 AC-2.7 names the set explicitly: the ledger and the seeded copies; the findings file, the key and the labels; and, for every S1 and S2 cycle, every pass's report (the agent's report file and the collected copy), every pass log, every kept prompt, every pass's captured agent output, and the cycle's captured wrapper stdout (`auditcycle.txt`). The wrapper stdout is calibration data, not only a token carrier: on a `PASS` or `FAIL` cycle `render` in `h-mad/scripts/h_mad_audit_cycle.py` prints a `Premise checklist:` with one line of finding text per must-fix and should-fix of every pass (`premise_items`), and those findings quote seeded spans. AC-2.7's catch-all still covers any other file carrying a seed's `seeded` span, its `expected` sentence, or the text of a finding filed on a seeded document. All of it goes only to the branch, under `docs/03-analysis/probes/grok-audit-surface/calibration/`, never to `main`. The recorded `AUDITCYCLE:` line of each cycle sits inside that cycle's `auditcycle.txt`, which AC-3.2 and AC-6.4 read from the score sha.
- **S0b, the calibration sha.** From the `main` commit that holds S0: `git switch -c calibration/grok-audit-surface <that main sha>`; author the ledger and the seeded copies under the calibration directory; commit; run the probe's ledger counts (AC-2.2), origin (AC-2.4) and rebuild (AC-2.5) checks and build every export root with its content scan and reach check. A refusal (`leak:<path>` and the rest) is answered by a **new branch commit** that widens or re-chooses a span, or by extending the declared exclusion list, which lives on `main` beside the probe (a new `main` commit, which becomes the list commit; see "Leak control", "Which list version"). It is never answered by an amend, a rebase or a force-push, because AC-2.7 forbids rewriting the branch. The calibration sha is the first branch commit on which every root reads clean. Then `git push -u origin calibration/grok-audit-surface`, and `git ls-remote origin refs/heads/calibration/grok-audit-surface` must print that sha in full; the full 40-hex sha is recorded for the measurement doc.
- **S1, the smoke commit.** On a smoke that derives to `PASS` or `FAIL`, the next branch commit after the calibration sha adds the S1 cycle records (each S1 cycle's calibration data, its `auditcycle.txt` with its `AUDITCYCLE:` line, and the record of the root it ran in) under the calibration directory, touching nothing outside it. Push, and confirm with the same `ls-remote`. On a smoke failure it is the branch tip and is cited (AC-1.8).
- **S2, the score sha.** The findings file, the key, the labels, and every FR-3 cycle's records (its `auditcycle.txt` with its recorded `AUDITCYCLE:` line, its dispatch command, its reports, logs, prompts and captured agent output, and its root record) are committed on the branch under the calibration directory, as one or more commits descending from the smoke commit that touch nothing outside it (AC-2.7 drift rule; the probe's `calibration_drift:<path>` and `calibration_drift:not_descendant` enforce it). Push, and confirm with the same `ls-remote` that the tip is the score sha.
- **S3, the re-score.** The AC-6.4 command runs from a `main` checkout: it fetches the ref, checks both shas are on it, exports the score sha with `git archive` into a fresh temporary directory outside every work tree and reads the ledger, seeded copies, findings, key, labels and recorded `AUDITCYCLE:` lines from there, runs the two-sha check and the main leak check over `HEAD`'s tree, compares the list blob at its own commit with every recorded root's list blob (`list_changed:<oid>`), rebuilds the roots from the calibration sha with that list, re-scores, and removes the temporary directory. It never checks the ref out in `main`'s work tree and never uses a `git worktree`.
- **The shas the measurement doc must cite**: the ref `refs/heads/calibration/grok-audit-surface`; the full calibration sha; the full smoke commit sha (AC-2.7, AC-3.6); the full score sha (absent on a smoke failure, AC-1.8); the full sha of the `main` commit whose probe produced the score; the full sha of the list commit and that list's blob id (AC-3.6; see "Leak control", "Which list version"); and the commit the main leak check scanned, as the probe printed it.
- **Residual.** The main leak check scans one commit's tree. Uncommitted files, other commits, and calibration objects fetched into a local clone's object store are outside it (AC-2.7 residuals (4) and (5)). Server-side protection of the ref is out of scope; its loss is the named `calibration_ref:<kind>` refusal.
- **The design pins**: the probe's mode names and command lines; how the fetch distinguishes `fetch_failed` from `ref_absent` (`git ls-remote` against the fetch); the ancestry check; and the calibration directory's file layout.

### Discrimination for tests over unchanged code
- **The axis.** A test whose subject already exists cannot be seen RED by writing the test first: FR-8 (`combine`, the evidence floors), FR-9 (`exit_check`, `round_check`, `_leg_key`), FR-10 (`_cmd_audit_cycle`'s `--surfaces` mapping and stamping), and every pin that keeps an existing assertion (AC-6.2a's kept `test_teammate_section_documents_the_grok_leg`, AC-6.2's kept `unmeasured` term, AC-7.3's kept `--surfaces agy,grok` pins). Writing them first shows green on arrival and proves nothing.
- **The rule.** Each such test is shown to fail by a scoped mutant in a committed `h_mad_mutation_harness.py` spec under `h-mad/tests/mutation-specs/`. Every row names the one test it must turn red in its `test` key. The procedure per row is: baseline GREEN; the harness applies the mutant and the named test goes RED; the harness restores; GREEN again. The run is accepted only on `MUTATION: ALL_CAUGHT` with `untargeted=0/<n>` and `crash_kills=0`, read from the token line, never from `$?`; a crash kill is a mutant that broke an import, not the assertion, and measures nothing about the test. `--check-anchors` (the pre-push sweep) must print `ANCHORS: ANCHORS_OK` with the new spec included.
- **Connection tests mutate both directions.** A test that pins a wire gets two rows: one that removes the wire and one that forces it. For FR-10 that is (remove) pass i no longer takes its agent from `_surf[i-1]` in `_cmd_audit_cycle`'s `agent[$i]` assignment, which AC-10.1's "once each, in that pass order" assertion must catch; and (force) every pass takes one fixed surface, which AC-10.1 must catch and AC-10.2's "no `one surface repeated` line" must catch separately. For AC-10.2's stamp, (remove) the wrapper no longer defaults `--legs` from `_surf`, so the stamp records no legs, and (force) it defaults `--legs` to one fixed list; a third, single-site row drops the sort in `_leg_key` (`h_mad_audit_gate.py`), which the `["agy","codex","grok"]` order must catch. For AC-9.4, (remove) `exit_check`'s per-cycle legs comparison never refuses, and (force) it always refuses with `legs_disagree:<phase>.v<N>`, whatever the leg sets. "Treats every leg set as equal" is not a force row: in `exit_check` it is the same mutant as the remove row (the `if len(distinct) > 1:` refusal never fires). The design names each row's find string and the test that catches it.
- **Single-site pins get one row.** FR-8 union (AC-8.1): `combine` drops the must-fixes of one pass index. Floors at index 3 (AC-8.2): the floor loop stops before the last pass. FR-9 AC-9.1–9.3: `legs_changed` not raised; a v1 three-leg cycle counted as three cycles. AC-10.3: the passes/surfaces count check removed. Kept doc pins: delete the pinned substring from SKILL.md.
- **New code keeps ordinary TDD.** The probe's own guards (each AC-1.7 and AC-5.4 refusal) are written RED first against an absent behaviour; Phase 5e then adds them to the same spec as rows, one per guard, so that a later edit that disarms one is caught.
- **Residual, stated exactly.** A mutant shows the named test can fail on that one change; a property the test asserts that no row disturbs stays unshown. The harness's anchors check catches a row that no longer lands; it does not catch a row that lands somewhere harmless.
- **Interpreter constraint (R13).** Most committed specs name a bare `python3.11` first in `command`, so a spec's baseline depends on what that name resolves to on the machine that runs it. On this machine it now resolves to `/opt/anaconda3/bin/python3.11`, which has pytest; v1.3's "absent" was a PATH condition of that shell, not a property of the machine. Where the name does not resolve, or resolves to an interpreter without pytest, the spec cannot reach a GREEN baseline (`MUTATION: BASELINE_NOT_GREEN`). The design pins the interpreter the new spec names and where Phase 5e runs it.

### Leak control (AC-2.6): what the plan carries
Spec v1.2 settles the axis and the rule, so this section stages it and names the constraints it puts on the work. The axis: **any route by which a reviewer with tools, working from the dispatch root, can recover a seed's `original` span or its `expected` finding**, through (a) this feature's own answer key, (b) git history, or (c) verbatim copies, named or not.

- **Order of operations per root.** Export the calibration sha's tree (the S0b commit on `calibration/grok-audit-surface`) into a fresh directory outside every git work tree (never a `git worktree`, clone or checkout). Remove every path on the declared exclusion list. Its required contents are spec AC-2.6's, quoted: "The list holds at least each source feature's `docs/archive/*/<feature>/` directory, `docs/03-analysis/probes/grok-audit-surface/`, every path anywhere in the tree whose final component begins with `grok-audit-surface` (this covers `grok-audit-surface-brainstorm.md` as well as the `grok-audit-surface.<phase>.md` files and the measurement doc), and `docs/03-analysis/agy-coder-fallback.authoring/`." The probes entry covers the calibration directory under it. Place the seeded target and only the paired documents the assembler reads for its phase. Run the content scan and the git reach check. Only on a clean result, dispatch with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` unset, recording the command verbatim. Every S1 and S2 root goes through the same order, and records the list blob id it was built with (AC-3.6). The probe's check refuses with `leak:<path>` or `root_git:<path>`, which are AC-5.4 UNREADABLE reasons and carry AC-5.5 fixtures at S0.
- **Which list version.** The list lives on `main` beside the probe. Every root build consumes the list as committed at one `main` commit, the *list commit*: the `main` commit whose list the root builds that fixed the calibration sha read. S0b may move the list commit, by a new `main` commit that extends the list, only until the calibration sha is fixed. After that, S1, S2 and the AC-6.4 re-score consume the list at the list commit and no other version. Every export root records the list blob id it was built with, and that record goes to the branch with the cycle that ran in the root (AC-3.6). The re-score runs from the `main` commit named in the measurement doc (AC-6.4) and compares the list blob at its own commit with every recorded root's list blob; a difference, or a root record that is absent or names no list blob, refuses `SEEDSCORE: UNREADABLE reason=list_changed:<oid>` (spec v1.6 AC-5.4), so the check is a probe refusal with its own AC-5.5 fixtures, not an operator step. The list path is pinned by the design. The measurement doc cites the full list commit sha and the list blob id.
- **The scan has no "excluding the seeded target" carve-out.** Every regular file in the root is scanned, the seeded target included, for all 27 seeds' `original` and `expected`, after decoding as UTF-8 with replacement and collapsing whitespace runs. The single exemption is narrow: a seed's `original` may appear only inside the paired copy of **that seed's own source document**, and only when that file's sha256 equals the archived source's. `expected` is never exempt. A hit on the seeded target means the seed's `original` span must be widened until it no longer occurs there.
- **Which roots need the exemption.** The assembler pairs a plan with the spec, a design with the spec and plan, and an impl-plan with the design only (R2 command; read in `assemble`'s `slots[...]` block). So the 3 design roots carry the archive plan (which holds the plan seeds' originals), and the 3 impl-plan roots carry the archive design (which holds the design seeds' originals). 6 of the 9 roots are buildable only with the exemption. The 3 plan roots need none.
- **A constraint on seed choice the scan enforces.** The paired spec in every plan and design root is not seeded and is not anyone's own source, so the exemption never covers it. A plan or design seed whose `original` span also occurs verbatim in that feature's spec gives `leak:<spec path>`. The answer is to re-choose or widen the span, never an automatic exclusion. The same holds for any other tree file that quotes a source document (R6 shows the scale for the one directory the spec already excludes). These hits surface at S0b, when the roots are first built from the calibration branch.
- **What the git reach check proves about placement.** It refuses a root holding a `.git` entry at any depth, and a root inside a work tree (`git -C <root> rev-parse --git-dir` succeeds). The design pins the root's parent directory. Whatever it pins, the check, not the choice, is the evidence.
- **Residuals carried as spec-stated**: paraphrase or partial copies; non-UTF-8 stored forms; reads outside the root by absolute path (not closed; agents' sandboxes are unmeasured; named in the measurement doc); name mentions with no seed text (R4 counts those mentions and is not a leak); submodule paths, which `git archive` exports empty, so a C2 seed must not name a path under the three gitlink entries (R11).

## Architecture Considerations
- **One wrapper call per first gate (AC-9.4).** The three first-gate legs must run as one `audit-cycle --passes 3` call so that every stamp in the cycle records the same leg set. Separately collected legs can disagree within a cycle, which gives `legs_disagree:<phase>.v<N>`. Stamps are written through `_leg_key` in `h_mad_audit_gate.py` (sorted and deduped), so a `codex,agy,grok` surfaces list stamps `["agy","codex","grok"]`, as AC-10.2 expects.
- **"In that pass order" means pass index, not wall-clock order (AC-10.1).** `_cmd_audit_cycle` launches every pass in the background (`&`) and then waits on each one. The test asserts the pass-i → agent mapping and the per-pass report path. It does not assert invocation time order, which is nondeterministic.
- **The scorer is a pure function of two trees.** It takes the `main` probe and the exclusion list at the list commit ("Leak control"), and the score sha's tree (ledger, seeded copies, reports, findings, labels, key, recorded `AUDITCYCLE:` lines) together with the archive sources, and returns one token line. That makes AC-6.4's re-run possible with no dispatch (it rebuilds the export roots from the calibration sha and re-runs their scan and reach check), and it makes every verdict testable from synthetic fixtures.
- **Exact rationals.** Fabrication rates compare as reduced fractions (`fractions.Fraction`), and `0/0` compares as zero (AC-5.2). The worst-case bounds of AC-5.3 are two predicate evaluations: grok's undecidables counted as fabricated against agy's counted as not fabricated, and the reverse.
- **Blinding is procedural, and it has a residual.** Opaque ids and a shuffled order hide the surface label. They do not hide each model's writing style, so the labeller may still be able to infer the surface. The measurement doc names this residual. The labeller is a fresh context that holds the findings file and the export roots, and not the key.
- **Calibration uses the production path unchanged, in a non-git root.** Seeded documents sit at the assembler's live paths in each export root (`docs/01-plan/features/`, `docs/02-design/features/`, under the source feature's name), with byte-identical paired copies. That works only because the tree has no live copy of any source feature's phase documents (R3), so nothing collides. The wrapper's own root handling is already git-optional on the code side: `_cmd_exec` passes codex `--skip-git-repo-check`, passes grok `--cwd`, and prints `tree delta: n/a (… not a git repo)` for a non-git root. Whether each agent actually accepts the root is the AC-1.6 measurement at S1, not a premise.
