# Plan: phase5-gate-feature-scope

## Executive Summary
Build one shared rule that applies a `step5` record only to the checkout it names, route every Phase-5 gate and every staging check through it, protect the inputs that arm it, and land the result as a single fast-forward after the operator has seen the landing report.

## Overview
Today any live record found under a repository root gates every codex and agy session rooted there, so a lane working on another feature needs an operator allow line for each audit cycle. This plan gives each record a checkout, applies it there and nowhere else, and treats every case it cannot judge as applying. The change is to live policy: the installed skill is a symlink into this checkout, so order, isolation and the landing step are part of the plan and not an afterthought.

## Scope
In scope, as user-visible behaviour:

- A codex or agy session to which no live record applies (FR-3, FR-4) runs its shell without the Phase-5 command list; a session in the named checkout is gated as now, and so is every session a record that cannot be judged applies to.
- A write into the named checkout is judged from whichever session issues it, on codex, agy and Claude.
- A state record carries the checkout, and a stage that starts the shell gate at 5d.
- A gated codex or agy session cannot change what arms or scopes its gate; it leaves `step5` through an ungated session.
- The decision can be read with one command, and a refusal names the record that caused it.
- State copies in git-excluded trees, nested checkouts and test fixtures stop arming the outer root.
- The four git environment variables the spec names change no decision, the choice of root on codex and agy included (D7).

System boundaries: `h-mad/scripts/h_mad_target_identity.py`, `h_mad_tdd_judge.py`, `h_mad_state_write.py`, `h_mad_bkit_guard.py`, `h_mad_state_schema.json`, `h_mad_assemble_tdd.py` (all under `h-mad/scripts/`), the three hooks under `h-mad/hooks/`, their tests and mutation specs, and the contract text in `h-mad/SKILL.md` and `h-mad/references/`.

## Goals
- A lane on another feature in another checkout needs no allow line (FR-3, FR-9).
- Every case that cannot be judged gates as today (FR-4, FR-10).
- One implementation of discovery, applicability, stage and arming-input rules (FR-2, FR-3, FR-5, FR-6, FR-9).
- Nothing a gated session can reach changes the rule's inputs, and every legitimate writer still has a route (FR-5, FR-6, FR-7).
- The operator can see why a session is or is not gated, and which lanes a landing affects (FR-8, FR-10).
- No lane changes decision on the day this lands, outside D1 to D7 and the residual of FR-10 (FR-10).

A linked git worktree of this repository, created before 5a with a detached HEAD; 5c creates the feature branch in it (§"Convention Prerequisites", Worktree before 5a). ### Every consumer, and the pin that fails when its call is removed
Each row is one `wiring` task; a row with ids in more than one step is one task in each, and the task of each step makes or re-routes a call of its own, which is what its mutants change. Rows 27 to 31 came with spec v1.2, and rows 32 and 33 with v1.10 of this plan: their two calls on each hook stand at `7a3cca48` and are not edited, and it is the mutants that change them. Every row, or every id where a row says so, is of one kind, and the kind fixes both mutants. The shared function stays intact in both; each mutant changes the call site only, except those of rows 6, 7 and 14 inside a shared function (design §13).

| Kind | Removal | Reverse | What each must be caught by |
|---|---|---|---|
| **scope**: the call makes the consumer apply less | the unscoped answer: every live record applies, and, as a mutant of its own where rule 3 says so, every file counts | the permissive answer: nothing applies | removal by a case that must be admitted; reverse by a gated case that must be refused |
| **protection**: the call makes the consumer refuse (arming inputs, rule 5, the target part of FR-3, staging HALTs, writer refusals) | the refusal is gone: permissive | the refusal is unconditional | removal by a case that must be refused; reverse by an ordinary case that must be admitted, staged or written |
| **value**: the call supplies something reported, found or stored | the value without the call | one fixed value in place of the result | two cases whose right values differ, one per mutant |
| **environment**: the call is one git call, wherever it stands (inside a root lookup or inside a shared function) | that git call runs with the inherited environment | that git call is given an environment that always sends git elsewhere. In both mutants only the environment argument of that one call changes; the rest of the lookup and the function that builds the environment do not | removal by a case with a variable set; reverse by an ordinary case with none set |

In scope and protection the two mutants have opposite effects, so they are caught by two cases with opposite required decisions. Two mutants caught by one same decision would be one mutation written twice, and the row would be unproved; the mutation spec of each row names the killing case of every mutant, and review checks that the decision required under a removal differs from the one under the reverse. Pins are in `h-mad/tests/test_h_mad_phase5_scope_wires.py` unless the row says otherwise; parametrised ids name the row.

### Tradeoffs to preserve
- **Fail closed costs convenience.** A moved or removed checkout gates every session that can see the record. The spec accepts it; the refusal text says which record and why, so the cost is one exit or re-arm.
- **Cheap when nothing is live.** Inside a git work tree every hook may start its discovery's git processes at once, at most four for one discovery of one root, with nothing found and nothing live. Outside one, or with git missing, a discovery may start one, the one that shows it; the walk is then unpruned and every candidate counts. One process answers for many paths: the two calls of `q` in the scratch script below printed `ign ign/a ign/trk`, and only `ign/a` while a file under `ign/trk` was tracked. So the highest excluded directory of a tree is found from its ancestors and its tracked content, and is not simply the directory the ignore rule names. A git error for a batch counts every candidate in it that git has not answered, as design §2 defines answered; a candidate whose answer is whole keeps it ("Answers stand"); a partly answered first batch counts whole, its content answer being missing ("Count the whole batch").
- **An excluded tree is pruned, not batched.** Batching bounds processes; the requirement is also that the tree is judged once, at its highest excluded directory, that the answer covers everything below, and that nothing below is opened or classified on its own. The test observes it and does not infer it from a count: a git shim records every path given for classification, and an audit hook records every directory listed and every file opened. It fails when a path strictly below the highest excluded directory is a classification input of its own, when a state file below it is opened, or when a directory strictly below it is listed. The controls are the same layout with one tracked file inside one sub-project (that sub-project counts, and its siblings are judged at lower directories), and the 100 separate trees of AC-2.9 (the process count does not move).
- **When the visits must stop.** No directory below the root is listed until git has answered for it, with or without a live record; where git cannot answer, the directory is not excluded. The excluded directories are known from the first answers, and no directory strictly below a highest excluded directory is listed, opened or classified. At a root outside any git work tree, or with git missing, the walk is unpruned. How many git processes this takes is bounded as AC-2.9 says. Four layouts prove it, with no live record in the root file and no other candidate. The first three are run from the session scan of codex and agy, each with the audit events `os.scandir`, `os.listdir` and `subprocess.Popen` in one ordered log (a walk by `rglob` or `os.walk` raises `os.scandir`, and `lstat` raises none of them: read with `sys.addaudithook` under `python3.11` at `b29173f1`, and `rglob` again under 3.9 and 3.15):
  - `[every-child]`: the excluded tree is the only holder of candidates, and each of its 100 child directories holds one, with further directories and copies below it. No directory strictly below the highest excluded one is listed at any time, whatever the order of the walk.
  - `[deep]`: the only candidate lies several levels down in the excluded tree, beside 100 wide and deep siblings without one. No directory strictly below the highest excluded one is listed at any time.
  - `[nothing-found]`: the layout of `[deep]` without its candidate. At most four git processes are started, and no directory strictly below the highest excluded one is listed.
  - `[no-work-tree]`: the layout of `[deep]` in a directory that is in no git work tree, and once more in a work tree with git missing. At most one git process is started, the listing of the tree is not restricted, and every candidate counts.  
  ```python
  import os, subprocess, time
  from pathlib import Path
  J = os.path.join; N = "docs/.bkit-memory.json"; G = ["git", "--no-optional-locks"]
  def git(a, data=None): return subprocess.run(G + a, input=data, capture_output=True, text=True).stdout
  def walk(prune):
      level, seen, hits, procs = ["."], 0, 0, 0
      while level:
          if prune == "ignored" and level != ["."]:
              out = set(git(["check-ignore", "-z", "--stdin"], "\0".join(level) + "\0").split("\0")); procs += 1
              level = [d for d in level if d not in out]
          kids = []
          for d in level:
              seen += 1; hits += os.path.lexists(J(d, N))
              kids += [J(d, e.name) for e in os.scandir(d) if e.is_dir(follow_symlinks=False) and e.name != ".git"]
          level = [k for k in kids if not (prune and os.path.lexists(J(k, ".git")))]
      return seen, hits, procs
  def listed():
      ds = {"."}
      for f in git(["ls-files", "-z", "-co", "--exclude-standard"]).split("\0"):
          while f := os.path.dirname(f): ds.add(f)
      return len(ds), sum(os.path.lexists(J(d, N)) for d in ds), 1
  ways = {"rglob": lambda: ("-", len(list(Path(".").rglob(N))), 0), "all": lambda: walk(""),
          "nested": lambda: walk("nested"), "ignored": lambda: walk("ignored"), "ls-files": listed}
  for name, way in ways.items():
      for _ in range(4):
          s = time.perf_counter(); r = way(); print(name, *r, round(time.perf_counter() - s, 2))
  ```
