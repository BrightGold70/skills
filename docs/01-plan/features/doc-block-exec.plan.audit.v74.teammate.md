## Nit

- The migrated `titled_section` is described as replacing its call sites "one-for-one", but the start offset moves. Today's regex is `(?m)^(?P<marks>#+) {heading}\s*$` and `match.end()` lands **before** the heading line's newline whenever the heading is followed immediately by a non-blank line (with a blank line after the heading, greedy `\s*` plus `(?m)$` lands it at the blank line's start and the two agree); `find_heading` is specified to return the offset *past* the heading line. The delta is one leading `\n` in the returned section body. Verified harmless: all five `titled_section`/`section_from` assertions in `h-mad/tests/test_docsections.py` are `in`/`not in`/`raises`, none pins bytes, so the plan's "no existing test pins the old behaviour" holds. Worth one clause saying the leading newline is intentionally dropped, so it is a decision rather than a discovery at 5d.

- The plan calls the design's mutation matrix a "heading"; it is a bolded lead-in paragraph at `docs/02-design/features/doc-block-exec.design.md:1138`, inside the `## Test Plan` ATX heading at `:1115`. The pointer resolves either way, but "under the heading" is the one phrasing a reader will grep for and not find.
