## Summary
`docs/01-plan/features/hmad-test-boundaries.plan.md` (v1.1) and its paired `docs/01-plan/features/hmad-test-boundaries.spec.md` (v1.1) cover all six functional requirement groups (`FR-1`..`FR-6`) and pass `h_mad_precheck_doc.py` and `h_mad_doc_shape_check.py`, but contain four `build`-class defects and one `measurement`-class defect verified against `HEAD` (`9f330f71d65b5e667bd42a92065e77b9bd030d82`). Most critically, the active-AC extraction rule in `FR-3.1` / `FR-3` scans every bullet line for unanchored `\bAC-(\d+)\.(\d+)([a-z]?)\b` matches, which extracts `21` active ACs instead of `17` from `docs/01-plan/features/hmad-test-boundaries.spec.md` itself (pulling in prose example tokens `AC-2.6a`, `AC-2.6b`, `AC-3.5a`, and `AC-3.7`), the published calibration regex in `hmad-test-boundaries.plan.md` contains an invalid character range `[:.,-\s]+` that raises `re.PatternError`, `FR-2.2` contradicts itself on whether a missing resolved `<spec_path>` exits `2` (`UNREADABLE`) or `0` (`FAIL` with `code=missing_spec`), and `FR-4.2` / `Scope` item 4 misstate `h_mad_audit_gate.py`'s stdout emission order for `GATE:` vs `GATE-CLASS:`/`GATE-LEGS:`.
